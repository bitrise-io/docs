With the GitHub integration enabled, your <GlossTerm baseform="rde session">sessions</GlossTerm> authenticate to GitHub as you. In every new session, `git clone`, `git push`, and the GitHub CLI (`gh`) work over HTTPS out of the box — no personal access tokens to paste and no SSH keys to manage.

## How it works

When you enable the integration, Bitrise plants a short-lived GitHub access token on each new session machine, issued through your GitHub account connection on Bitrise (the Bitrise GitHub App):

- Tokens are valid for at most eight hours and refresh automatically for the whole lifetime of the session, including restores.
- No long-lived credential is ever stored on the machine.
- Commits you author in a session are attributed to your GitHub account, using your GitHub noreply email address so your real email address is never exposed.
- Disabling the integration stops credential issuance immediately.

## Enabling the integration

1. Connect your GitHub account to Bitrise: on your profile's **Connected accounts** page, connect **GitHub** through the Bitrise GitHub App.
1. In the [Bitrise RDE UI](/en/bitrise-rde/rde-options/bitrise-rde-ui), select **Saved Inputs** on the left, under **User settings**.
1. On the **GitHub** card, check that your account shows as connected, then enable the toggle.

   ![The GitHub card on the Saved Inputs page, connected and ready to enable](/img/rde/2026-07-31-rde-github-integration-card.png)

New sessions you create from this point get automatic GitHub access. Sessions created before you enabled the integration are not changed.

## Repositories you can access

Sessions act as you through the Bitrise GitHub App, so a session can access the repositories that meet both conditions:

- You have access to the repository on GitHub.
- The Bitrise GitHub App is installed on the repository.

:::info[Repository not found?]

If a clone fails with "repository not found" for a repository you can open in the browser, the Bitrise GitHub App isn't installed on that repository or organization — your own permissions are fine. Ask an organization admin to install the app there.

:::

## Disabling the integration

Turn off the toggle on the **GitHub** card. New sessions no longer receive credentials, running sessions immediately stop being able to refresh theirs, and the most recently issued token expires within eight hours.
