You can use the Bitrise Build Cache to speed up Xcode builds in a GitHub Actions workflow, without moving your CI to Bitrise. It works the same way on GitHub-hosted runners and on [Bitrise Build Hub](/bitrise-build-hub/build-hub-for-github-actions/build-hub-for-github-actions-overview) runners.

Your workflow needs two extra steps: one that installs the Bitrise Build Cache CLI, and one that activates the cache for Xcode. Every `xcodebuild` step that runs afterwards in the same job uses the cache.

You can also set this up with an AI coding agent instead of following the steps manually. See [Getting started with AI](/bitrise-build-cache/getting-started-with-the-build-cache/getting-started-with-ai).

## Requirements

- Xcode 26 or later. The Xcode Compilation Cache is not available on earlier versions.
- Bitrise Build Cache CLI v1.0.0 or later. If you already install the CLI for another build tool, make sure the version you pin supports Xcode.

## Adding the Build Cache to your workflow

1. Add the two environment variables to the job. Take the token from a secret and the Workspace slug from a variable:

   ```yaml
   jobs:
     build:
       runs-on: macos-latest
       env:
         BITRISE_BUILD_CACHE_AUTH_TOKEN: ${{ secrets.BITRISE_BUILD_CACHE_AUTH_TOKEN }}
         BITRISE_BUILD_CACHE_WORKSPACE_ID: ${{ vars.BITRISE_BUILD_CACHE_WORKSPACE_ID }}
   ```
1. Add a step that installs the Bitrise Build Cache CLI:

   ```yaml
   - name: Install the Bitrise Build Cache CLI
     run: curl --retry 5 -sSfL 'https://raw.githubusercontent.com/bitrise-io/bitrise-build-cache-cli/main/install/installer.sh' | sh -s -- -b /tmp/bin -d
   ```
1. Add a step that activates the Build Cache for Xcode, before the step that runs `xcodebuild`:

   ```yaml
   - name: Activate Bitrise Build Cache for Xcode
     run: /tmp/bin/bitrise-build-cache activate xcode --cache --cache-push
   ```

   `--cache` enables reading from the cache and `--cache-push` enables writing to it. CI is normally the environment that fills the cache, so keep both enabled.

   :::important[Call `xcodebuild` through `PATH`]

   Activation puts a wrapped `xcodebuild` at the front of `PATH`. A command that calls the binary by its absolute path, such as `/usr/bin/xcodebuild`, goes around the wrapper and is not cached. This also applies to tools that call `xcodebuild` or `xcrun` by absolute path on your behalf.

   :::

## Example workflow

<Tabs>
<TabItem value="github-hosted" label="GitHub-hosted runners" default>

```yaml
name: build

on: [push, pull_request]

jobs:
  build:
    runs-on: macos-latest
    env:
      BITRISE_BUILD_CACHE_AUTH_TOKEN: ${{ secrets.BITRISE_BUILD_CACHE_AUTH_TOKEN }}
      BITRISE_BUILD_CACHE_WORKSPACE_ID: ${{ vars.BITRISE_BUILD_CACHE_WORKSPACE_ID }}
    steps:
      - uses: actions/checkout@v4

      - name: Install the Bitrise Build Cache CLI
        run: curl --retry 5 -sSfL 'https://raw.githubusercontent.com/bitrise-io/bitrise-build-cache-cli/main/install/installer.sh' | sh -s -- -b /tmp/bin -d

      - name: Activate Bitrise Build Cache for Xcode
        run: /tmp/bin/bitrise-build-cache activate xcode --cache --cache-push

      - name: Build
        run: |
          xcodebuild build-for-testing \
            -workspace MyApp.xcworkspace \
            -scheme MyApp \
            -destination 'generic/platform=iOS Simulator'
```

</TabItem>
<TabItem value="build-hub" label="Build Hub runners">

The only difference is the `runs-on` label. Bitrise creates a `bitrise-runner-<pool name>` label for every machine pool, so a pool named `ios-builds` is targeted with `bitrise-runner-ios-builds`.

```yaml
name: build

on: [push, pull_request]

jobs:
  build:
    runs-on: bitrise-runner-ios-builds
    env:
      BITRISE_BUILD_CACHE_AUTH_TOKEN: ${{ secrets.BITRISE_BUILD_CACHE_AUTH_TOKEN }}
      BITRISE_BUILD_CACHE_WORKSPACE_ID: ${{ vars.BITRISE_BUILD_CACHE_WORKSPACE_ID }}
    steps:
      - uses: actions/checkout@v4

      - name: Install the Bitrise Build Cache CLI
        run: curl --retry 5 -sSfL 'https://raw.githubusercontent.com/bitrise-io/bitrise-build-cache-cli/main/install/installer.sh' | sh -s -- -b /tmp/bin -d

      - name: Activate Bitrise Build Cache for Xcode
        run: /tmp/bin/bitrise-build-cache activate xcode --cache --cache-push

      - name: Build
        run: |
          xcodebuild build-for-testing \
            -workspace MyApp.xcworkspace \
            -scheme MyApp \
            -destination 'generic/platform=iOS Simulator'
```

Make sure the image of the machine pool has Xcode 26 or later. You can also use a custom label of the pool: for more information, see [Configuring your GitHub Actions workflow](/bitrise-build-hub/build-hub-for-github-actions/configuring-your-github-actions-workflow).
