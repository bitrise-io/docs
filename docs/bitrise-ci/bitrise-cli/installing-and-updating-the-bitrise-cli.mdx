The Bitrise CLI is Bitrise's open source runner. The CLI is used to run your builds on [bitrise.io](https://www.bitrise.io) and you can install and run it on your own computer to run builds locally.

The Bitrise CLI is distributed as a single binary for macOS and Linux. You can download it using curl or Homebrew.


## Installing the Bitrise CLI with curl

1. Run the following command in a bash shell:

   ```bash
   curl -fL https://github.com/bitrise-io/bitrise/releases/latest/download/bitrise-$(uname -s)-$(uname -m) > /usr/local/bin/bitrise
   ```

   You can check the latest release of the Bitrise CLI on its [releases](https://github.com/bitrise-io/bitrise/releases) page.
1. Make the downloaded binary executable:

   ```bash
   chmod +x /usr/local/bin/bitrise
   ```
1. Run `bitrise local setup`.

   This will verify if everything that is required for Bitrise to run is installed and available. If you skip this, the CLI will perform the setup anyway the first time you call `bitrise local run`.


## Installing the Bitrise CLI with Homebrew

If you have the Homebrew package manager installed on your Mac, you can use it to install the Bitrise CLI.

1. Open the `Terminal` app on your Mac and run:

   ```bash
   brew update && brew install bitrise
   ```
1. Perform a first-time setup for the Bitrise CLI:

   ```bash
   bitrise local setup
   ```

   This will verify if everything that is required for Bitrise to run is installed and available. If you skip this, the CLI will perform the setup anyway the first time you call `bitrise local run`.


## Updating the Bitrise CLI

Updating the Bitrise CLI is easy, and it doesn’t matter if you installed it with Homebrew or from the GitHub release.

Simply run `bitrise update` - that’s it! The CLI checks for updates once every day and notifies you as soon as there is a new version.


## Configuration file locations

The CLI reads configuration from up to three files, in order of precedence from highest to lowest:

- `~/.bitrise/config.json` — a legacy config file. Earlier CLI versions wrote it, and it is authoritative if present. New settings don't belong here.
- `.bitrise-cli.yml` — a per-directory config file. The CLI looks for it in the current directory and its parent directories.
- `~/.config/bitrise/cli/config.yml` — a global config file. Set `$XDG_CONFIG_HOME` to read it from somewhere other than `~/.config`.

If none of the files set a value, the CLI falls back to its built-in default.

The `api_base_url`, `web_base_url`, and `rde_api_base_url` settings are an exception: only the global config file can set them, and the `BITRISE_API_BASE_URL`, `BITRISE_WEB_BASE_URL`, and `BITRISE_RDE_API_BASE_URL` environment variables override even that. All three point the CLI at a host it then sends your credentials to, and a `.bitrise-cli.yml` is read from any parent directory without asking you first — so a repository you only cloned could otherwise redirect your login to a server you don't control.

Make sure `~/.config` (or `$XDG_CONFIG_HOME`, if you set it) is writable. Otherwise, `bitrise local setup` and plugin commands can fail.
