You can install .ipa files generated during a Bitrise build on test devices in two ways:

- [Using the public install page](#installing-an-ipa-file-on-test-devices-from-the-public-install-page). The public install page is a generated URL that you can share with anyone who has an iPhone or iPad that the app is provisioned for. They don't need a Bitrise account.
- [Using the **Artifacts** tab](#installing-an-ipa-file-on-test-devices-from-the-artifacts-tab) on the build's page on Bitrise. This is only possible for Bitrise users.

## Before you install

Make sure that:

- The .ipa file has development, ad hoc, or enterprise distribution. The public install page can't install an .ipa file with App Store distribution.
- For development and ad hoc builds, the device is included in the app's provisioning profile. If it isn't, add the device in your Apple Developer account and rebuild the app. Enterprise builds don't need this.
- The device is of a type that the app supports and runs at least the minimum iOS version of the app. The install page lists both under **Supported device types** and **Minimum OS version**.
- You open the page in Safari in normal (non-incognito) mode. In any other browser, the page shows the **Install through Safari** message and you can only download the .ipa file.

We also recommend that you [register the test device on Bitrise](/bitrise-ci/testing/testing-ios-apps/registering-a-test-device).

:::tip[Using an iPad]

On an iPad, open the public install page in Safari with its default settings. You don't need to request the mobile version of the website.

:::

## What the public install page shows

The page shows the app, its version, and the details of the build. What the **Install this version** section shows depends on the device that opens the page:

| You see | What it means | What to do |
|---|---|---|
| **Install through Safari** | You opened the page in a browser other than Safari. | Open the page in Safari. |
| **Check compatibility** | Bitrise doesn't know the device yet, and you're not logged in to Bitrise in Safari. | Tap **Check compatibility** to [install the registration profile](#installing-an-app-on-a-test-device-without-a-bitrise-account). |
| **Register device**, with the message that the device isn't registered to your account | You're logged in to Bitrise in Safari, but the device isn't registered to your account. | Tap **Register device** to [register the device](#installing-an-app-on-a-test-device-not-registered-to-bitrise). |
| **App not allowed to be installed on this device** | The device isn't included in the app's provisioning profile. | Ask your team administrator to add the device and rebuild the app. If you restored the settings of an old device to this one, select **clear your cache**, then register the device again. |
| **App cannot be installed on this device** | The device type or the iOS version doesn't meet the requirements of the app. The message names the reason. | Use a compatible device or update iOS. |
| **Install** | The device is ready for the installation. | Tap **Install**. |
| **This version is intended for distribution via the App Store** | The .ipa file has App Store distribution. | Build the app with development, ad hoc, or enterprise distribution to install it on test devices. |

:::note[Safari 16.3 and earlier]

On Safari 16.3 and earlier, the page has a simpler layout. It offers the same actions, and the buttons carry the same names. Only some of the messages are worded slightly differently.

:::

## Installing an .ipa file on test devices from the public install page

The public install page is a convenient way of sharing the latest version of your app with team members and any other stakeholders who wish to check the app out.

You can configure the **Deploy to Bitrise.io** <GlossTerm baseform="step">Step</GlossTerm> to send an email to users with a link to the public install page. This link can be shared with anyone.

During the whole flow, use Safari in normal mode instead of any in-app browser.

:::tip[Would you rather download the app?]

If you only wish to download the app and manually upload it somewhere else, use the download icon next to the file on the **Artifacts** tab of the build. Downloading an app does not mean you can install it on the test device.

:::

### Installing an app on a test device without a Bitrise account

1. Open the link to the public install page in Safari. If you copy the link, paste it into Safari.
1. Tap **Check compatibility**. This button downloads a configuration profile that gives Bitrise the UDID of your device for the compatibility check.
1. <Partial_InstallingTheDeviceRegistrationProfile />
1. On the public install page, tap **Install**. The button is only available if the device is compatible and included in the app's provisioning profile.

   ![The Install this version section of the public install page with the Install button](/img/ios-deployment/2026-11-12-public-install-page-install-button.png)

1. Confirm the iOS prompt that asks whether to install the app, then go to the Home Screen to follow the installation.

When the installation finishes, you can find the app on the Home Screen of your test device.

### Installing an app on a test device not registered to Bitrise

If you're logged in to Bitrise in Safari and the public install page shows that the device isn't registered to your account, together with a **Register device** button, you have to register the device on Bitrise. This only takes a few extra steps compared to the flow above.

You can only register a test device if you have a Bitrise account.

1. Tap **Register device**.
1. <Partial_InstallingTheDeviceRegistrationProfile />
1. On the registration page, check the **Title** and **Device Unique Identifier** fields. Bitrise fills in both fields with the name and the UDID of your device. You can only change the title.
1. Tap **Register device**. Bitrise takes you back to the public install page.
1. Tap **Install**. If the page shows **App not allowed to be installed on this device** instead, the device isn't in the app's provisioning profile yet: add it in your Apple Developer account and rebuild the app.
1. Confirm the iOS prompt that asks whether to install the app, then go to the Home Screen to follow the installation.

When the installation finishes, you can find the app on the Home Screen of your test device.

## Installing an .ipa file on test devices from the Artifacts tab

You can install an .ipa file from the **Artifacts** tab of your build. This provides a more secure way than the public install page, but it requires you to log in to your Bitrise account on the test device. That makes it less suitable for external testers.

To install an .ipa file from the **Artifacts** tab:

1. <Partial_AccessingBuildsTabAndSelectingABuild />
1. Open the **Artifacts** tab.
1. In the **Installable app packages** section, find the .ipa file and click the arrow icon (**View artifact**) next to it. The download icon only downloads the file.
1. On the artifact page, scan the QR code with your test device, or click **Copy page URL** and open the link on the device. Open it in Safari in normal mode, and log in to Bitrise if Safari asks you to: the page requires authentication.
1. If the page shows **Register this device**, tap **Register device** and follow the instructions. For more details, check out [Registering a test device](/bitrise-ci/testing/testing-ios-apps/registering-a-test-device).
1. Tap **Install** and confirm the iOS prompt that asks whether to install the app.

:::note[Installing on a computer]

The artifact page doesn't offer **Install** when you open it in a browser other than Safari. It only shows the **Install through Safari** message, **Download artifact**, and **Copy page URL**.

:::

The same page has a **Public install link** section where you can get the link to the public install page and manage who can use it.
