How the Build Cache authenticates depends on where the job runs.

<Tabs>
<TabItem value="build-hub" label="Build Hub runners" default>

On [Bitrise Build Hub](/bitrise-build-hub/build-hub-for-github-actions/build-hub-for-github-actions-overview) runners there is nothing to set up. The machine is already connected to your Bitrise Workspace, so the CLI picks up the credentials from it: you don't create a token, and you don't add any secret or variable to GitHub.

The machine pool has to belong to the same Workspace as the Build Cache you want to use.

</TabItem>
<TabItem value="workspace-api-token" label="Workspace API token">

On GitHub-hosted runners, a [Workspace API token](/bitrise-platform/workspaces/workspace-api-token) is the recommended option. It belongs to the Workspace rather than to a person, so it keeps working when someone changes roles or leaves the company.

Give the token at least the **viewer** Workspace role: that is the lowest role that can access the Build Cache.

</TabItem>
<TabItem value="personal-access-token" label="Personal access token">

A [Personal Access Token](/bitrise-platform/accounts/personal-access-tokens#creating-a-personal-access-token) also works and is quick to create, which makes it a reasonable choice while you are evaluating the Build Cache.

:::caution[A Personal Access Token inherits your roles]

A Personal Access Token has the same roles as the user who created it. Its access changes whenever that user's roles change, and it stops working when the user leaves the Workspace. For a shared CI configuration, use a Workspace API token instead.

:::

</TabItem>
</Tabs>

If you use a Workspace API token or a Personal Access Token, pass it and your Workspace slug to the job in two environment variables:

- `BITRISE_BUILD_CACHE_AUTH_TOKEN`: the Workspace API token or the Personal Access Token. Store it as a repository or organization **secret**.
- `BITRISE_BUILD_CACHE_WORKSPACE_ID`: your Bitrise Workspace slug. This is not sensitive, so you can store it as a repository or organization **variable**.

[Find your Workspace slug](/bitrise-ci/api/identifying-workspaces-and-apps-with-their-slugs) on the **Workspace settings** page, under **General settings**.
