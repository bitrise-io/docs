<GlossTerm baseform="device preview link">device preview link</GlossTerm>は、受信者のブラウザーで、アプリのビルドをライブの iOS シミュレーターまたは Android エミュレーター上で開く URL です。リンクを開いた人は、アプリがインストールおよび起動済みで、すぐに操作できる自分専用の新しいデバイスを利用できます。Bitrise アカウント、Xcode、Android Studio、その他のインストールは不要で、必要なのはブラウザーだけです。

代表的な用途はコードレビューです。CI Workflow がアプリをビルドし、そのビルド用のリンクを発行して、プルリクエストに投稿します。レビュアー、デザイナー、リンクを共有したその他の人は、マージされる前に変更を試せます。

## プレビューリンクについて {#about-preview-links}

- リンクは、1つのアプリビルドと1つのデバイス構成に対して発行されます。発行時には何も保存されません。リンクは署名付きトークンであり、誰にも開かれなかったリンクにはコストがかかりません。
- リンクを開くたびに、<GlossTerm baseform="workspace">workspace</GlossTerm>に新しい<GlossTerm baseform="device session">device session</GlossTerm>が開始され、デバイスの起動、ビルドのダウンロード、アプリのインストールと起動が行われます。1つのリンクで複数のレビュアーが同時に利用できます。
- リンクから開かれるセッションは、誰がリンクを発行したかにかかわらず、通常の workspace 所有のセッションです。workspace のすべてのメンバーが、RDE UI の <strong>Workspace sessions</strong> でセッションを確認および管理でき、個人のセッション一覧には表示されません。パーソナルアクセストークンで発行したリンクでは作成者としてあなたが記録されますが、リンクは Bitrise 外の人とも共有されるため、そのセッションが個人のセッションになることはなく、保存済みの入力や認証情報も引き継がれません。CI から [Workspace API token](/bitrise-platform/workspaces/workspace-api-token) で発行したリンクには、作成者がまったくありません。
- 誰も一定時間デバイスを見ていないと、デバイスは自動的にシャットダウンします。プレビューデバイスを復元することはできません。リンクを開き直すと、新しいデバイスが起動します。
- リンクは有効期限が切れると使えなくなります。すでに開いているデバイスには影響しません。

ビルドはシミュレーターまたはエミュレーター用のビルドで、匿名の `GET` から絶対 `https` URL で取得できる必要があります。対応する形式については、[Supported platforms](/bitrise-rde/devices/virtual-devices#supported-platforms)を参照してください。署名付きで有効期限のあるダウンロード URL も使用でき、閲覧者には表示されませんが、リンクより長く有効である必要があります。URL の期限が切れた後にリンクを開いた閲覧者のデバイスでは、インストールに失敗します。

## CI Workflowからリンクを作成する {#creating-a-link-from-a-ci-workflow}

Bitrise Stepライブラリの[<strong>Device Preview</strong> Step](https://bitrise.io/integrations/steps/device-preview)は、次のことを行います。

- Workflowで先にビルドされたアプリのリンクを作成します。
- それを`$BITRISE_DEVICE_PREVIEW_URL`としてエクスポートします。
- 必要に応じて、ビルドが属するプルリクエストにコメントとして投稿します。

ビルド自身のAPIトークンで認証するため、設定は不要です。Workflow EditorのStepライブラリからWorkflowに追加するか、`bitrise.yml`の`device-preview@1`として追加します。プレビュー中にStepを Git URLで参照していた場合は、バージョン管理された更新を受け取るために、Stepライブラリ ID に切り替えてください。

<Tabs>
<TabItem value="ios" label="iOS" default>

```yaml
workflows:
  pr-preview:
    steps:
    - xcode-build-for-simulator@0:
        inputs:
        - project_path: $BITRISE_PROJECT_PATH
        - scheme: $BITRISE_SCHEME
    - deploy-to-bitrise-io@2: {}
    - device-preview@1:
        inputs:
        - app_path: $BITRISE_APP_DIR_PATH.zip
        - post_pr_comment: "true"
```

</TabItem>
<TabItem value="android" label="Android">

```yaml
workflows:
  pr-preview:
    steps:
    - android-build@1:
        inputs:
        - variant: debug
    - deploy-to-bitrise-io@2: {}
    - device-preview@1:
        inputs:
        - app_path: $BITRISE_APK_PATH
        - post_pr_comment: "true"
```

</TabItem>
</Tabs>

Stepは、`app_path`入力からプラットフォームを検出します。iOS の場合は `.zip`、Androidの場合は `.apk` です(上記の例を参照)。`app_path`は、CI build machine上のローカルファイルです。[Deploy to Bitrise.io](https://bitrise.io/integrations/steps/deploy-to-bitrise-io) StepがそのファイルをWorkflowで先にアップロード済みの場合、Device Preview Stepは URL を再利用してプレビューリンクを作成します。そうでない場合は、ファイル自体をアップロードし、そこからリンクを作成します。

その他の入力は、後述の[リンクオプション](#link-options)に対応しています。`device_model`、`os_version`、`system_image`、`link_ttl_hours`、`auto_terminate_minutes`、`stack`、`machine_type`、およびAndroidのエミュレーターサイズ入力です。`warm_pool_id`は、リンクの起動を[プール](#serving-links-from-a-pool)から提供します。すべての入力と出力は、[Stepの README](https://github.com/bitrise-steplib/steps-device-preview#readme)に記載されています。

Stepは、後続のSteps向けに `BITRISE_DEVICE_PREVIEW_URL` と `BITRISE_DEVICE_PREVIEW_EXPIRES_AT` をエクスポートします。URLを Slack に投稿したり、チェックに添付したり、リリースノートに追加したりできます。Stepは、リンクを作成できない場合にビルドを失敗させます。プレビューの問題でビルドを止めたくない場合は、`is_skippable: true` を設定してください。

:::tip[Build for the simulator on pull requests]

デバイス向けビルドのみを生成するプルリクエストWorkflowでは、プレビューするものがありません。シミュレーターまたはエミュレーターのビルドをWorkflowに追加するか、Pipelineで並列実行し、その出力をStepに渡してください。

:::

## CLI からリンクを作成する {#creating-a-link-from-the-cli}

すでに URL があるビルドのリンクを発行します。

```bash
bitrise-cli rde preview-link create --device-platform ios --artifact-url https://…/App.zip
```

このコマンドは、リンク、その ID、有効期限を出力します。`--output json` を追加すると JSON と同じフィールドが出力され、`--artifact-url-stdin` を追加するとコマンドラインの代わりにファイルから署名付き URL を読み込めます。

CI や、誰もサインインしていない環境では、<strong>Remote Dev Environments</strong> アクセス権で作成した [Workspace API token](/bitrise-platform/workspaces/workspace-api-token) で認証します。これを `BITRISE_TOKEN` として渡し、workspace を明示的に指定してください。workspace トークンは1つの workspace に属しており、それを検索できないためです。

```bash
BITRISE_TOKEN=bitwat_… bitrise-cli rde preview-link create --workspace WORKSPACE_ID \
  --device-platform android --artifact-url-stdin < artifact-url.txt
```

## AIエージェントからリンクを作成する {#creating-a-link-from-an-ai-agent}

たとえば、「アプリをシミュレーター用にビルドして、デザインチャンネルに投稿できるプレビューリンクをください」のように、普通の言葉で依頼します。エージェントはセッション内でアプリをビルドし、アクセス可能な場所にアップロードして、`device_spec` と `artifact` を指定して `bitrise_devenv_create_preview_link` を呼び出します。ツールは、共有用の URL を返します。

ツールの説明には、プレビューリンクが適切なツールとなる場面、つまり人がアプリを試す場面が記載されています。エージェント自身がデバイスを操作する必要がある場合は、代わりに [device session](/bitrise-rde/devices/device-sessions) を作成します。

## API でリンクを作成する {#creating-a-link-with-the-api}

create preview link エンドポイントを呼び出します。RDE API の他のエンドポイントと異なり、パーソナルアクセストークンに加えて Workspace API トークンも使用できます。

```bash
curl -X POST "https://api.bitrise.io/rde/v1/workspaces/WORKSPACE_ID/preview-links" \
  -H "Authorization: token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "device_spec": { "platform": "android" },
    "artifact": {
      "url": "https://…/app.apk",
      "app_name": "My App",
      "build_number": "1234",
      "commit_sha": "0a1b2c3"
    },
    "ttl_seconds": 14400
  }'
```

レスポンスには、共有可能な `url`、リンクの ID、`expires_at` が含まれます。[Create device preview link](/bitrise-rde-api/api-reference/codespaces-service-create-preview-link) を API リファレンスで参照してください。

## リンクオプション {#link-options}

デバイスのフィールドは、device session の [device options](/bitrise-rde/devices/device-sessions#device-options) と同じで、プラットフォーム、デバイスモデル、OS バージョンまたはシステムイメージ、Android ではエミュレーターのサイズ指定です。違いは2点あります。プラットフォームとアプリビルドは必須であること、そしてデバイスモデルはリンクの発行時に検証されないため、不明なモデルを指定するとデフォルトのモデルが起動し、閲覧者に通知が表示されることです。

リンク固有のオプションは次のとおりです。

| Option | Description |
| --- | --- |
| App name, build number, commit | 閲覧者ページに表示される表示用メタデータです。レビュアーがどのビルドを見ているかを把握できます。 |
| Link lifetime | リンクを開ける期間です。デフォルトは24時間、最大は72時間です。 |
| Auto-terminate | 最後の閲覧者が切断してから、デバイスが起動し続ける時間です。デフォルトは60分で、最短は10分です。 |
| Stack and machine type | デバイスが実行される場所です。プラットフォームのデフォルトを使う場合は空のままにします。プラットフォームに合わない値は、リンクの発行時に拒否されます。 |

## プールからリンクを提供する {#serving-links-from-a-pool}

プールがない場合、リンクを開くたびに新しいセッションが一から開始されます。マシンのプロビジョニング、セッションのセットアップの実行、シミュレーターまたはエミュレーターの起動が行われ、その後ようやくアプリのダウンロードとインストールが始まります。この起動時間が、レビュアーが待つ 1~3 分のほとんどを占めます。[プール](/bitrise-rde/configuration/pools)を使うと、この待ち時間をなくせます。アプリのデバイスを起動するテンプレートのプールに対してリンクを発行すると、リンクを開くたびにプールのウォームセッションが 1 つ割り当てられます。そのセッションはすでにデバイスが起動した状態で動作しているため、クリックしてからアプリが表示されるまでの時間は、アプリのダウンロード時間だけです。その時点でプールにウォームセッションがない場合は、プールの構成からセッションが作成されるため、リンクは引き続き動作しますが、速度は遅くなります。

プールの構成は、アプリのプラットフォームのデバイスを起動するものである必要があります。プールがデバイスとマシンを固定します。プールに対して発行する場合は、デバイスモデル、OSバージョン、システムイメージ、エミュレーターサイズ、スタック、マシンタイプを未設定のままにしてください。アプリのプラットフォームは引き続き確認されるため、Androidビルドを iOS プールに対して発行することはできません。

Device Preview Stepで、`warm_pool_id` にプールの ID を設定します。ID は、RDE UIのプールのページ、または `bitrise-cli rde pool view` からコピーできます。

```yaml
workflows:
  pr-preview:
    steps:
    - android-build@1:
        inputs:
        - variant: debug
    - deploy-to-bitrise-io@2: {}
    - device-preview@1:
        inputs:
        - app_path: $BITRISE_APK_PATH
        - warm_pool_id: 571eff49-368b-400c-86c3-f4ce49be9159
        - post_pr_comment: "true"
```

他のクライアントも、同じプール参照を受け取ります。

- CLI: `bitrise-cli rde preview-link create --warm-pool POOL --artifact-url URL`。`POOL` はプールの ID または名前です。
- AIエージェント(MCP): `bitrise_devenv_create_preview_link` ツールの `warm_pool_id`。
- API: プレビューリンク作成リクエストの `warm_pool_id`。

プールを使用するリンクでは、次の 2 点が変わります。

- プールを削除すると、リンクは無効になります。以降、リンクを開くと、有効期限が切れたリンクと同じように失敗します。アイドル状態のデバイスへの課金を止めつつリンクを有効なままにするには、代わりにプールのサイズを 0 に設定してください。
- プールを使用するリンクは、プールのテンプレートから構築されたセッションを開くため、レビュアーのデバイスでは、そのテンプレートのセットアップスクリプトと入力値で設定された内容が実行されます。プールがない場合、リンクはアプリだけがインストールされた素のデバイスを開きます。

## 受信者に表示される内容 {#what-the-recipient-sees}

リンクを開くと、アプリ名、ビルド番号、コミットが表示され、続いてデバイスの起動とアプリのインストールおよび起動の進行状況が表示されます。これには通常1〜3分かかります。その後、閲覧者はデバイスの画面上でタップ、入力、スワイプができ、ホームボタン、アプリスイッチャー、Android の戻るボタン、画面の回転、ライト/ダークの外観切り替え、フル解像度のスクリーンショットのコントロールを利用できます。

2つの more actions が利用できます。

- <strong>Share this device</strong> は、このデバイスをそのままの状態で開くリンクをコピーします。2人目の人は、新しくインストールされたデバイスではなく、同じ画面を見ることができます。見つけたばかりのバグを相手に見せるときに使ってください。
- <strong>Delete session</strong> は、タイムアウトを待たずにデバイスをすぐに終了します。

リンクの有効期限が切れた後にリンクを開くと、プレビューリンクの期限が切れていることが表示されます。workspace のログイン権限を持つ人は、RDE UI の <strong>Workspace sessions</strong> で、そのリンクが作成したセッションを引き続き確認できます。

## セキュリティと制限 {#security-and-limits}

プレビューリンクはパスワードと同様に扱ってください。URL を持っている人は誰でも workspace 内のデバイスを開くことができ、リンクを取り消すことはできません。リンクは有効期限が切れるまで動作します。リンクはプルリクエストやチームのチャンネルに投稿し、公開の場には決して投稿しないでください。また、有効期間はレビューサイクルが許す範囲で短くしてください。

1つのリンクで発生しうるコストを抑える制限は次のとおりです。

- リンクは、デフォルトで24時間、最大で72時間有効です。
- 同時に稼働できるデバイスは、1つのリンクにつき最大5台、workspace につき最大20台です。上限を超える open は、デバイスがシャットダウンするまで拒否されます。
- 各デバイスは、閲覧者がいない状態で auto-terminate の時間が経過するとシャットダウンし、合計で8時間を超えて動作することはありません。

リンクがすでに開いたデバイスを停止するには、RDE UI の <strong>Workspace sessions</strong> 一覧からセッションを終了または削除するか、`bitrise-cli rde session list --scope workspace` を使用してください。漏えいした Workspace API トークンによる新たなリンクの発行を止めるには、トークンを再生成してください。

プレビューリンクを使用するには、workspace で Remote Dev Environments へのアクセスが必要です。Workspace API トークンでリンクを発行できるのは、<strong>Remote Dev Environments</strong> アクセス権で作成されている場合のみです。
