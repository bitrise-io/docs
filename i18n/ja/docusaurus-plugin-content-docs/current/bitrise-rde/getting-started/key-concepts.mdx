Remote Dev Environments は、すべてのクライアントで同じ構成要素を共有しています。CLI、Web UI、MCP サーバー、API です。これらの概念を理解しておくと、クライアント間をスムーズに行き来できます。

## セッション {#sessions}

<GlossTerm baseform="rde session">セッション</GlossTerm>は、Remote Dev Environments の単一のインスタンスです。接続して作業するための 1 台のクラウドマシンを指します。セッションは、[テンプレート](#templates)から作成するか、[スタックとマシンタイプ](#stacks-and-machine-types)を直接選択して作成します。

各セッションは、作成された <GlossTerm baseform="workspace">workspace</GlossTerm> に属し、作成したユーザーが所有します。workspace所有のセッションの場合は、workspace自体が所有します。[Can several people share one session?](/bitrise-rde/getting-started/rde-faq)(FAQ)をご覧ください。セッションには複数の方法で接続できます。[Connecting to a session](/bitrise-rde/rde-options/connecting-to-a-session)をご覧ください。

## セッションの状態 {#session-lifecycle}

セッションは、存続期間中にいくつかの状態を遷移します。

- <strong>Running</strong>：マシンがプロビジョニングされ、接続できる状態です。セッションを作成または復元すると、短い起動処理の後に実行中になります。
- <strong>Terminated</strong>：マシンは停止していますが、セッションと永続ディスクは保持されます。終了は元に戻せます。
- <strong>Deleted</strong>：セッションが完全に削除された状態です。削除できるのは、すでに終了しているセッションのみです。

セッションを終了しても<strong>永続ディスク</strong>は保持されるため、復元すると、ファイルや変更内容はそのまま残っています。終了したセッションの保持期間に制限はなく、削除するまで、または作成元のスタックがBitriseから削除されるまで保持されます。

セッションのディスクには、作成元のスタックイメージに加えた変更だけが保存されるため、セッションを開始できるのは、そのスタックイメージが利用可能な間のみです。Stacksは、公開されているスケジュールに従って、少なくとも4週間前に通知したうえで削除されます。詳しくは、[Stackの非推奨および削除ポリシー](/bitrise-build-hub/infrastructure/build-stacks/stack-deprecation-and-removal-policy)を参照してください。スタックが削除されると、そのスタックから作成されたセッションは完全に消去され、復元できなくなります。その前に、最新のスタックから新しいセッションを作成し、残しておきたいものをコミットまたはエクスポートしてください。

マシンが起動したままになるのを防ぐため、すべてのセッションには<strong>自動終了</strong>タイマーがあります。

- デフォルトは、5日間の非アクティブ状態です。
- 最大30日まで任意の期間を設定できます。また、オフにすると、セッションは自動終了されません。
- 無料トライアルのworkspacesのセッションは8時間に制限されており、この設定を変更できません。

## Stacksとマシンタイプ {#stacks-and-machine-types}

セッションを作成するときは、次の2つを選択します。

- <strong><GlossTerm baseform="stack">スタック</GlossTerm></strong>：オペレーティングシステムのイメージと、あらかじめインストールされているツール（macOS上の特定のXcodeバージョンなど）です。これらは、Bitrise CIで使用されるスタックと同じです。
- <strong>machine type</strong>：CPUとRAMで定義されるマシンのサイズです。macOSではAppleシリコンのマシンタイプを使用します。Linuxのマシンタイプは、小規模な共有インスタンスから大規模な専有インスタンスまであります。

テンプレートでこれらを設定することも、セッションの作成時に直接選択することもできます。利用できるスタックとマシンタイプは、workspaceによって異なります。

<strong>セッションは、選択したスタックに紐付いたままになります。</strong>スタックは単なる開始点ではなく、セッションは作成元のスタックイメージに対する依存関係を恒久的に保持します。セッションのディスクには、そのイメージに加えた変更だけが保存されるため、セッションを開始できるのは、そのイメージがBitriseで利用可能な間のみです。既存のセッションを別のスタックに移行することはできません。新しいスタックに移行するには、そのスタックから新しいセッションを作成してください。スタックは公開されているスケジュールに従って最終的に削除されるため、これはセッションを保持できる期間も左右します。詳しくは、[セッションの状態](#session-lifecycle)を参照してください。

## 仮想デバイス {#virtual-devices}

セッションでは、iOS シミュレーターや Android エミュレーターを起動することもできます。これを <GlossTerm baseform="device session">デバイスセッション</GlossTerm>と呼びます。<GlossTerm baseform="device preview link">デバイスプレビューリンク</GlossTerm>を使うと、リンクを知っている人なら誰でも、そのデバイス上でアプリのビルドを開けます。[Virtual devices](/bitrise-rde/devices/virtual-devices)をご覧ください。

## テンプレート {#templates}

<GlossTerm baseform="rde template">テンプレート</GlossTerm>は、再利用できるセッション設定です。セッションを作成するたびにスタック、マシンタイプ、セットアップ手順を選択する代わりに、テンプレートで一度だけ定義し、そこからセッションを作成します。テンプレートには、次の内容を含められます。

- スタック、マシンタイプ、作業ディレクトリ。
- <strong>ライフサイクルフック</strong>：セッションの作成時（<strong>On create</strong>）、誰かがセッションを取得したとき（<strong>On claim</strong>）、復元のたび（<strong>On restore</strong>）に実行されるセットアップスクリプトです。
- <strong>Variable</strong>と<strong>入力</strong>：フックが必要とする値です。ターミナルで使用できるようにしたり、シークレットとして指定したりすることもできます。
- <strong>Workspaceリンク</strong>：特定のフォルダーをIDEで開くショートカットボタンです。

詳しくは、[テンプレート](/bitrise-rde/configuration/templates)と[ライフサイクルフック](/bitrise-rde/configuration/lifecycle-hooks)を参照してください。

## Warm pools

<GlossTerm baseform="warm pool">warm pool</GlossTerm>は、1つの設定で起動済みのアイドル状態のセッションを一定数保持します。プールからのセッション作成は数秒で完了します。新しいマシンを起動する代わりにプールからセッションが取得され、プールは代わりのセッションを起動します。プールはテンプレートを入力値およびオーバーライドとともに保存し、workspaceに属します。プールサイズはスケジュールによる変更を含め、いつでも変更できます。

Warm poolsはアルファ版であり、後方互換性のない変更が加えられる可能性があります。詳細については、[Warm pools](/bitrise-rde/configuration/warm-pools)を参照してください。

## 保存済み入力 {#saved-inputs}

<GlossTerm baseform="saved input">保存済み入力</GlossTerm>は、再利用可能な値や認証情報です。たとえば SSH 公開鍵、API トークン、Claude Code 認証情報などで、一度保存しておけば、必要に応じてセッションにマッピングできます。保存済み入力のスコープは単一の workspace ではなくユーザーアカウントで、シークレット値は保存時に暗号化されます。

詳細は、[Saved inputs](/bitrise-rde/configuration/saved-inputs)をご覧ください。
