Remote Dev Environment は、クライアントの種類を問わず同じ基本要素を共有しています。CLI、Web UI、MCP サーバー、API です。これらの概念を理解しておくと、クライアント間の移動がスムーズになります。

## セッション {#sessions}

<GlossTerm baseform="rde session">セッション</GlossTerm>とは、単一の Remote Dev Environment インスタンスのことです。つまり、接続して作業を行う1台のクラウドマシンです。セッションは、[テンプレート](#templates) から作成するか、[スタックとマシンタイプ](#stacks-and-machine-types) を直接選択して作成します。

各セッションは、作成元の <GlossTerm baseform="workspace">workspace</GlossTerm> に属し、作成したユーザーが所有します。セッションへの接続方法はいくつかあります。詳しくは [Connecting to a session](/bitrise-rde/rde-options/connecting-to-a-session)をご覧ください。

## セッションのライフサイクル {#session-lifecycle}

セッションは、その存続期間中にいくつかの状態を移行します。

- <strong>Running</strong>: マシンがプロビジョニングされ、接続可能な状態です。セッションを作成または復元すると、短い起動時間の後にこの状態になります。
- <strong>Terminated</strong>: マシンは停止していますが、セッションと永続ディスクは保持されます。終了操作は元に戻すことができます。
- <strong>Deleted</strong>: セッションは完全に削除されます。削除できるのは、すでに終了済みのセッションのみです。

セッションを終了しても <strong>永続ディスク</strong> は保持されるため、復元するとファイルや変更内容はそのまま残っています。終了したセッションの保持期間に制限はありません。削除するか、作成元のスタックが Bitrise から削除されるまで保持されます。

セッションのディスクには、作成元のスタックイメージに対して行った変更のみが保存されます。そのため、そのスタックイメージが利用可能な間のみセッションを起動できます。Stacks は公開スケジュールに従って削除され、少なくとも4週間前に通知されます。詳しくは [Stackの非推奨化と削除ポリシー](/bitrise-build-hub/infrastructure/build-stacks/stack-deprecation-and-removal-policy)をご覧ください。スタックが削除されると、そこから作成されたセッションは完全に消去され、復元できなくなります。それまでに、現行のスタックから新しいセッションを作成し、保持したい内容はコミットまたはエクスポートしてください。

マシンを起動したままにしないよう、すべてのセッションには <strong>auto-terminate</strong> タイマーが設定されています。

- 既定値は、非アクティブ状態が5日間続いた場合です。
- 最大30日まで任意の値に設定できるほか、オフにしてセッションが自動終了しないようにすることもできます。
- 無料トライアルの workspaces 内のセッションは8時間が上限で、この設定を変更できません。

## Stacksとマシンタイプ {#stacks-and-machine-types}

セッションを作成する際には、次の2つを選択します。

- <strong><GlossTerm baseform="stack">スタック</GlossTerm></strong>: OS イメージと、そこにプリインストールされたツール群です。例えば macOS 上の特定の Xcode バージョンなどです。これらは Bitrise CI で使用されているものと同じスタックです。
- <strong>machine type</strong>: マシンの CPU と RAM によって決まるサイズです。macOS では Apple シリコン搭載のマシンタイプが使用され、Linux のマシンタイプは、小規模な共有インスタンスから大規模な専用インスタンスまで多岐にわたります。

テンプレートでこれらを設定することも、セッション作成時に直接選択することもできます。利用可能なスタックとマシンタイプは、ご利用の workspace によって異なります。

<strong>セッションは、選択したスタックに固定されたままになります。</strong> スタックは単なる起点ではありません。セッションは、作成元のスタックイメージに対して恒久的な依存関係を持ちます。セッションのディスクには、そのイメージに対して行った変更のみが保存されるため、そのイメージが Bitrise 上で利用可能な間のみセッションを起動できます。既存のセッションを別のスタックに移動することはできません。新しいスタックに移行するには、そのスタックから新しいセッションを作成してください。スタックは最終的に公開スケジュールに従って削除されるため、これによってセッションを保持できる期間も決まります。詳しくは [セッションのライフサイクル](#session-lifecycle) をご覧ください。

## 仮想デバイス {#virtual-devices}

セッションでは、iOS シミュレーターや Android エミュレーターを起動することもでき、その場合は <GlossTerm baseform="device session">デバイスセッション</GlossTerm>になります。また、<GlossTerm baseform="device preview link">デバイスプレビューリンク</GlossTerm>を使うと、リンクを持つ誰でもそのデバイス上でアプリのビルドを開くことができます。詳しくは [仮想デバイス](/bitrise-rde/devices/virtual-devices)をご覧ください。

## テンプレート {#templates}

<GlossTerm baseform="rde template">テンプレート</GlossTerm>とは、再利用可能なセッション構成です。スタック、マシンタイプ、セットアップ手順を毎回選択する代わりに、テンプレートでこれらを一度定義しておき、そこからセッションを作成します。テンプレートには、次の要素を含めることができます。

- スタック、マシンタイプ、作業ディレクトリ
- セッションの初回作成時に一度だけ実行される <strong>warmup script</strong> と、起動のたびに実行される <strong>startup script</strong>
- <strong>テンプレート変数</strong> と <strong>セッション入力</strong>: セッションに必要な値で、environment variables として公開したり、シークレットとして設定したりできます。
- <strong>Workspace リンク</strong>: IDE で特定のフォルダーを開くショートカットボタンです。

詳しくは、[テンプレート](/bitrise-rde/configuration/templates)をご覧ください。

## 保存済みの入力 {#saved-inputs}

<GlossTerm baseform="saved input">保存済みの入力</GlossTerm>とは、一度保存しておき、必要に応じてセッションにマッピングできる再利用可能な値や認証情報です。例えば、SSH 公開鍵、API トークン、Claude Code 認証情報などです。保存済みの入力はユーザーアカウント単位で管理され、単一の workspace に限定されることはなく、シークレット値は保存時に暗号化されます。

詳しくは、[保存済みの入力](/bitrise-rde/configuration/saved-inputs)をご覧ください。
