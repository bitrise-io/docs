<GlossTerm baseform="warm pool">warm pool</GlossTerm>は、指定した数の <GlossTerm baseform="rde session">RDE セッション</GlossTerm>を起動済みのアイドル状態に保ちます。プールからセッションを作成する場合は、新しいマシンの起動とセットアップの実行に必要な数分ではなく、数秒で済みます。セッションを作成するときと同じように、セッションを一度だけ記述し、プールサイズを設定します。Bitrise はその数のセッションをウォーム状態に保ち、リクエストに応じて 1 つを割り当てます。

次のように、セッションがすぐに必要な場合は warm pool を使用します。

- 今すぐマシンが必要な AIエージェント。
- 1 日に多数の似たセッションを開始するチーム。
- レビュアーがクリックしてすぐにアプリが画面に表示されることを期待する、[デバイスプレビューリンク](/bitrise-rde/devices/device-preview-links)。

Warm pools は、無料トライアルの workspaces では利用できません。

:::warning[アルファ機能]

Warm pools はアルファ版です。RDE UI の <strong>Alpha</strong> バッジがそれを示しています。プールの構成、取得したセッションをパーソナライズする方法、関連する CLI コマンド、MCP ツール、API エンドポイントは、予告なく後方互換性のない形で変更される場合があります。テンプレート、スクリプト、自動化の調整が必要になることを想定してください。

:::

## warm poolの仕組み {#how-a-warm-pool-works}

warm poolは、保存されたセッション構成とプールサイズの2つの部分で構成されます。プールはworkspaceが所有します。

- 構成には、セッション作成リクエストと同じフィールドが含まれます：<GlossTerm baseform="rde template">template</GlossTerm>、そのSharedおよび <strong>On create</strong> 入力の値、有効にした機能フラグ、そしてスタック、マシンタイプ、クラスター、仮想デバイスに対する任意のオーバーライド。
- プールサイズは、プールが起動した状態で保持するセッション数です。Bitriseがセッションを作成し、workspaceに[workspaceスクリプト](/bitrise-rde/configuration/workspace-script)がある場合はそれを実行し、続いてテンプレートの <strong>On create</strong> フックを実行して、セッションを準備完了の状態に保ちます。誰かが1つを取得すると、代わりのセッションが起動します。
- サイズ0のプールはセッションを保持しませんが、構成プリセットとしては引き続き機能します。そこから取得すると、保存された構成からセッションが作成されます。

セッションを取得すると、プールのウォームセッションの1つが割り当てられます。Bitriseが名前を変更し、指定した名前、ラベル、自動終了ウィンドウを適用します。準備完了のセッションがまだない場合は、まだウォームアップ中のセッションが割り当てられ、そのセッションがあなたのセッションとして起動を完了します。プールにウォームセッションがまったくない場合は、代わりにBitriseがプールの構成からセッションを作成します。すべてのセッションは由来を記録します：取得されたセッションのウォーム状態は`claimed`、オンデマンドで作成されたセッションのウォーム状態は`cold`です。RDE UIのセッション一覧では、これらが <strong>Claimed</strong> と <strong>Built cold</strong> のバッジとして表示されます。

ウォームセッションは、取得されるのを待つ通常のセッションであり、待機中もマシン時間を消費します。誰かが取得するまでは、どのセッション一覧にも表示されず、誰も接続、変更、終了できません。プールのページでそのログを読んで、テンプレートの <strong>On create</strong> フックが動作することを確認できます。ウォームセッションには自動終了タイマーがありません。誰かが取得するか、プールが縮小された、または構成が変更されたためにBitriseが破棄するまで待機します。

## プールを使用できるユーザー {#who-can-use-a-pool}

RDEアクセス権を持つ<GlossTerm baseform="workspace">workspace</GlossTerm>のメンバーは全員、プールを表示し、そこから取得し、管理できます。[Workspace APIトークン](/bitrise-platform/workspaces/workspace-api-token)で、CIからアクセスすることもできます。

プールは、テンプレートのSharedおよび <strong>On create</strong> 入力をプレーンな値として保存し、シークレットとしてマークされている場合は保存時に暗号化します。セッションを取得する人が <strong>On claim</strong> と <strong>On restore</strong> の入力を入力します。[保存済み入力](/bitrise-rde/configuration/saved-inputs)は個人用のため、プールから参照できません：プールが保存済み入力を使える特定の個人がいないためです。

## 取得したセッションの所有者 {#who-owns-a-claimed-session}

プールから取得したセッションは、自分で作成したセッションと同様にあなたのものであり、あなただけが表示・管理できます。ウォームセッションは誰かが取得する前に起動されるため、取得されるまでは個人的な情報は何も含まれていません。取得すると、Bitriseが、指定した場合はSSHキーとClaude認証情報をセットアップし、[GitHub連携](/bitrise-rde/configuration/github-integration)をオンにしている場合はGitHubにログインし、その後、<strong>On claim</strong> 入力を使ってテンプレートの <strong>On claim</strong> フックを実行します。[warm poolでのフックの使用](/bitrise-rde/configuration/lifecycle-hooks#using-hooks-with-a-warm-pool)を参照してください。

取得したセッションを代わりに共有するには、取得時にオーナーとして <strong>Workspace</strong> を選択します。すると、すべてのメンバーが <strong>Workspace sessions</strong> の下でそのセッションを表示・管理でき、あなたは作成者として記録されます。Workspace APIトークンで取得したセッションと、[プレビューリンク](/bitrise-rde/devices/device-preview-links)で開かれるデバイスセッションは、常にworkspaceに属します。

## プールの作成 {#creating-a-pool}

<Tabs>
<TabItem value="ui" label="RDE UI" default>

1. Remote Dev Environmentsセクションで <strong>Warm pools</strong> を開き、<strong>New warm pool</strong> をクリックします。テンプレートのページでは、<strong>Create warm pool</strong> をクリックすると、テンプレートが選択済みの同じフォームが開きます。
1. テンプレートを選択します。フォームには、そのテンプレートに必要な項目のみが表示されます：SharedおよびOn createの入力、機能フラグ、テンプレートがデバイスを起動する場合はデバイスセクション、そしてセッションフォームと同じ <strong>Override machine configuration</strong> スイッチです。
1. <strong>Pool name</strong> を入力します。
1. <strong>Pool size</strong> を設定します。
1. <strong>Create warm pool</strong> をクリックします。

プールのページには、準備完了のセッション数とまだウォームアップ中のセッション数が表示されます。また、ウォームセッションを名前で一覧表示し、取得済みセッションとコールドセッションの累計数も表示します。

</TabItem>
<TabItem value="cli" label="CLI">

```bash
bitrise-cli rde warm-pool create ios-reviewers --template "iOS Xcode 26" --size 2
```

`--input`と`--secret-input`はテンプレートのSharedおよび <strong>On create</strong> 入力を設定し、`--feature-flag`はテンプレートの機能フラグを有効にし、`--stack`、`--machine-type`、`--device-*`フラグはテンプレートの宣言をオーバーライドします。プールIDを受け取るすべてのコマンドは、プールの名前も受け付けます。

</TabItem>
<TabItem value="mcp" label="AI agent (MCP)">

平易な言葉で依頼します。例：*「チーム用に、iOS Xcode 26テンプレートのセッションを2つウォーム状態に保ってください。」* エージェントは、テンプレート、入力、プールサイズを指定して`bitrise_devenv_create_warm_pool`を呼び出します。

</TabItem>
<TabItem value="api" label="API">

```bash
curl -X POST "https://api.bitrise.io/rde/v1/workspaces/WORKSPACE_ID/warm-pools" \
  -H "Authorization: token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ios-reviewers",
    "template_id": "TEMPLATE_ID",
    "pool_size": 2
  }'
```

構成フィールドは、セッション作成リクエストのものと同じです。APIリファレンスの[warm poolの作成](/bitrise-rde-api/api-reference/codespaces-service-create-warm-pool)を参照してください。

</TabItem>
</Tabs>

Bitriseは、セッション作成リクエストと同じ方法で構成を検証します。不明な入力、必須入力の不足、マシンタイプで実行できないデバイスは、保存時に拒否されます。ウォームセッションは実行中のセッションであるため、他のセッションと同様にworkspaceのセッション上限にカウントされます。workspaceが上限に達していてプールがサイズに到達できない場合、プールのページにエラーが表示され、プールは再試行を続けます。

## セッションの取得 {#claiming-a-session}

<Tabs>
<TabItem value="ui" label="RDE UI" default>

<strong>New session</strong> フォームで、テンプレートを選択すると、<strong>Start from warm pool</strong> にそのプールが一覧表示され、プールが1つだけの場合は自動的に選択されます。プールを選択すると、構成セクションはプールによって固定されます。セッションに名前を付け、オーナー（デフォルトは <strong>Me</strong>）を選択し、自動終了ウィンドウを設定し、テンプレートに <strong>On claim</strong> と <strong>On restore</strong> の入力がある場合は入力します。プールのページにも、プールが選択済みのフォームを開く <strong>Claim a session</strong> ボタンがあります。

</TabItem>
<TabItem value="cli" label="CLI">

```bash
bitrise-cli rde session create my-fix --warm-pool ios-reviewers
```

`--input`と`--map-saved-inputs`が、テンプレートの <strong>On claim</strong> と <strong>On restore</strong> の入力を設定します。

</TabItem>
<TabItem value="mcp" label="AI agent (MCP)">

エージェントは`warm_pool_id`を`bitrise_devenv_create`に渡します。取得できるプールを確認するには、`bitrise_devenv_list_warm_pools`を呼び出します。

</TabItem>
<TabItem value="api" label="API">

セッション作成リクエストで`warm_pool_id`を設定し、構成フィールドは空のままにします。テンプレートの <strong>On claim</strong> と <strong>On restore</strong> の入力は`session_inputs`で送信します。

</TabItem>
</Tabs>

プールが構成を固定します。テンプレート、SharedまたはOn createの入力、機能フラグ、スタック、マシンタイプ、クラスター、デバイスも渡す取得リクエストは、無視されずに拒否されます。セッションごとに、名前、説明、ラベル、自動終了ウィンドウは引き続き選択できます。デバイスを起動するプールでは、インストールするアプリのビルドも選択できます。

## プールを健全に保つ {#keeping-the-pool-healthy}

Bitriseがすべてのプールを定期的にチェックし、サイズを維持します。知っておくべき点がいくつかあります：

- <strong>構成を編集するとウォームセッションが置き換えられます。</strong> 入力、機能フラグ、マシンまたはデバイスの設定を変更すると、Bitriseは古い構成でウォームアップされたセッションを破棄し、新しいセッションを起動します。このような変更を保存する前に、UIが警告します。プールの名前変更やサイズ変更は、ウォームセッションに影響しません。
- <strong>テンプレートの編集も同様です。</strong> プールはテンプレートに従うため、テンプレートのフックや変数を編集すると、プールのウォームセッションも置き換えられます。
- <strong>構成が壊れるとプールが一時停止します。</strong> テンプレートの編集によって、プールが設定していない必須入力が追加されたり、プールが有効にしている機能フラグが削除されたりすることがあります。その場合、プールは構成エラーを表示し、修正するまでセッションの作成を停止します。プールの既存のウォームセッションは引き続き取得できます。
- <strong>On create の失敗でプールが停止します。</strong> After 3回連続で失敗すると、プールに <strong>Setup failed</strong> と表示され、ウォームアップを停止し、取得を拒否します。調査用に最後に失敗したマシンが保持され、<strong>Retry</strong> をクリックするとウォームアップが再開します。[warm poolで On create が失敗した場合](/bitrise-rde/configuration/lifecycle-hooks#when-on-create-fails-in-a-warm-pool)を参照してください。
- <strong>マシンの失敗が繰り返されるとプールが一時停止します。</strong> マシンの起動に失敗すると、プールは再試行するまでしばらく待機し、新しいマシンを起動し続けないようにします。プールのページに最後のエラーが表示されます。

## スケジュールによるプールのスケーリング {#scaling-a-pool-on-a-schedule}

ウォームセッションはアイドル中もマシン時間のコストがかかるため、プールサイズは需要に必要な数に保ってください。サイズの変更は 1 回の呼び出しで行えるため、スケジュールを簡単に組めます。たとえば、営業時間に合わせてプールをウォームアップし、夕方に空にできます。Workspace API トークンを使った cron ジョブで実現できます。

```bash
0 8  * * 1-5  BITRISE_TOKEN=bitwat_… bitrise-cli rde warm-pool set-size ios-reviewers 3 --workspace WORKSPACE_ID -q
0 19 * * 1-5  BITRISE_TOKEN=bitwat_… bitrise-cli rde warm-pool set-size ios-reviewers 0 --workspace WORKSPACE_ID -q
```

サイズを 0 にすると、すべてのウォームセッションが破棄されますが、プール、その構成、およびそのプールで発行されたプレビューリンクは残ります。プールを削除すると、ウォームセッションが破棄され、そのプレビューリンクも無効になります。すでにプールから取得したセッションは通常のセッションであり、どちらの操作の影響も受けません。

## デバイスプールとプレビューリンク {#device-pools-and-preview-links}

プールのテンプレートが仮想デバイスを起動する場合、プールはデバイスも起動済みの状態に保ちます。このため、[デバイスプレビューリンク](/bitrise-rde/devices/device-preview-links)は、アプリのダウンロードにかかる時間で開きます。プールを指定してリンクを発行すると、リンクが開かれるたびに、そのウォームデバイスの 1 つが取得されます。[warm poolからのリンクの提供](/bitrise-rde/devices/device-preview-links#serving-links-from-a-warm-pool)を参照してください。

デバイスプールから取得する場合は、アプリビルドをすぐにインストールできます。ビルドの URL を、セッションのアーティファクトとして渡します。デバイスはすでに実行中のため、セッションが割り当てられた時点でアプリがインストールされます。

## プールの管理 {#managing-pools}

<strong>Warm pools</strong> ページには、workspaceのプールが一覧表示されます。プールのページから、サイズの変更、構成の編集、セッションの取得、削除ができます。CLIでは、`bitrise-cli rde warm-pool list`、`view`、`update`、`set-size`、`retry`、`delete`で同じ操作ができ、[API](/bitrise-rde/configuration/rde-api#warm-pools)ではwarm poolエンドポイントで同じ操作ができます。

Workspaceのオーナーと請求を管理するメンバーも、すべてのプールとそのサイズを表示できます。プールは <strong>Usage</strong> ページと`bitrise-cli rde warm-pool list --all`に、workspaceのその他のRDE支出とともに表示されます。
