<GlossTerm baseform="warm pool">warm pool</GlossTerm>は、指定した数の <GlossTerm baseform="rde session">RDE セッション</GlossTerm>を起動済みのアイドル状態に保ちます。プールからセッションを作成する場合は、新しいマシンの起動とセットアップの実行に必要な数分ではなく、数秒で済みます。セッションを作成するときと同じように、セッションを一度だけ記述し、プールサイズを設定します。Bitrise はその数のセッションをウォーム状態に保ち、リクエストに応じて 1 つを割り当てます。

次のように、セッションがすぐに必要な場合は warm pool を使用します。

- 今すぐマシンが必要な AIエージェント。
- 1 日に多数の似たセッションを開始するチーム。
- レビュアーがクリックしてすぐにアプリが画面に表示されることを期待する、[デバイスプレビューリンク](/bitrise-rde/devices/device-preview-links)。

Warm pools は、無料トライアルの workspaces では利用できません。

:::warning[アルファ機能]

Warm pools はアルファ版です。RDE UI の <strong>Alpha</strong> バッジがそれを示しています。プールの構成、取得したセッションをパーソナライズする方法、関連する CLI コマンド、MCP ツール、API エンドポイントは、予告なく後方互換性のない形で変更される場合があります。テンプレート、スクリプト、自動化の調整が必要になることを想定してください。

:::

## warm pool の仕組み {#how-a-warm-pool-works}

warm pool は、保存済みのセッション構成とプールサイズの 2 つの要素で構成されます。プールは workspace が所有します。

- 構成には、セッション作成リクエストと同じフィールドが含まれます。<GlossTerm baseform="rde template">テンプレート</GlossTerm>、そのセッション入力値、有効にした機能フラグ、そしてスタック、マシンタイプ、クラスター、仮想デバイスに対する任意の上書き設定です。
- プールサイズは、プールが起動済みに保つセッションの数です。Bitrise がセッションを作成し、テンプレートのウォームアップスクリプトと起動スクリプトをそれらのセッションで実行して、準備完了の状態に保ちます。誰かがセッションを取得すると、代わりのセッションが起動します。
- サイズが 0 のプールはセッションを保持しませんが、構成のプリセットとしては引き続き機能します。このプールから取得すると、保存済みの構成からセッションが作成されます。

セッションを取得すると、プールのウォームセッションの 1 つが割り当てられます。Bitrise は、そのセッションの名前を変更し、指定した名前、ラベル、自動終了までの時間を適用します。準備完了のセッションがまだない場合は、まだウォームアップ中のセッションが割り当てられ、起動が完了すると、そのままあなたのセッションになります。プールにウォームセッションがまったくない場合は、代わりに Bitrise がプールの構成からセッションを作成します。すべてのセッションには作成元が記録されます。取得したセッションのウォーム状態は `claimed`、オンデマンドで作成したセッションのウォーム状態は `cold` です。RDE UI のセッション一覧では、これらが <strong>Claimed</strong> バッジと <strong>Built cold</strong> バッジとして表示されます。

ウォームセッションは、取得されるのを待っている通常のセッションであり、待機中もマシン時間のコストがかかります。誰かが取得するまでは、どのセッション一覧にも表示されず、誰も接続、変更、終了できません。セットアップスクリプトが正しく動作するかどうかは、プールページでログを確認できます。ウォームセッションには自動終了タイマーがありません。誰かが取得するか、プールの縮小や構成の変更により Bitrise がそのセッションを破棄するまで、待機し続けます。

## プールを使用できるユーザー {#who-can-use-a-pool}

RDE にアクセスできる <GlossTerm baseform="workspace">workspace</GlossTerm>のすべてのメンバーが、プールを表示し、プールからセッションを取得し、プールを管理できます。[Workspace API トークン](/bitrise-platform/workspaces/workspace-api-token)を使うと、CI からプールにアクセスできます。

プールの入力値は通常の値として保存され、シークレットとしてマークした場合は保存時に暗号化されます。[保存済みの入力値](/bitrise-rde/configuration/saved-inputs)は個人のものであるため、プールから参照できません。プールが使用できる保存済み入力値を持つ、特定の個人がいないためです。

## 取得したセッションの所有者 {#who-owns-a-claimed-session}

プールから取得したセッションは、自分で作成したセッションと同様にあなたのものであり、自分だけが表示と管理を行えます。ウォームセッションは誰かが取得する前に起動されているため、保存済みの入力値や GitHub の認証情報など、個人に紐づくものは含まれていません。これらは、取得後に追加してください。たとえば SSH 経由で追加できます。

取得したセッションを共有したい場合は、取得時に所有者として <strong>Workspace</strong> を選択します。すると、すべてのメンバーが <strong>Workspace sessions</strong> の下でそのセッションを表示、管理できるようになり、作成者としてあなたが記録されます。Workspace API トークンで取得したセッションや、[プレビューリンク](/bitrise-rde/devices/device-preview-links)から開かれるデバイスセッションは、常に workspace に属します。

## プールの作成 {#creating-a-pool}

<Tabs>
<TabItem value="ui" label="RDE UI" default>

1. Remote Dev Environments セクションで <strong>Warm pools</strong> を開き、<strong>New warm pool</strong> をクリックします。テンプレートのページから <strong>Create warm pool</strong> をクリックすると、そのテンプレートが選択済みの同じフォームが開きます。
1. テンプレートを選択します。フォームには、そのテンプレートに必要な項目だけが表示されます。セッション入力値、機能フラグ、テンプレートがデバイスを起動する場合はデバイスのセクション、そしてセッションフォームと同じ <strong>Override machine configuration</strong> スイッチです。
1. <strong>Pool name</strong> を入力します。
1. <strong>Pool size</strong> を設定します。
1. <strong>Create warm pool</strong> をクリックします。

プールページには、準備完了のセッション数と、まだウォームアップ中のセッション数が表示されます。また、ウォームセッションが名前の一覧で表示され、取得されたセッションとコールドセッションの累計数も確認できます。

</TabItem>
<TabItem value="cli" label="CLI">

```bash
bitrise-cli rde warm-pool create ios-reviewers --template "iOS Xcode 26" --size 2
```

`--input` と `--secret-input` はテンプレートのセッション入力値を設定し、`--feature-flag` はテンプレートの機能フラグを有効にします。`--stack`、`--machine-type`、`--device-*` フラグは、テンプレートで宣言された内容を上書きします。プール ID を受け取るコマンドは、すべてプールの名前も指定できます。

</TabItem>
<TabItem value="mcp" label="AI agent (MCP)">

たとえば、次のように自然な言葉で依頼します。*「チーム用に、iOS Xcode 26 テンプレートのセッションを 2 つウォーム状態に保ってください。」* エージェントは、テンプレート、入力値、プールサイズを指定して `bitrise_devenv_create_warm_pool` を呼び出します。

</TabItem>
<TabItem value="api" label="API">

```bash
curl -X POST "https://api.bitrise.io/rde/v1/workspaces/WORKSPACE_ID/warm-pools" \
  -H "Authorization: token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ios-reviewers",
    "template_id": "TEMPLATE_ID",
    "pool_size": 2
  }'
```

構成フィールドは、セッション作成リクエストのものと同じです。APIリファレンスの[warm poolの作成](/bitrise-rde-api/api-reference/codespaces-service-create-warm-pool)を参照してください。

</TabItem>
</Tabs>

Bitrise は、セッション作成リクエストと同じ方法で構成を検証します。不明な入力値、必須入力値の欠落、マシンタイプで実行できないデバイスは、保存時に拒否されます。ウォームセッションは実行中のセッションであるため、他のセッションと同様に、workspaceのセッション数の上限にカウントされます。workspaceが上限に達していてプールがサイズに到達できない場合は、プールページにエラーが表示され、プールは再試行を続けます。

## セッションの取得 {#claiming-a-session}

<Tabs>
<TabItem value="ui" label="RDE UI" default>

<strong>New session</strong> フォームでテンプレートを選択すると、<strong>Start from warm pool</strong> にそのテンプレートのプールが一覧表示され、プールが 1 つしかない場合は自動的に選択されます。プールを選択すると、構成のセクションはプールによって固定されます。セッションの名前、所有者（デフォルトは <strong>Me</strong>）、自動終了までの時間だけを指定します。プールのページにも <strong>Claim a session</strong> ボタンがあり、そのプールが選択された状態でフォームが開きます。

</TabItem>
<TabItem value="cli" label="CLI">

```bash
bitrise-cli rde session create my-fix --warm-pool ios-reviewers
```

</TabItem>
<TabItem value="mcp" label="AI agent (MCP)">

エージェントは `warm_pool_id` を `bitrise_devenv_create` に渡します。取得できるプールを確認するには、`bitrise_devenv_list_warm_pools` を呼び出します。

</TabItem>
<TabItem value="api" label="API">

セッション作成リクエストに `warm_pool_id` を設定し、構成フィールドは空のままにします。

</TabItem>
</Tabs>

構成はプールによって固定されます。テンプレート、入力値、機能フラグ、スタック、マシンタイプ、クラスター、デバイスのいずれかを同時に渡した取得リクエストは、無視されずに拒否されます。セッションごとに、名前、説明、ラベル、自動終了までの時間は引き続き選択できます。デバイスを起動するプールでは、インストールするアプリビルドも選択できます。

## プールを正常に保つ {#keeping-the-pool-healthy}

Bitrise はすべてのプールを定期的にチェックし、プールをそのサイズに保ちます。次の点に注意してください。

- <strong>構成を編集すると、ウォームセッションが置き換えられます。</strong> 入力値、機能フラグ、マシンやデバイスの設定を変更すると、Bitrise は古い構成でウォームアップされたセッションを破棄し、新しいセッションを起動します。このような変更を保存する前に、UI が警告を表示します。プールの名前の変更やサイズの変更は、ウォームセッションに影響しません。
- <strong>テンプレートを編集した場合も同様です。</strong> プールはテンプレートに追従するため、テンプレートのスクリプトや変数を編集すると、プールのウォームセッションも置き換えられます。
- <strong>構成が壊れると、プールは一時停止します。</strong> テンプレートの編集によって、プールに設定されていない必須の入力値が追加されたり、プールが有効にしている機能フラグが削除されたりする場合があります。その場合、プールには構成エラーが表示され、修正するまでセッションの作成を停止します。プールにすでにあるウォームセッションは、引き続き取得できます。
- <strong>失敗が繰り返されると、プールは一時停止します。</strong> プールは再試行までしばらく待機するため、壊れたセットアップスクリプトのせいで新しいマシンが起動され続けることはありません。プールページには、直近のエラーが表示されます。

## スケジュールによるプールのスケーリング {#scaling-a-pool-on-a-schedule}

ウォームセッションはアイドル中もマシン時間のコストがかかるため、プールサイズは需要に必要な数に保ってください。サイズの変更は 1 回の呼び出しで行えるため、スケジュールを簡単に組めます。たとえば、営業時間に合わせてプールをウォームアップし、夕方に空にできます。Workspace API トークンを使った cron ジョブで実現できます。

```bash
0 8  * * 1-5  BITRISE_TOKEN=bitwat_… bitrise-cli rde warm-pool set-size ios-reviewers 3 --workspace WORKSPACE_ID -q
0 19 * * 1-5  BITRISE_TOKEN=bitwat_… bitrise-cli rde warm-pool set-size ios-reviewers 0 --workspace WORKSPACE_ID -q
```

サイズを 0 にすると、すべてのウォームセッションが破棄されますが、プール、その構成、およびそのプールで発行されたプレビューリンクは残ります。プールを削除すると、ウォームセッションが破棄され、そのプレビューリンクも無効になります。すでにプールから取得したセッションは通常のセッションであり、どちらの操作の影響も受けません。

## デバイスプールとプレビューリンク {#device-pools-and-preview-links}

プールのテンプレートが仮想デバイスを起動する場合、プールはデバイスも起動済みの状態に保ちます。このため、[デバイスプレビューリンク](/bitrise-rde/devices/device-preview-links)は、アプリのダウンロードにかかる時間で開きます。プールを指定してリンクを発行すると、リンクが開かれるたびに、そのウォームデバイスの 1 つが取得されます。[warm poolからのリンクの提供](/bitrise-rde/devices/device-preview-links#serving-links-from-a-warm-pool)を参照してください。

デバイスプールから取得する場合は、アプリビルドをすぐにインストールできます。ビルドの URL を、セッションのアーティファクトとして渡します。デバイスはすでに実行中のため、セッションが割り当てられた時点でアプリがインストールされます。

## プールの管理 {#managing-pools}

<strong>Warm pools</strong> ページには、workspaceのプールが一覧表示されます。プールのページでは、サイズの変更、構成の編集、セッションの取得、プールの削除を行えます。CLI では、`bitrise-cli rde warm-pool list`、`view`、`update`、`set-size`、`delete` で同じ操作を行え、[API](/bitrise-rde/configuration/rde-api#warm-pools)では warm pool エンドポイントで行えます。

請求を管理する Workspace のオーナーとメンバーは、すべてのプールとそのサイズも確認できます。プールは <strong>Usage</strong> ページと `bitrise-cli rde warm-pool list --all` に、workspaceの他の RDE 利用コストとともに表示されます。
