Linux上のBitriseスタックは、Ubuntu LTSリリースをベースにしています。各Bitriseスタックは1つのUbuntu LTSバージョンをベースにしており、別のバージョンへアップグレードされることはありません。その代わりに、新しいスタックをリリースし、古いスタックは時間をかけて段階的に廃止します。

:::note[スタックの旧バージョン]

スタックを新しいバージョンに更新すると、一部のビルドで問題が発生する可能性があります。移行をスムーズにするため、更新後2~3日間はスタックの旧バージョンを使用できます。[スタックの旧バージョンの使用](/bitrise-build-hub/infrastructure/build-stacks/stack-update-policy#using-the-previous-version-of-a-stack)。

:::

macOS固有の情報については、[macOSスタック更新ポリシー](/bitrise-build-hub/infrastructure/build-stacks/macos-stack-update-policy)をご確認ください。

## Linuxスタックの提供内容

Bitriseは、さまざまなユースケースに対応するため、複数のLinuxスタックを提供しています。

利用可能なスタックは、[こちら](https://bitrise.io/stacks/)からいつでも確認できます。

各スタックは、Linuxディストリビューションの1つのリリースをベースにしています。現在、Ubuntu LTSリリースをベースにしたスタックを提供しています。このベースイメージにツールをインストールすることで、システムのBitriseエディションが作成されます。

stack nameとIDには上記のパラメータがすべて含まれており、実際には次のようになります。

- 名前: Ubuntu Noble 24.04 - Bitrise 2025 Edition
- ID: `ubuntu-noble-24.04-bitrise-2025-android`

異なるLinuxスタックとその更新頻度には微妙な違いがあります。適切なスタックを選択し、突然のビルド破損を避けるためには、これらの詳細を理解しておく必要があります。

## Linuxスタックの更新

新しいBitriseエディションと新しいスタックは、毎年作成されます。これは常に最新のUbuntu LTSリリースをベースにしています。

新しいUbuntuリリースに加えて、この新しい年次Bitriseエディションには、既存のスタックに適用すると影響が大きすぎる破壊的変更が含まれています。例:

- プリインストールされたツールを、破壊的変更を伴う新しいバージョンにアップグレードする。
- ツールの複数バージョンがインストールされている場合（例: Ruby、Node.js）、サポート終了（EOL）に達し、セキュリティ修正が提供されなくなった古いバージョンを削除する。
- 一部またはすべてのユーザーのワークフローに影響を与える可能性のある設定変更を行う。

## Stackのライフサイクル

macOSのBitriseスタックと同様に、Linuxのスタックには次のライフサイクルがあります: Edge、Stable、Frozen、Removed。

新しいスタックはまずEdgeスタックとして導入され、1年間のテストとフィードバックを経てStableスタックになります。その1年後にFrozenとしてマークされ、さらに1年後に完全に削除されます。

1つのスタックの各段階:

![stack-state-change.svg](/img/_paligo/uuid-5169df38-e851-52da-fb4f-d37c3f98e8d8.svg)

毎年4月頃、新しいUbuntuバージョンのリリースに合わせて:

- 新しいスタックがEdgeスタックとして導入されます。
- 昨年のEdgeスタックがStableになります。
- 昨年のStableスタックがFrozenになります。
- 昨年のFrozenスタックが削除されます。

過去および今後のスタックにおける状態の変化:

![multiple-stack-state-change.svg](/img/_paligo/uuid-bcc68f5e-feec-8292-2e57-1bfb0dd9d9b9.svg)

スタックが削除される前に、削除予定としてフラグが付けられ、UI全体で最終削除日が表示されます。さらに、そのスタックを引き続き使用しているユーザーには、Bitriseからメール通知が送信されます。
