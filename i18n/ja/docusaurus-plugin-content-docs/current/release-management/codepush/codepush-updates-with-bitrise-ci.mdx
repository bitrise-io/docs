CodePush アップデートは、[Bitrise CI](/bitrise-ci) <GlossTerm baseform="Workflow">Workflow</GlossTerm> からリリースできます。このプロセスには次の作業が必要です:

- CodePush の認証情報の設定: アプリ ID、deployment name、対象バージョン、および Bitrise API トークンを保持する [Environment Variables](/bitrise-ci/configure-builds/environment-variables) と <GlossTerm baseform="Secret">Secret</GlossTerm> を作成します。
- iOS と Android の両方のアップデートパッケージを作成し、どちらも Bitrise にアップロードする Workflow の作成。


## Bitrise での CodePush 認証情報の設定 {#configuring-codepush-credentials-on-bitrise}

1. Release Management のアプリ ID ([確認方法](/release-management/codepush/codepush-cli/using-the-codepush-cli#setting-up-a-project)) と、[CodePush deployments](/release-management/codepush/creating-a-codepush-deployment) の名前を確認します。
1. 接続したアプリ ID、deployment name、対象バージョン用に [Environment Variables を作成します](/bitrise-ci/configure-builds/environment-variables#setting-an-env-var-in-the-workflow-editor):

   - `IOS_CONNECTED_APP_ID`: iOS アプリのアプリ ID。
   - `ANDROID_CONNECTED_APP_ID`: Android アプリのアプリ ID。
   - `CODEPUSH_DEPLOYMENT`: リリース先のデプロイの名前 (例: `Staging`)。
   - `APP_TARGET_VERSIONS`: アップデートを受け取るアプリのバージョン。正確なバージョンまたは[範囲式](/release-management/codepush/creating-and-releasing-codepush-updates#target-versions)を使用します (例: `1.2.0` または `>=1.5.0`)。

   デプロイはアプリに属するため、iOS アプリと Android アプリにはそれぞれ独自のデプロイがあります。2つのデプロイは、同じ名前 (例: `Staging`) にできます。その場合は、`CODEPUSH_DEPLOYMENT` を `Staging` に設定すると、Bitrise がアプリごとに適切なデプロイを見つけます。

   Bitrise は、アップデートがアプリバージョンのネイティブコードで動作するかどうかを確認できません。どのバージョンに互換性があるかはユーザーが判断するため、リリースのたびに `APP_TARGET_VERSIONS` を自分で設定してください。
1. 個人用アクセストークン、または <GlossTerm baseform="workspace">workspace</GlossTerm> API トークンを保持する、`BITRISE_API_TOKEN` という名前の [Secret を作成します](/bitrise-ci/configure-builds/secrets#setting-a-secret)。


## CodePush アップデート用の Workflow の作成 {#creating-a-workflow-for-codepush-updates}

このセクションでは、次の処理を行う CI Workflow の作成方法を説明します:

- iOS のアップデートパッケージを作成する。
- iOS のアップデートパッケージを Bitrise にアップロードする。
- Android のアップデートパッケージを作成する。
- Android のアップデートパッケージを Bitrise にアップロードする。

これらのアップデートパッケージの作成とアップロードは、Bitrise CodePush Publish Step または [CodePush CLI](/release-management/codepush/codepush-cli/about-the-codepush-cli) のいずれかで行えます。どちらも、プロジェクトがベアの React Native と Expo のどちらを使用しているかを検出します。1回の実行で処理できるプラットフォームは1つのため、iOS 用と Android 用に1回ずつ追加してください。

### Bitrise CodePush Publish Step の使用 {#using-the-bitrise-codepush-publish-step}

ほとんどのプロジェクトでは Step をお勧めします。JavaScript の依存関係をインストールし、アプリをバンドルして、アップデートをアップロードします。`git-clone` Step の後に、プラットフォームごとに1回ずつ追加してください:

```yaml
workflows:
  codepush_update_deploy:
    steps:
    - git-clone@8: {}
    - codepush-publish@1:
        title: Publish iOS update
        inputs:
        - platform: ios
        - app_id: $IOS_CONNECTED_APP_ID
        - deployment: $CODEPUSH_DEPLOYMENT
        - app_version: $APP_TARGET_VERSIONS
        - api_token: $BITRISE_API_TOKEN
    - codepush-publish@1:
        title: Publish Android update
        inputs:
        - platform: android
        - app_id: $ANDROID_CONNECTED_APP_ID
        - deployment: $CODEPUSH_DEPLOYMENT
        - app_version: $APP_TARGET_VERSIONS
        - api_token: $BITRISE_API_TOKEN
```

Step には、`rollout_percentage`、`mandatory`、`description` などの任意の入力もあります。エントリーファイルと Hermes の設定は自動的に検出されますが、`entry_file` と `hermes` で上書きできます。以前の Step ですでに依存関係をインストールしている場合は、`skip_dependency_install` を `"true"` に設定してください。

[アップデートに署名](/release-management/codepush/code-signing-with-codepush)するには、秘密鍵を Secret File としてアップロードし、`private_key_path` にその Environment Variable (例: `$CODEPUSH_PRIVATE_KEY`) を設定します。

Step はアップデートパッケージを `$BITRISE_DEPLOY_DIR` にエクスポートするため、後続の <strong>Deploy to Bitrise.io</strong> Step がそれをビルドのアーティファクトに追加します。

### CodePush CLI の使用 {#using-the-codepush-cli}

アップデートの公開以外の操作が必要な場合 (たとえば、リリースを別のデプロイにプロモートする場合や、ロールバックする場合) は、CLI を使用します。CodePush CLI プラグインをインストールし、依存関係をインストールして、プラットフォームごとに1回ずつ `push --bundle` を実行します。このコマンドは JavaScript をバンドルし、アップデートをアップロードします。CLI は、環境から `BITRISE_API_TOKEN` を自動的に読み取ります。

```yaml
workflows:
  codepush_update_deploy:
    steps:
    - git-clone@8: {}
    - script@1:
        title: Install the CodePush CLI
        inputs:
        - content: bitrise plugin install https://github.com/bitrise-io/bitrise-plugins-codepush-cli.git
    - npm@1:
        inputs:
        - command: install
    - script@1:
        title: Push iOS update
        inputs:
        - content: |-
            bitrise :codepush push --bundle --platform ios \
              --app-id "$IOS_CONNECTED_APP_ID" \
              --deployment "$CODEPUSH_DEPLOYMENT" \
              --app-version "$APP_TARGET_VERSIONS"
    - script@1:
        title: Push Android update
        inputs:
        - content: |-
            bitrise :codepush push --bundle --platform android \
              --app-id "$ANDROID_CONNECTED_APP_ID" \
              --deployment "$CODEPUSH_DEPLOYMENT" \
              --app-version "$APP_TARGET_VERSIONS"
```

Bitrise ビルドでは、CLI がビルド番号とコミットハッシュをアップデートに付与します。また、アップデート ID を次の Steps にエクスポートします。すべてのコマンドとフラグについては、[CodePush CLI リファレンス](/release-management/codepush/codepush-cli/codepush-cli-reference)を参照してください。


## CodePush アップデートのリリースの自動化 {#automating-the-codepush-update-release}

CodePush アップデートを生成してアップロードする Workflow を作成したら、次の2つの方法で実行できます:

- [Workflow を手動で実行します](/bitrise-ci/run-and-analyze-builds/starting-builds/starting-builds-manually)。
- 定義した条件が満たされたときに、[ビルドを自動的にトリガーします](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers)。利用可能な条件については、[サポートされているトリガー条件](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers#supported-trigger-conditions)を参照してください。

複数の種類のトリガーを設定して、プロセスを自動化できます。ここでの設定例では、ラベル付きのプルリクエストトリガーを使用します:

<strong>プルリクエストにラベルが付いたときに CodePush アップデートをリリースする</strong>

この例では、プルリクエストに `release-update` ラベルが付いたときに `codepush_update_deploy` Workflow が実行されるトリガーを設定します。マージ前のテスト用に、プルリクエストを `Staging` などのデプロイにリリースする場合に使用します。

1. [トリガーを作成します](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers#creating-build-triggers): `label` 条件を `release-update` に設定したプルリクエストトリガーを設定します。`target_branch` 条件のデフォルトは `*` で、あらゆるブランチへのプルリクエストが一致します。リリースを特定のブランチに限定するには、`target_branch` も設定します。

   :::tip[GUI設定]

   これらは <GlossTerm baseform="workflow editor">Workflow Editor</GlossTerm> の GUI でも設定できます。ここでは YAML の設定を示します。

   :::

   ```yaml
   format_version: "13"
   default_step_lib_source: https://github.com/bitrise-io/bitrise-steplib.git
   project_type: react-native
   workflows:
     codepush_update_deploy:
       status_report_name: 'Executing <target_id> for <project_title>'
       description: |
         Uploads Update Bundle to Bitrise
       steps:
       [...]
       triggers:
         pull_request:
         - label: release-update
   ```
1. CodePush アップデートをリリースする場合は、プルリクエストを開きます。
1. プルリクエストのレビューと承認が完了したら、`release-update` ラベルを付けます。

:::note

Bitrise は、プルリクエストがマージされる前の、ラベルを追加した時点でビルドを実行します。プルリクエストのコードからアップデートをリリースします。

:::
