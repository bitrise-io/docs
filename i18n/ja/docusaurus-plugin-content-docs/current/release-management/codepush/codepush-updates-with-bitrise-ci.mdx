CodePushアップデートは、[Bitrise CI](/bitrise-ci) <GlossTerm baseform="Workflow">Workflow</GlossTerm>でリリースできます。このプロセスには次のものが必要です。

- CodePushの認証情報の設定: アプリID、デプロイID、ターゲットバージョン、Bitrise APIトークンを保持する[Environment Variables](/bitrise-ci/configure-builds/environment-variables)と、<GlossTerm baseform="Secret">シークレット</GlossTerm>を作成します。
- iOSとAndroidの両方のアップデートパッケージを作成し、両方をBitriseにアップロードするWorkflowの作成。


## BitriseでのCodePush認証情報の設定 {#configuring-codepush-credentials-on-bitrise}

1. [認証情報を取得します](/release-management/codepush/creating-and-releasing-codepush-updates#getting-your-codepush-credentials)。Release ManagementのアプリIDとCodePushのデプロイIDが必要です。
1. デプロイID、接続済みアプリID、ターゲットバージョン用に[Environment Variablesを作成します](/bitrise-ci/configure-builds/environment-variables#setting-an-env-var-in-the-workflow-editor)。

   - `IOS_PROD_DEPLOYMENT_ID`: iOSアプリのデプロイID。
   - `ANDROID_PROD_DEPLOYMENT_ID`: AndroidアプリのデプロイID。
   - `IOS_CONNECTED_APP_ID`: iOSアプリのアプリID。
   - `ANDROID_CONNECTED_APP_ID`: AndroidアプリのアプリID。
   - `APP_TARGET_VERSIONS`: アップデートを受け取るアプリのバージョン。正確なバージョンまたは[範囲式](/release-management/codepush/creating-and-releasing-codepush-updates#target-versions)を使用します。例: `1.2.0`、`>=1.5.0`。

   Bitriseは、アップデートがアプリバージョンのネイティブコードで動作するかどうかを確認できません。どのバージョンに互換性があるかはユーザーが判断するため、リリースのたびに`APP_TARGET_VERSIONS`を自分で設定してください。
1. APIトークン用に[シークレットを作成します](/bitrise-ci/configure-builds/secrets#setting-a-secret)。

   - `BITRISE_API_TOKEN`: パーソナルアクセストークン、または<GlossTerm baseform="workspace">workspace</GlossTerm> APIトークン。


## CodePushアップデート用のWorkflowの作成 {#creating-a-workflow-for-codepush-updates}

このセクションでは、次の処理を行うCI Workflowを作成する方法を説明します。

- iOS用のアップデートパッケージを作成する。
- iOSのアップデートパッケージをBitriseにアップロードする。
- Android用のアップデートパッケージを作成する。
- AndroidのアップデートパッケージをBitriseにアップロードする。

<Tabs>

1. Workflowを作成し、`git-clone` <GlossTerm baseform="step">Step</GlossTerm>の後に、`install`コマンドで`npm` Stepを追加します。

   ```yaml
   ---
   format_version: '13'
   default_step_lib_source: https://github.com/bitrise-io/bitrise-steplib.git
   project_type: react-native
   workflows:
     codepush_update_deploy:
       description: Generates your update and pushes it to Bitrise.
       steps:
       - git-clone@8: {}
       - npm@1:
           inputs:
           - command: install
   ```
1. GitHubから`release-management-recipes`リポジトリをクローンする別の`script` Stepを追加します。このリポジトリには、後で使用するアップロードスクリプトが含まれています。

   ```yaml
   - script@1:
       title: Get Release Management Recipes
       inputs:
       - content: >-
           #!/usr/bin/env bash
           # fail if any commands fails
           set -e
           # make pipelines' return status equal the last command to exit with a
           non-zero status, or zero if all commands exit successfully
           set -o pipefail
           # debug log
           set -x

           # write your script here
           git clone https://github.com/bitrise-io/release-management-recipes
   ```
1. iOSのアップデートバンドルを生成し、そこからzipアーカイブを作成します。

   ```yaml
   - script@1:
       title: Generate iOS Update Bundle
       inputs:
       - content: >-
           #!/usr/bin/env bash
           # fail if any commands fails
           set -e
           # make pipelines' return status equal the last command to exit with a
           non-zero status, or zero if all commands exit successfully
           set -o pipefail
           # debug log
           set -x

           # remove output of earlier runs so the zip holds one platform only
           rm -rf ./build update.zip

           npx react-native bundle \
             --platform ios \
             --dev false \
             --entry-file index.js \
             --bundle-output ./build/main.jsbundle \
             --assets-dest ./build

           # Create zip archive
           zip -r update.zip ./build
   ```
1. `upload_code_push_package.sh`を使用して、iOSのアップデートバンドルをBitriseにアップロードします。

   ```yaml
   - script@1:
       title: Upload iOS Update Bundle to Bitrise
       inputs:
       - content: >
           #!/usr/bin/env bash
           # fail if any commands fails 
           set -e 
           # make pipelines' return status equal the last command to exit with a non-zero status, or zero if all
           commands exit successfully 
           set -o pipefail 
           # debug log 
           set -x

           cd release-management-recipes

           UPLOAD_RESPONSE=$(PACKAGE_PATH=../update.zip \
                           AUTHORIZATION_TOKEN=$BITRISE_API_TOKEN \
                           CONNECTED_APP_ID=$IOS_CONNECTED_APP_ID \
                           DEPLOYMENT_ID=$IOS_PROD_DEPLOYMENT_ID \
                           APP_VERSION=$APP_TARGET_VERSIONS /bin/bash ./api/upload_code_push_package.sh 2>&1)
           EXIT_CODE=$?

           if [ $EXIT_CODE -ne 0 ]; then 
           \  echo \"❌ upload_code_push_package.sh failed with exit code
           $EXIT_CODE\"
           \  echo \"$UPLOAD_RESPONSE\"
           \  exit $EXIT_CODE
           fi

           # Take only the last line of the response (final/latest status JSON
           object) FINAL_RESPONSE=$(echo "$UPLOAD_RESPONSE" | tail -n1)

           # Check explicitly for ERR_INTERNAL or other internal error indicators
           if echo \"$UPLOAD_RESPONSE\" | grep -q \"ERR_INTERNAL\"; then
           \  ERROR_MESSAGE=$(echo \"$FINAL_RESPONSE\" | jq -r '.message' ||
           echo \"Unknown error\")
           \  echo \"❌ Server returned internal error: $ERROR_MESSAGE\"
           \  exit 1
           fi


           # Now safely parse 'status' and 'status_reason' from the final
           response line PACKAGE_STATUS=$(echo "$FINAL_RESPONSE" | jq -r
           '.status' || echo "null") STATUS_REASON=$(echo "$FINAL_RESPONSE" | jq
           -r '.status_reason' || echo "")

           if [ "$PACKAGE_STATUS" = "processed_valid" ]; then   echo "✅ Package
           uploaded and processed successfully."   rm -rf ../build.zip    rm -rf
           ../build else   echo "⚠️ Package upload unexpected status:
           $PACKAGE_STATUS - Reason: $STATUS_REASON"   exit 1 fi cd ..
   ```

## CodePushアップデートリリースの自動化 {#automating-the-codepush-update-release}

CodePushアップデートを生成してアップロードするWorkflowを作成した後は、2つの方法で実行できます。

- [Workflowを手動で実行します](/bitrise-ci/run-and-analyze-builds/starting-builds/starting-builds-manually)。
- 定義した条件が満たされたときに、[ビルドを自動的にトリガーします](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers)。利用可能な条件については、[サポートされているトリガー条件](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers#supported-trigger-conditions)を参照してください。

自動化のために、さまざまな種類のトリガーを複数設定できます。この設定例では、ラベル付きのプルリクエストトリガーを使用します。

<strong>特定のブランチへのプルリクエストにラベルが付いたときにCodePushアップデートをリリースする</strong>

この例では、次のようなトリガーを設定します。

- Bitriseは、`updates`をターゲットブランチとして開かれたプルリクエストを監視します。
- そのブランチへのプルリクエストに`release-update`ラベルが付くと、`codepush_update_deploy` Workflowが実行されます。

1. [トリガーを作成します](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers#creating-build-triggers)。`target_branch`と`label`の2つの条件を持つプルリクエストトリガーを設定します。

   - `target_branch`を`updates`に設定します。
   - `label`を`release-update`に設定します。

   :::tip[GUI設定]

   これらは<GlossTerm baseform="workflow editor">Workflow Editor</GlossTerm>のGUIでも設定できます。ここではYAMLの設定を示しています。

   :::

   ```yaml
   format_version: "13"
   default_step_lib_source: https://github.com/bitrise-io/bitrise-steplib.git
   project_type: react-native
   workflows:
     codepush_update_deploy:
       status_report_name: 'Executing <target_id> for <project_title>'
       description: |
         Uploads Update Bundle to Bitrise
       steps:
       [...]
       triggers:
         pull_request:
         - target_branch: updates
           label: release-update
   ```
1. CodePushアップデートをリリースするときは、`updates`ブランチへのプルリクエストを開きます。
1. プルリクエストがレビューされて承認された後、`release-update`ラベルを付けます。

:::note

ビルドは、マージ後のブランチではなく、プルリクエストのコードで実行されます。Bitriseは、プルリクエストをマージする前にアップデートをリリースします。

:::
