CodePushアップデートは、[Bitrise CI](/bitrise-ci) <GlossTerm baseform="Workflow">Workflow</GlossTerm>でリリースできます。このプロセスには次のものが必要です。

- CodePush認証情報の設定: アプリID、deployment name、ターゲットバージョン、Bitrise APIトークンを保持する[Environment Variables](/bitrise-ci/configure-builds/environment-variables)と<GlossTerm baseform="Secret">シークレット</GlossTerm>を作成します。
- Workflowの作成: iOSとAndroidの両方のアップデートパッケージを作成し、両方をBitriseにアップロードします。


## BitriseでのCodePush認証情報の設定 {#configuring-codepush-credentials-on-bitrise}

1. Release ManagementのアプリID（[確認方法](/release-management/codepush/codepush-cli/using-the-codepush-cli#setting-up-a-project)）と[CodePush deployments](/release-management/codepush/creating-a-codepush-deployment)の名前を取得します。
1. 接続されたアプリID、deployment name、ターゲットバージョン用の[Environment Variablesを作成](/bitrise-ci/configure-builds/environment-variables#setting-an-env-var-in-the-workflow-editor)します。

   - `IOS_CONNECTED_APP_ID`: iOSアプリのアプリID。
   - `ANDROID_CONNECTED_APP_ID`: AndroidアプリのアプリID。
   - `CODEPUSH_DEPLOYMENT`: リリース先のデプロイの名前（例: `Staging`）。
   - `APP_TARGET_VERSIONS`: アップデートを受け取るアプリバージョン。正確なバージョンまたは[範囲式](/release-management/codepush/creating-and-releasing-codepush-updates#target-versions)を使用します（例: `1.2.0`または`>=1.5.0`）。

   デプロイはアプリに属するため、iOSアプリとAndroidアプリにはそれぞれ独自のデプロイがあります。2つのデプロイには同じ名前を付けることができます（例: `Staging`）。その場合、`CODEPUSH_DEPLOYMENT`を`Staging`に設定すると、Bitriseが各アプリに対応するデプロイを見つけます。

   Bitriseは、アップデートがアプリバージョンのネイティブコードで動作するかどうかを確認できません。互換性のあるバージョンはご自身で判断するため、各リリースの前に`APP_TARGET_VERSIONS`を設定してください。
1. 個人用アクセストークンまたは<GlossTerm baseform="workspace">workspace</GlossTerm> APIトークンを保持する、`BITRISE_API_TOKEN`という名前の[シークレットを作成](/bitrise-ci/configure-builds/secrets#setting-a-secret)します。


## CodePushアップデート用のWorkflowの作成 {#creating-a-workflow-for-codepush-updates}

このセクションでは、次の処理を行うCI Workflowの作成方法を説明します。

- iOS用のアップデートパッケージを作成します。
- iOSのアップデートパッケージをBitriseにアップロードします。
- Android用のアップデートパッケージを作成します。
- AndroidのアップデートパッケージをBitriseにアップロードします。

これらのアップデートパッケージの作成とアップロードには、Bitrise CodePush Publish Stepまたは[CodePush CLI](/release-management/codepush/codepush-cli/about-the-codepush-cli)のどちらかを使用できます。どちらもプロジェクトがbare React NativeとExpoのどちらを使用しているかを検出し、1回の実行で1つのプラットフォームを処理します。そのため、iOS用に1回、Android用に1回追加してください。

### Bitrise CodePush Publish Stepの使用 {#using-the-bitrise-codepush-publish-step}

ほとんどのプロジェクトにはStepをお勧めします。JavaScriptの依存関係をインストールし、アプリをバンドルして、アップデートをアップロードします。`git-clone` Stepの後に、プラットフォームごとに1回ずつ追加してください。

```yaml
workflows:
  codepush_update_deploy:
    steps:
    - git-clone@8: {}
    - codepush-publish@1:
        title: Publish iOS update
        inputs:
        - platform: ios
        - app_id: $IOS_CONNECTED_APP_ID
        - deployment: $CODEPUSH_DEPLOYMENT
        - app_version: $APP_TARGET_VERSIONS
        - api_token: $BITRISE_API_TOKEN
    - codepush-publish@1:
        title: Publish Android update
        inputs:
        - platform: android
        - app_id: $ANDROID_CONNECTED_APP_ID
        - deployment: $CODEPUSH_DEPLOYMENT
        - app_version: $APP_TARGET_VERSIONS
        - api_token: $BITRISE_API_TOKEN
```

Stepには、`rollout_percentage`、`mandatory`、`description`などのオプションの入力もあります。エントリファイルとHermesの設定は自動的に検出され、`entry_file`と`hermes`で上書きできます。前のStepですでに依存関係をインストールしている場合は、`skip_dependency_install`を`"true"`に設定してください。

[アップデートに署名する](/release-management/codepush/code-signing-with-codepush)には、秘密鍵をSecret Fileとしてアップロードし、`private_key_path`にその環境変数（例: `$CODEPUSH_PRIVATE_KEY`）を設定します。

Stepはアップデートパッケージを`$BITRISE_DEPLOY_DIR`にエクスポートするため、後続の<strong>Deploy to Bitrise.io</strong> Stepがそれをビルドのアーティファクトに追加します。

### CodePush CLIの使用 {#using-the-codepush-cli}

アップデートの公開以外の操作が必要な場合（たとえば、リリースを別のデプロイに昇格させたり、ロールバックしたりする場合）は、CLIを使用します。CodePush CLIプラグインと依存関係をインストールしてから、プラットフォームごとに1回ずつ`push --bundle`を実行します。このコマンドはJavaScriptをバンドルし、アップデートをアップロードします。CLIは環境から`BITRISE_API_TOKEN`を自動的に読み取ります。

```yaml
workflows:
  codepush_update_deploy:
    steps:
    - git-clone@8: {}
    - script@1:
        title: Install the CodePush CLI
        inputs:
        - content: bitrise plugin install https://github.com/bitrise-io/bitrise-plugins-codepush-cli.git
    - npm@1:
        inputs:
        - command: install
    - script@1:
        title: Push iOS update
        inputs:
        - content: |-
            bitrise :codepush push --bundle --platform ios \
              --app-id "$IOS_CONNECTED_APP_ID" \
              --deployment "$CODEPUSH_DEPLOYMENT" \
              --app-version "$APP_TARGET_VERSIONS"
    - script@1:
        title: Push Android update
        inputs:
        - content: |-
            bitrise :codepush push --bundle --platform android \
              --app-id "$ANDROID_CONNECTED_APP_ID" \
              --deployment "$CODEPUSH_DEPLOYMENT" \
              --app-version "$APP_TARGET_VERSIONS"
```

Bitriseビルドでは、CLIがビルド番号とコミットハッシュをアップデートに付加します。また、アップデートIDを次のStepsにエクスポートします。すべてのコマンドとフラグについては、[CodePush CLIリファレンス](/release-management/codepush/codepush-cli/codepush-cli-reference)を参照してください。


## CodePushアップデートリリースの自動化 {#automating-the-codepush-update-release}

CodePushアップデートを生成してアップロードするWorkflowを作成したら、次の2つの方法で実行できます。

- [Workflowを手動で実行する](/bitrise-ci/run-and-analyze-builds/starting-builds/starting-builds-manually)。
- 定義した条件が満たされたときに[ビルドを自動的にトリガーする](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers)。使用できる条件については、[サポートされているトリガー条件](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers#supported-trigger-conditions)を参照してください。

さまざまな種類のトリガーを設定して、プロセスを自動化できます。この設定例では、ラベルを使ったプルリクエストトリガーを使用します。

<strong>プルリクエストにラベルが付いたときにCodePushアップデートをリリースする</strong>

この例では、いずれかのプルリクエストに`release-update`ラベルが付いたときに`codepush_update_deploy` Workflowが実行されるトリガーを設定します。マージする前のテストとして、プルリクエストを`Staging`などのデプロイにリリースする場合に使用します。

1. [トリガーを作成します](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers#creating-build-triggers)。`label`条件を`release-update`に設定したプルリクエストトリガーを設定します。`target_branch`条件のデフォルトは`*`のため、すべてのブランチへのプルリクエストが一致します。リリースを1つのブランチに限定するには、`target_branch`も設定してください。

   :::tip[GUI設定]

   これらは<GlossTerm baseform="workflow editor">Workflow Editor</GlossTerm>のGUIでも設定できます。ここではYAMLの設定を示しています。

   :::

   ```yaml
   format_version: "13"
   default_step_lib_source: https://github.com/bitrise-io/bitrise-steplib.git
   project_type: react-native
   workflows:
     codepush_update_deploy:
       status_report_name: 'Executing <target_id> for <project_title>'
       description: |
         Uploads Update Bundle to Bitrise
       steps:
       [...]
       triggers:
         pull_request:
         - label: release-update
   ```
1. CodePushアップデートをリリースするときは、プルリクエストを作成します。
1. プルリクエストがレビューされて承認されたら、`release-update`ラベルを追加します。

:::note

Bitriseは、ラベルを追加した時点で、プルリクエストがマージされる前にビルドを実行します。アップデートはプルリクエストのコードからリリースされます。

:::
