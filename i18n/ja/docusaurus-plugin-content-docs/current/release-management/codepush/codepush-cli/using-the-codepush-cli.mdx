## プロジェクトのセットアップ {#setting-up-a-project}

CodePush CLIのインストールと認証の設定が完了したら、プロジェクトを初期化して、アプリIDをローカルに保存します。

```bash
bitrise :codepush init
```

このコマンドは、カレントディレクトリに`.codepush.json`ファイルを作成します。このファイルをバージョン管理にコミットすると、チームで同じ設定を共有できます。

`init`を初めて実行すると、CLIがアプリIDの入力を求めます。アプリIDは、Release ManagementのアプリのURLから取得できます: `https://app.bitrise.io/release-management/workspaces/<workspace-slug>/connected-apps/<app-id>/`、または[API経由](https://api.bitrise.io/release-management/api-docs/index.html#/Connected%20Apps/ListApps)で取得できます。

```yaml
Enter your app ID (UUID):
>a3f47d2c-6b9e-4f1a-9d2b-7c8e5a1b2c3d
```

`--app-id`で直接指定するか、`CODEPUSH_APP_ID`環境変数を設定することもできます。CLIは、次の順序でアプリIDを解決します。

1. `--app-id`フラグ (最優先)
1. `CODEPUSH_APP_ID`環境変数
1. `.codepush.json`内の`app_id`フィールド

既存の`.codepush.json`を上書きするには、次のようにします。

```bash
bitrise :codepush init --force --app-id a3f47d2c-6b9e-4f1a-9d2b-7c8e5a1b2c3d
```


## Release management

### アプリのバンドル {#bundling-your-app}

`bundle`コマンドは、React NativeおよびExpoプロジェクト向けのJavaScriptバンドルを生成します。プロジェクトの種類、エントリーファイル、Hermesの設定、Metroの設定を自動で検出します。

プラットフォームごとに個別にアプリをバンドルします。

```bash
bitrise :codepush bundle --platform ios
bitrise :codepush bundle --platform android
```

自動検出に失敗した場合は、関連するフラグを手動で指定します。

```bash
bitrise :codepush bundle --platform ios \
  --entry-file index.js \
  --config metro.config.js \
  --pod-file ios/Podfile
```

Hermesを使用するAndroidでは、`--pod-file`の代わりに`--gradle-file`を使用します。

```bash
bitrise :codepush bundle --platform android \
  --entry-file index.js \
  --gradle-file android/app/build.gradle
```

CLIは、デフォルトでソースマップを生成し、`push`がアップロードするバンドルディレクトリの外にある`<output-dir>.sourcemaps/<bundle-name>.map`に書き込みます。別の場所に書き込むには、`--sourcemap-output` (`-s`) を使用します。パスは出力ディレクトリの外にする必要があります。

```bash
bitrise :codepush bundle --platform ios \
  --sourcemap-output ./sourcemaps/main.jsbundle.map
```

バンドルとプッシュを1ステップで行う場合、`push --bundle`は同じ`--sourcemap`フラグと`--sourcemap-output`フラグを受け付けます。

### アップデートのプッシュ {#pushing-updates}

`push`コマンドは、ビルド済みのバンドルをCodePushサーバーにアップロードします。デプロイとアプリバージョンを指定する必要があります。

```bash
bitrise :codepush push ./codepush-bundle \
  --deployment Staging --app-version 1.0.0
```

`--bundle`フラグを使用すると、バンドルとプッシュを1ステップで行うこともできます。

```bash
bitrise :codepush push --bundle --platform ios \
  --deployment Staging --app-version 1.0.0
```

### リリースのプロモート {#promoting-a-release}

`promote`コマンドは、あるデプロイから別のデプロイにリリースをコピーします。ステージング環境から本番環境へリリースを移行する際に最もよく使用されます。

```bash
bitrise :codepush promote \
  --source-deployment Staging \
  --destination-deployment Production \
  --rollout 25 --description "Gradual rollout"
```

:::tip

対象のデプロイに同一内容のリリースがすでに存在する場合に、エラーではなく警告付きで終了コード0で終了するには、`--no-duplicate-release-error`を指定します。

:::

### リリースのパッチ適用 {#patching-a-release}

`patch`コマンドは、コードを再デプロイせずに、既存のリリースのメタデータを更新します。

ラベルを指定して特定のリリースにパッチを適用します。

```bash
bitrise :codepush patch --deployment Production --label v5 --mandatory true
```

最新のリリースのrollout percentageを引き上げます。

```bash
bitrise :codepush patch --deployment Production --rollout 50
```

### ロールバック {#rolling-back}

`rollback`コマンドは、以前のバージョンを再現する新しいリリースを作成します。

直前のリリースにロールバックします。

```bash
bitrise :codepush rollback --deployment Production
```

ラベルを指定して特定のリリースにロールバックします。

```bash
bitrise :codepush rollback --deployment Production --target-release v3
```


## デプロイの管理 {#deployment-management}

デプロイを作成して、デプロイキーを取得します。アプリにCodePushアップデートをリリースするには、デプロイキーが必要です。

すべてのデプロイを一覧表示します。

```bash
bitrise :codepush deployment list
bitrise :codepush deployment list --display-keys  # include deployment keys
```

新しいデプロイを作成します。

```bash
bitrise :codepush deployment add Beta
```

カスタムのデプロイキーを指定して新しいデプロイを作成します。

```bash
bitrise :codepush deployment add Beta --key my-custom-key
```

デプロイの詳細と最新のリリースを表示します。

```bash
bitrise :codepush deployment info Staging
```

リリース履歴を表示します。デフォルトでは、直近10件のリリースが表示されます。

```bash
bitrise :codepush deployment history Staging
bitrise :codepush deployment history Staging --limit 25
bitrise :codepush deployment history Staging --display-author
```

デプロイの名前を変更します。

```bash
bitrise :codepush deployment rename OldName --name NewName
```

デプロイからすべてのリリースを消去します。これは破壊的な操作です。CIで確認プロンプトをスキップするには、`--yes`を指定します。

```bash
bitrise :codepush deployment clear Staging --yes
```

デプロイを削除します。これは破壊的な操作です。CIで確認プロンプトをスキップするには、`--yes`を指定します。

```bash
bitrise :codepush deployment remove Beta --yes
```


## アップデートの管理 {#update-management}

デプロイ内の最新のアップデートの詳細を表示します。

```bash
bitrise :codepush update info Staging
```

ラベルを指定して特定のアップデートを表示します。

```bash
bitrise :codepush update info Staging --label v5
```

アップデートの処理ステータスを確認します。プッシュ後にアップデートが受理されたことを確認する際に便利です。

```bash
bitrise :codepush update status Staging
```

特定のアップデートを削除します。`--label`でアップデートを指定し、`--yes`で確認を省略します。

```bash
bitrise :codepush update remove Staging --label v3 --yes
```


## JSON出力 {#json-output}

任意のコマンドに`--json`を指定すると、機械可読なJSON出力が stdout に出力されます。人間が読める出力は常に stderr に出力されるため、JSON出力はパイプ処理に適したクリーンな状態になります。

プッシュ結果をJSONで取得します。

```bash
bitrise :codepush push ./CodePush \
  --deployment Staging --app-version 1.0.0 --json
```

デプロイをJSONで一覧表示します。

```bash
bitrise :codepush deployment list --json
```

`jq`で出力を解析します。

```bash
bitrise :codepush update info Staging --json | jq '.app_version'
```


## Bitrise CIとの統合 {#bitrise-ci-integration}

CLIは、`BITRISE_BUILD_NUMBER`または`BITRISE_DEPLOY_DIR`environment variablesからBitrise CI環境を検出します。Bitriseビルド内で実行すると、CLIは自動的に次の処理を行います。

- ビルド番号とコミットハッシュをプッシュのメタデータに付加します。
- バンドル後に`codepush-bundle-summary.json`をエクスポートします。
- プッシュ後に`codepush-push-summary.json`をエクスポートします。
- パッチ適用後に`codepush-patch-summary.json`をエクスポートします。
- 後続の Step で使用できるように、`envman`経由でenvironment variablesをエクスポートします。
- 対話型のプロンプトとスピナーを無効にします。


## Workflowの例 {#workflow-examples}

### リリースライフサイクル全体 {#full-release-lifecycle}

1. Bitrise API トークンで認証します。

   ```bash
   bitrise :codepush auth login --token $BITRISE_API_TOKEN
   ```

1. 対象プラットフォーム向けにJavaScriptをバンドルします。

   ```bash
   bitrise :codepush bundle --platform ios
   ```

1. 限定的なロールアウトで Staging にプッシュします。

   ```bash
   bitrise :codepush push ./CodePush \
     --deployment Staging \
     --app-version 1.2.0 --rollout 10 --description "Fix login crash"
   ```

1. 処理ステータスを確認して、アップデートが受理されたことを確かめます。

   ```bash
   bitrise :codepush update status Staging
   ```

1. テストデバイスで確認した後、ロールアウトを引き上げます。

   ```bash
   bitrise :codepush patch --deployment Staging --rollout 100
   ```

1. Production にプロモートします。

   ```bash
   bitrise :codepush promote \
     --source-deployment Staging \
     --destination-deployment Production \
     --rollout 25
   ```

1. 問題が発生した場合は、ロールバックします。

   ```bash
   bitrise :codepush rollback --deployment Production
   ```

### Bitrise CIパイプライン {#bitrise-ci-pipeline}

Bitrise Workflowで、`BITRISE_API_TOKEN`、`CODEPUSH_APP_ID`、`CODEPUSH_DEPLOYMENT`をenvironment variablesとして設定し、次のコマンドを1つ実行します。

```bash
bitrise :codepush push --bundle --platform ios --app-version $APP_VERSION
```

CLIはBitrise環境を自動的に検出し、ビルドのメタデータ (ビルド番号とコミットハッシュ) を付加して、サマリーファイルを`$BITRISE_DEPLOY_DIR`にエクスポートします。

### Expoワークフロー {#expo-workflow}

Expoは`package.json`から自動検出されるため、追加のフラグは不要です。CLIは、内部で`react-native bundle`の代わりに`npx expo export:embed`を使用します。その他のフラグ (デプロイ、アプリバージョン、ロールアウトなど) は、まったく同じように動作します。

```bash
bitrise :codepush push --bundle --platform ios \
  --deployment Staging \
  --app-version 1.0.0
```

2つのフラグでバンドラーの動作を制御します。

- `--minify` (デフォルトは`false`): バンドルを minify するかどうかを指定します。デバッグしやすいように、デフォルトでは無効になっています。バンドルを最小サイズにするには、`--minify=true`を設定します。
- `--reset-cache` (デフォルトは`true`): 実行のたびに Metro バンドラーのキャッシュをクリアして、クリーンな出力を保証します。キャッシュのクリアをスキップして、ローカルでの繰り返し実行を高速化するには、`--reset-cache=false`を設定します。
