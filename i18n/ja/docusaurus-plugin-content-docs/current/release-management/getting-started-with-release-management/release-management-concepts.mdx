Release Managementを正しく使用するには、いくつか理解しておくべき概念があります。

## 接続済みアプリ {#connected-app}

[アプリを接続](/release-management/getting-started-with-release-management/connecting-an-app)App StoreまたはGoogle Playから、Bitrise projectに接続します。これを接続済みアプリ(connected app)と呼びます。

Release Managementでリリースを追加・管理するには、少なくとも1つの接続済みアプリが必要です。[ビルド配布](/release-management/build-distribution/distributing-builds-to-testers)を使用するだけであれば、アプリを接続する必要はありません。

## リリース {#releases}

接続済みアプリの[リリースを管理](/release-management/releases/adding-a-new-release)します。各リリースは、アプリの新しいバージョンです。iOSのリリースにはバージョン番号があり、Androidのリリースにはリリース名があります。

## Release Manager

Release Managementのチームメンバーのうち、リリースを管理するための[必要な権限](/release-management/configuring-connected-apps/release-management-roles-and-permissions)を持つ人です。プロジェクト管理者は、[チームメンバー](/release-management/configuring-connected-apps/release-management-roles-and-permissions)にRelease Managerロールを付与できます。このロールを持つRelease Managerだけが、Release Managementでエンドユーザーに影響するすべての操作(iOSアプリの審査提出や、アプリストアへのアプリのリリース)を実行できます。

## Release presets

接続済みアプリごとに、新しい空のリリースに自動的に適用される設定値として[プリセット](/release-management/releases/release-presets)を定義できます。プリセットの適用後も、release process中にこれらの値を編集できます。

[リリースノートのプリセット](/release-management/releases/release-presets)も作成できます。これにより、すべてのリリースが同じリリースノートでApp StoreまたはGoogle Playに提出されます。リリースノートのプリセットはすべてのローカライズで同一にすることも、リリースステージで手動で編集することもできます。

## リリースステージ {#release-stages}

接続済みアプリに新しいリリースを追加して設定したら、release processのさまざまなリリース手順(ステージ)に進めます。次のリリースステージに進めるのは現在のステージを完了した後のみですが、前のステージにはいつでも戻れます。

iOS

Android

1. [リリース候補](/release-management/releases/managing-the-release-process/selecting-a-release-candidate): <strong>Release candidate</strong>ステージで、release branchを指定し、IPAファイルを生成するWorkflowを選択します。
1. [TestFlight](/release-management/releases/managing-the-release-process/testflight-upload-stage#uploading-the-release-candidate-to-testflight): リリース候補をTestFlightにアップロードし、テスト用に配布します。
1. [承認](/release-management/releases/managing-the-release-process/creating-tasks-for-the-approvals-stage): App Storeへのリリースを続行するために承認が必要なステークホルダーやチームメンバーに対して、タスクを作成できます。
1. [App Store審査](/release-management/releases/managing-the-release-process/sending-your-app-to-app-store-review): アップデートをApp Storeの審査に提出し、承認の進捗情報を確認します。
1. [App Storeでのリリース](/release-management/releases/managing-the-release-process/releasing-your-app-on-the-app-store): すべてのユーザーに同時にアプリをリリースするか、段階的リリースを設定できます。

1. [リリース候補](/release-management/releases/managing-the-release-process/selecting-a-release-candidate): <strong>Release candidate</strong>ステージで、release branchを指定し、AABファイルを生成するWorkflowを選択します。
1. [Google Playのアップロードとテスト](/release-management/releases/managing-the-release-process/google-play-upload-stage#uploading-the-release-candidate-to-google-play): リリース候補をGoogle Playにアップロードし、テスト用に配布します。
1. [承認](/release-management/releases/managing-the-release-process/creating-tasks-for-the-approvals-stage): Google Playへのリリースを続行するために承認が必要なステークホルダーやチームメンバーに対して、タスクを作成できます。
1. [Google Playでのリリース](/release-management/releases/managing-the-release-process/releasing-your-app-on-the-app-store): すべてのユーザーに同時にアプリをリリースするか、段階的なロールアウトを設定できます。

## ビルド配布 {#build-distribution}

Release Managementを使用すると、TestFlightやGoogle Playを利用することなく、[モバイルアプリのビルドをテスターに配布](/release-management/build-distribution/distributing-builds-to-testers)できます。

インストール可能なアーティファクトがあれば、Bitriseはプライベートとパブリックの両方のインストールリンクを生成でき、テスターやその他の関係者はそのリンクからOver-the-Air (OTA)インストールで実機にアプリをインストールできます。

インストール可能なアーティファクトに関する通知とアクセス先を受け取る[テスターグループを定義](/release-management/build-distribution/tester-groups)できます。

## 承認タスク {#approval-task}

App Store ConnectまたはGoogle Playへのリリースを続行するために承認が必要なステークホルダーやチームメンバーごとに、[タスクを作成](/release-management/releases/managing-the-release-process/creating-tasks-for-the-approvals-stage)できます。

必要に応じて、承認タスクをチームメンバーに割り当てるか、未割り当てのままにできます。割り当てられたチームメンバーだけがタスクを承認できます。必要な数のタスクを作成して割り当てることができます。すべてのタスクにチェックが入ると、左側のナビゲーションバーの<strong>Approvals</strong>にもチェックが入り、App Store審査、またはGoogle Playへのアプリのリリースに進めます。
