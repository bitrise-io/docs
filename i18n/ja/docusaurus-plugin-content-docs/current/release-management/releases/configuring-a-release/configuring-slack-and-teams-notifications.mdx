Release Managementイベントについて、SlackとMicrosoft Teamsの通知を有効にできます。利用したいサービスで受信Webhookを作成し（両方作成することも可能です）、Release Managementにwebhook URLを追加してください。

:::important[Standardプランのみ]

この機能は[有料プラン](https://bitrise.io/pricing)でのみ利用できますのでご注意ください。

:::

## リリースの通知を設定する {#configuring-notifications-for-a-release}

各リリースごとに個別に通知を設定できます。

<Tabs>
<TabItem value="slack" label="Slack" default>

1. workspace](/bitrise-platform/workspaces/workspace-slack-integration)用にSlackインテグレーションを設定します。
1. <Partial_GettingToReleaseConfiguration />
1. <strong>Release process</strong>セクションで<strong>Notifications</strong>カードを見つけます。
1. <strong>Show details</strong>をクリックします。
1. <strong>Slack</strong>の横にあるオプションメニュー（⋮）をクリックします。

   ![2025-08-08-rm-slack-notification.png](/img/_paligo/uuid-40c38dac-74da-dcc2-0e07-64366c2732dc.png)
1. <strong>Change configuration</strong>をクリックします。
1. ダイアログで、事前に設定したSlack configurationを選択します。

   :::tip[テスト通知]

   設定が正しく機能することを確認するため、<strong>Send test notification</strong>をクリックしてください。

   :::

</TabItem>
<TabItem value="teams" label="Teams">

1. [Teams用の受信Webhook](https://learn.microsoft.com/en-us/microsoftteams/platform/webhooks-and-connectors/how-to/add-incoming-webhook?tabs=dotnet)を設定します。
1. <Partial_GettingToReleaseConfiguration />
1. <strong>Release process</strong>セクションで<strong>Notifications</strong>カードを見つけます。
1. <strong>Show details</strong>をクリックします。
1. <strong>Teams</strong>の横にあるオプションメニュー（⋮）をクリックします。
1. <strong>Edit webhook URL</strong>を選択します

   ![2025-08-08-rm-configure-teams-notification.png](/img/_paligo/uuid-823c9a6f-187a-6778-36eb-130492487193.png)
1. ダイアログの<strong>URL</strong>フィールドにwebhook URLをコピーして貼り付け、<strong>Save</strong>をクリックします。

   :::tip[テスト通知]

   Webhookが正しく機能することを確認するため、<strong>Send test notification</strong>をクリックしてください。

   :::

</TabItem>
</Tabs>

## リリースプリセットとして通知を設定する {#configuring-notifications-as-a-release-preset}

[リリースプリセットテンプレート](/release-management/releases/release-presets)の一部として通知を設定できます。これらの通知設定は、このテンプレートを使用するすべての新しいリリースに適用されます。

<Tabs>
<TabItem value="slack" label="Slack" default>

1. workspace](/bitrise-platform/workspaces/workspace-slack-integration)用にSlackインテグレーションを設定します。
1. Release Managementを開き、一覧からyour appを選択します。
1. 左側のナビゲーションメニューから<strong>Release presets</strong>を選択します。

   ![release-presets-notif.png](/img/_paligo/uuid-7c480e99-66d6-8197-a63a-e9275e127d78.png)
1. 必要なテンプレートの横にあるオプションメニュー（⋮）をクリックし、<strong>Change</strong>を選択します。
1. <strong>Notifications</strong>セクションでSlackを見つけ、その名前の横にある省略記号をクリックします。

   ![slack-int-rm.png](/img/_paligo/uuid-0876f906-f150-c883-a882-3d1da1ae42dc.png)
1. <strong>Change configuration</strong>をクリックします。
1. ダイアログで、事前に設定したインテグレーションを選択します。

   :::tip[テスト通知]

   設定が正しく機能することを確認するため、<strong>Send test notification</strong>をクリックしてください。

   :::

</TabItem>
<TabItem value="teams" label="Teams">

1. [Teamsでの受信Webhook](https://learn.microsoft.com/en-us/microsoftteams/platform/webhooks-and-connectors/how-to/add-incoming-webhook?tabs=dotnet)を設定します。
1. Release Managementを開き、一覧からyour appを選択します。
1. 左側のナビゲーションメニューから<strong>Release presets</strong>を選択します。

   ![release-presets-notif.png](/img/_paligo/uuid-7c480e99-66d6-8197-a63a-e9275e127d78.png)
1. 必要なテンプレートの横にあるオプションメニュー（⋮）をクリックし、<strong>Change</strong>を選択します。
1. <strong>Notifications</strong>セクションでTeamsを見つけ、その横にある省略記号をクリックします。
1. <strong>Edit webhook URL</strong>をクリックします。
1. ダイアログの<strong>URL</strong>フィールドにwebhook URLをコピーして貼り付け、<strong>Save</strong>をクリックします。

   :::tip[テスト通知]

   Webhookが正しく機能することを確認するため、<strong>Send test notification</strong>をクリックしてください。

   :::

</TabItem>
</Tabs>

## Notification events

| ステージ | イベント | イベントの説明 |
| --- | --- | --- |
| リリース候補 | リリース候補設定済み | Release candidate stageで新しいリリース候補が選択されるたびにこのイベントがトリガーされます。これは自動的に発生する場合（新しいビルドが新しいIPAを生成した場合）と、手動で発生する場合（リリースマネージャーがRelease candidate stage上で特定のアーティファクトをロックした場合）があります。 |
| TestFlightアップロード | アップロードと処理が完了 | アップロードされたIPAのTestFlight処理が完了するとこのイベントがトリガーされます。まずIPAをTestFlightにアップロードし、その後TestFlightの処理が開始されます。処理が完了すると、イベントを<GlossTerm baseform="trigger">トリガー</GlossTerm>します。 |
|  | TestFlightアプリレビューで承認済み | 外部ベータテスターとアプリを共有するために必要なベータアプリレビューをAppleが承認するとこのイベントがトリガーされます。 |
|  | TestFlightアプリレビューで却下 | 外部ベータテスターとアプリを共有するために必要なベータアプリレビューをAppleが却下するとこのイベントがトリガーされます。 |
| 承認 | リリース承認済み | 承認ステージですべてのタスクが承認されるとこのイベントがトリガーされます。個々の承認のたびにはトリガーされず、すべてのタスクが完了した時点でのみトリガーされます。承認タスクが設定されていない場合、前のイベントの直後にこのイベントがトリガーされます。 |
| App Storeレビュー | レビューのためリリース送信済み | ストアレビューの提出が開始されるとこのイベントが発生します（リリースマネージャーが送信ボタンをクリックし、Appleがそれを受理したとき）。 |
|  | レビュー提出のステータスが変更 | レビュー提出のステータスに変更があるたびにこのイベントがトリガーされます（承認、却下、キャンセルなど）。 |
| リリース | リリース開始済み | 提出が受理され、リリースのロールアウトが開始した後にこのイベントがトリガーされます（つまり新しいバージョンがApp Store Connectで利用可能になります）。 |
|  | リリース完了 | Release Managementでリリースが完了ステータスになるとこのイベントがトリガーされます（これはリリースがGoogle PlayまたはApp Storeに完全にロールアウトされたことを意味します）。 |

| ステージ | イベント | イベントの説明 |
| --- | --- | --- |
| リリース候補 | リリース候補設定済み | Release Candidate stageで新しいリリース候補が選択されるたびにこのイベントがトリガーされます。これは自動的に発生する場合（新しいビルドが新しいAABを生成した場合）と、手動で発生する場合（リリースマネージャーがRelease candidate stage上で特定のアーティファクトをロックした場合）があります。 |
| Google Playアップロード | アップロードと処理が完了 | AABがGoogle Play consoleにアップロードされ、App bundle explorerで利用可能になった後にこのイベントがトリガーされます。 |
|  | テストトラックでリリース | リリース候補がGoogle Playのテストトラックでリリースされた後にこのイベントがトリガーされます。 |
| 承認 | リリース承認済み | 承認ステージですべてのタスクが承認されるとこのイベントがトリガーされます。個々の承認のたびにはトリガーされず、すべてのタスクが完了した時点でのみトリガーされます。 |
| リリース | リリース開始済み | リリースが開始されるとこのイベントがトリガーされます。これは完全リリースの場合と段階的ロールアウトの場合があります。段階的ロールアウトの場合、最初のロールアウト時に一度だけ発生します。 |
|  | リリース完了 | Release Managementでリリースが完了するとこのイベントがトリガーされます。 |
|  | Rollout percentageが変更 | rollout percentageが0%以外の割合から変化するとこのイベントがトリガーされます。たとえば、rollout percentageが10%から20%に変化した場合です。最初のロールアウトが発生したときにはトリガーされません。 |
