インストール可能なアーティファクトをRelease Managementにアップロードしてリリース候補として使用するには、2 つの方法があります。

- [接続済みアプリ](/release-management/getting-started-with-release-management/connecting-an-app)の Bitrise ビルドで生成する。
- API エンドポイントを使用する。Bitrise ではなく別の CI サービスを使用している場合に特に便利です。
- [用意されている bash スクリプト](https://github.com/bitrise-io/release-management-recipes/blob/main/api/upload_installable_artifact.sh)を使用して、API エンドポイントを利用する。

## Bitrise ビルドを使用する {#using-a-bitrise-build}

Bitrise CIを使用している場合、インストール可能なアーティファクトを入手するには、アーティファクトを生成するビルドを実行するだけです。

1. Release Managementに[接続済みアプリ](/release-management/getting-started-with-release-management/connecting-an-app)があることを確認します。
1. インストール可能なアーティファクト (IPA、APK、AAB) を生成するBitrise <GlossTerm baseform="workflow">Workflow</GlossTerm>に、[<strong>Deploy to Bitrise.io</strong>](https://github.com/bitrise-steplib/steps-deploy-to-bitrise-io) <GlossTerm baseform="step">Step</GlossTerm>があることを確認します。
1. ビルドを実行します。

成功したビルドのインストール可能なアーティファクトはすべて <strong>Artifacts</strong> ページに表示され、[リリース候補として選択](/release-management/releases/managing-the-release-process/selecting-a-release-candidate)できます。

## APIの使用 {#using-the-api}

APIでは、インストール可能なアーティファクトをアップロードするために 2 つのリクエストが必要です。

1. 1 つ目のリクエストは、アップロード情報を取得するためのものです。このリクエストには次の内容を含める必要があります。

   - APIの認証トークン。[Workspace トークン](/bitrise-platform/workspaces/workspace-api-token)と[パーソナルアクセストークン](/bitrise-platform/accounts/personal-access-tokens)のどちらも使用できます。
   - 接続済みアプリの ID。Release Management UIからリクエストを取得した場合は、自動的に入力されます。
   - アーティファクト用に生成する新しい UUID (リクエスト内の `[NEW_ARTIFACT_UUID]`)。
   - ファイル名とバイト単位のファイルサイズ。
1. 2 つ目のリクエストは、ファイルをartifact storageにアップロードするためのものです。リクエストは、前のリクエストのレスポンスを使用して作成する必要があります。レスポンスには次の内容が含まれます。

   - 必要なHTTPヘッダー。
   - アップロードに使用するHTTPメソッド。
   - リクエスト (必要な情報をすべて含む) の送信先のURL。
1. 必要に応じて、3 つ目のリクエストでアップロードのステータスを確認できます。1 つ目のリクエストと同じアーティファクトの UUID を使用します。

関連するエンドポイントは、[公式の API ドキュメント](https://api.bitrise.io/release-management/api-docs/index.html#/Installable%20Artifacts%20-%20COMING%20SOON/GenerateInstallableArtifactUploadUrl)で確認できます。

APIリクエストは、<strong>Release candidate</strong> ステージまたは <strong>Artifacts</strong> ページから取得できます。

1. APIリクエストを使用して、アーティファクトをアップロードします。

## bash スクリプトの使用 {#using-the-bash-script}

APIをより便利に使えるように、アップロード手順を簡素化する bash スクリプトを用意しています。このスクリプトは、Linux ディストリビューション (alpine、arch、centos、debian、fedora、rhel、ubuntu) と macOS をサポートしています。スクリプトはシステムを確認した後、インストール可能なアーティファクトをRelease Managementにアップロードしようとします。

スクリプトを使用するには、次の手順を実行します。

1. [GitHubからスクリプトを取得](https://gist.github.com/miklosboros/4855a59213724f6eb5960579e15d285b)します。
1. システムで `sudo` 権限があること、または `jq` と `openssl` のパッケージがインストールされていることを確認します。
1. システムで次のEnvironment Variablesを Set up します。

   - ARTIFACT_PATH: アップロードするアーティファクトのローカルパス。
   - AUTHORIZATION_TOKEN: Bitrise Release Management API のアクセストークン。Bitrise [パーソナルアクセストークン](/bitrise-platform/accounts/personal-access-tokens)または [Workspace トークン](/bitrise-platform/workspaces/workspace-api-token)を使用できます。
   - CONNECTED_APP_ID: アーティファクトのアップロード先となる[接続済みアプリ](/release-management/getting-started-with-release-management/connecting-an-app)のアプリ ID。ID は、bitrise.io のアプリのページの URL で確認できます: https://app.bitrise.io/release-management/workspaces/WORKSPACE_ID/connected-apps/CONNECTED_APP_ID.
1. スクリプトを実行します。
