Release Managementで操作を実行するには、アカウントに必要なアクセス権が付与されている必要があります。このアクセス権は権限によって制御されます。権限とは、アプリの追加と接続、リリースの作成、接続済みapp settingsの変更など、特定の操作を実行できる能力のことです。

## ロールと権限の概要 {#roles-and-permissions-overview}

チームメンバーにはそれぞれ異なるロールを割り当てることができます。Release Managementには、3つのレベルにわたる5つのロールがあります。

- <strong>Workspaceレベルのロール</strong>: これらのロールは特定のRelease Managementアプリに紐づいておらず、Release Managementで変更することもできません。[接続済みアプリが属するBitrise projectを所有するWorkspaceに完全に紐づいています](/bitrise-platform/workspaces/collaboration-and-permissions-in-workspaces/workspace-collaboration)。Workspaceレベルのロールは次のとおりです。

  - <strong>Workspaceオーナー</strong>: Workspaceオーナーは、Release Management内のアプリのあらゆる側面に対して、制限や例外なく完全な管理権限を持ちます。
  - <strong>Workspaceマネージャー</strong>: workspaceマネージャーの主な目的は、workspaceのコラボレーションを管理することです。Release Managementでは、新しいプロジェクトの作成時に新しいアプリを追加し、リリースマネージャーを指名できます。ただし、既存のプロジェクトの下に新しいRMアプリを追加することはできません。
  - <strong>Contributor</strong>および<strong>Viewer</strong>: これらのWorkspaceレベルのロールには、Release Managementアプリへのデフォルトのアクセス権はありません。
- <strong>Project admin</strong>: Release Managementで唯一の[プロジェクトレベルのロール](/bitrise-platform/projects/roles-and-permissions-for-bitrise-ci)です。ユーザーをプロジェクトに追加しても、Adminロールを持つユーザーを除き、Release Managementでの権限が自動的に付与されることはありません。プロジェクト管理者は、アプリ、ビルド、Release Management、アプリのデプロイに対する完全な管理権限を持ちますが、いくつかの例外があります。Release Managementに新しいプロジェクトとともに新しいアプリを追加すること、Standardライセンスを購入すること、CodePushアドオンのプランを変更することはできません。Release Managementに新しいアプリを追加する場合は、自身が管理者であるプロジェクトの下にのみ追加できます。
- <strong>Release Managementレベルのロール</strong>: Release Management内で設定できるロールです。

  - <strong>Release manager</strong>: リリースマネージャーの主な目的は、オンラインストアへのリリースを処理することです。新しいアプリの追加やインテグレーションへのアクセスはできません。
  - <strong>App tester</strong>: App testerロールは、社内テスター向けです。アプリとそのアーティファクト、および[ビルド配布](/release-management/build-distribution/distributing-builds-to-testers)と[テスターグループ](/release-management/build-distribution/tester-groups)メニューにアクセスできます。それ以外のアクセス権はありません。
