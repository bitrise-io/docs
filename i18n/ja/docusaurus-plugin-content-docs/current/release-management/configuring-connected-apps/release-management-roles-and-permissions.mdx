Release Managementでアクションを実行するには、アカウントが必要なアクセス権を持っている必要があります。このアクセスはパーミッションによって制御されます。パーミッションとは、アプリの追加や接続、リリースの作成、接続されたapp settingsの変更など、特定のアクションを実行できる権限のことです。

## ロールとパーミッションの概要 {#roles-and-permissions-overview}

チームメンバーにはそれぞれ異なるロールを割り当てることができます。Release Managementには、3つの異なるレベルに5つの異なるロールがあります。

- <strong>Workspaceレベルのロール</strong>: これらのロールは特定のRelease Managementアプリに紐づくものではなく、Release Management内で変更することもできません。[接続されたアプリが属するBitrise projectを所有するWorkspace](/bitrise-platform/workspaces/collaboration-and-permissions-in-workspaces/workspace-collaboration)に完全に紐づいています。Workspaceレベルのロールは2つあります。

  - <strong>Workspace owner</strong>: Workspaceオーナーは、Release Management内のアプリのあらゆる側面に対して、制限や例外なく完全な管理権限を持ちます。
  - <strong>Workspace manager</strong>: workspaceマネージャーの主な目的は、workspaceのコラボレーションを管理することです。Release Managementでは、新しいプロジェクトを作成する際に新しいアプリを追加できます。ただし、既存のプロジェクトの下に新しいRMアプリを追加することはできません。
  - <strong>Contributor</strong>および<strong>Viewer</strong>: これらのWorkspaceレベルのロールには、デフォルトではRelease Managementアプリへのアクセス権がありません。
- <strong>Project Admin</strong>: Release Managementにおける唯一の[プロジェクトレベルのロール](/bitrise-platform/projects/roles-and-permissions-for-bitrise-ci)です。ユーザーをプロジェクトに追加しても、Adminロールを持つユーザーを除き、Release Management内で自動的に何らかのパーミッションが付与されるわけではありません。プロジェクトAdminは、アプリ、ビルド、Release Management、およびアプリのデプロイに対して完全な管理権限を持ちますが、一つだけ例外があります。それは、プロジェクトAdminがRelease Managementに新しいプロジェクトを伴う新しいアプリを追加できないことです。Release Managementに新しいアプリを追加する場合、自分がAdminであるプロジェクトの下にのみ追加できます。
- <strong>Release Managementレベルのロール</strong>: これらはRelease Management内で設定できるロールです。

  - <strong>Release manager</strong>: Release Managerの主な目的は、オンラインストアへのリリースを処理することです。新しいアプリを追加したり、app settingsにアクセスしたりすることはできません。
  - <strong>App tester</strong>: App testerロールは社内のテスター向けです。アプリとそのアーティファクト、[ビルド配布](urn:resource:component:92118)、および[テスターグループ](/release-management/build-distribution/tester-groups)メニューにアクセスできます。それ以外のアクセス権はありません。
