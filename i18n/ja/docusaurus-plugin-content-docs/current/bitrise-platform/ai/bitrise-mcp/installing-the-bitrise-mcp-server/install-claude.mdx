# Claude アプリケーションにBitrise MCPサーバーをインストールする {#install-bitrise-mcp-server-in-claude-applications}

## Claude Code CLI

### 前提条件 {#prerequisites}
- Claude Code CLI がインストールされていること(MCP OAuth サポートを含む最新バージョン)
- Bitrise アカウント
- プロジェクトのディレクトリ内で Claude Code を開いてください(最適な使用感と設定範囲の明確化のため推奨)

### リモートサーバーのセットアップ(Streamable HTTP)— 推奨 {#remote-server-setup-streamable-http--recommended}

リモートサーバーは OAuth を使用して Bitrise アカウントに対する認証を行います。トークンをコピー&ペーストする必要はありません。

1. サーバーを追加します:
   ```bash
   claude mcp add --transport http bitrise https://mcp.bitrise.io
   ```
2. Claude Code を再起動します。
3. 初めてツールを使用する際、Claude Code がブラウザを開いてサインインを求めます。Bitrise にログインし(または既存のセッションを確認し)、同意画面を承認してください。
4. `claude mcp list` を実行して、サーバーが設定されていることを確認します。

#### フォールバック: PATベースの認証 {#fallback-pat-based-authentication}

MCP OAuth サポートがない Claude Code バージョンを使用している場合、または個人アクセストークン(Personal Access Token)を使用したい場合:

1. [Account Settings → Security](https://app.bitrise.io/me/account/security) 配下で [Bitrise API トークンを作成します](https://devcenter.bitrise.io/api/authentication)。
2. トークンを Bearer ヘッダーとして指定し、サーバーを追加します:
   ```bash
   claude mcp add --transport http bitrise https://mcp.bitrise.io -H "Authorization: Bearer YOUR_BITRISE_PAT"
   ```

<details>
<summary><b>PATを安全に保存する</b></summary>
<br/>

セキュリティのため、トークンをハードコーディングしないようにしてください。一般的な方法の一つは次のとおりです:

1. トークンを `.env` ファイルに保存します

   ```
   BITRISE_PAT=your_token_here
   ```

2. .gitignore に追加します

   ```bash
   echo -e ".env\n.mcp.json" >> .gitignore
   ```

3. 追加する際にそれを参照します:

   ```bash
   claude mcp add --transport http bitrise https://mcp.bitrise.io -H "Authorization: Bearer $(grep BITRISE_PAT .env | cut -d '=' -f2)"
   ```

</details>

### ローカルサーバーのセットアップ(Go が必要) {#local-server-setup-go-required}

ローカルサーバーは stdio モードで動作し、個人アクセストークンで認証します(stdio モードではブラウザの OAuth フローはありません)。

前提条件: [Go](https://go.dev/)(1.25 以上)がインストールされていること、および Bitrise PAT。

1. 実行します:
   ```bash
   claude mcp add bitrise -e BITRISE_TOKEN=YOUR_BITRISE_PAT -- go run github.com/bitrise-io/bitrise-mcp/v2@v2
   ```

   環境変数を使用する場合:
   ```bash
   claude mcp add bitrise -e BITRISE_TOKEN=$(grep BITRISE_PAT .env | cut -d '=' -f2) -- go run github.com/bitrise-io/bitrise-mcp/v2@v2
   ```
2. Claude Code を再起動します。
3. `claude mcp list` を実行して、Bitrise サーバーが設定されているかを確認します。

### 検証 {#verification}
```bash
claude mcp list
claude mcp get bitrise
```

## Claude Desktop

### 前提条件 {#prerequisites-1}
- Claude Desktop がインストールされていること(latest version)
- Bitrise アカウント

### 設定ファイルの場所 {#configuration-file-location}
- <strong>macOS</strong>: `~/Library/Application Support/Claude/claude_desktop_config.json`
- <strong>Windows</strong>: `%APPDATA%\Claude\claude_desktop_config.json`
- <strong>Linux</strong>: `~/.config/Claude/claude_desktop_config.json`

### リモートサーバーのセットアップ(Streamable HTTP)— 推奨 {#remote-server-setup-streamable-http--recommended-1}

最近の Claude Desktop バージョンでは MCP OAuth をネイティブにサポートしています。[Claude | Connecting to a Remote MCP Server](https://modelcontextprotocol.io/docs/develop/connect-remote-servers#connecting-to-a-remote-mcp-server) を参照してください。初回接続時に、Claude Desktop がブラウザを開いて Bitrise で認証します — トークンは不要です。

お使いの Claude Desktop バージョンがリモート MCP サーバーをまだネイティブサポートしていない場合は、アダプターとして [mcp-remote](https://www.npmjs.com/package/mcp-remote) を使用できます:

```json
{
  "mcpServers": {
    "bitrise": {
      "command": "npx",
      "args": [
        "mcp-remote",
        "https://mcp.bitrise.io"
      ]
    }
  }
}
```

`mcp-remote` が OAuth フローを代行します。お使いの `mcp-remote` のバージョンが OAuth をまだサポートしていない場合は、PAT を指定する方法にフォールバックできます:

```json
{
  "mcpServers": {
    "bitrise": {
      "command": "npx",
      "args": [
        "mcp-remote",
        "https://mcp.bitrise.io",
        "--header",
        "Authorization: Bearer YOUR_BITRISE_PAT"
      ]
    }
  }
}
```

設定ファイルを保存し、Claude Desktop を再起動します。正しく設定されていれば、メッセージ作成欄の横にハンマーアイコンが表示されます。

Claude が `npx` を検出できない場合(`ENOENT`)は、`env` セクションで `npx` バイナリへのパスを指定してください:

```json
{
  "mcpServers": {
    "bitrise": {
      ...
      "env": {
        "PATH": "PATH to bin of npx"
      }
    }
  }
}
```

### ローカルサーバーのセットアップ(Go が必要) {#local-server-setup-go-required-1}

ローカルサーバーは個人アクセストークンを使用して stdio で動作します:

```json
{
  "mcpServers": {
    "bitrise": {
      "command": "go",
      "args": [
        "run",
        "github.com/bitrise-io/bitrise-mcp/v2@v2"
      ],
      "env": {
        "BITRISE_TOKEN": "YOUR_BITRISE_PAT",
        "PATH": "PATH to bin directory of go:PATH to directory of git",
        "GOPATH": "your GOPATH",
        "GOCACHE": "your GOCACHE"
      }
    }
  }
}
```

### Manual Setup Steps
1. Claude Desktop を開きます
2. Go to Settings → Developer → Edit Config
3. 上記のコードブロックを設定ファイルに貼り付けます
4. アプリ外から設定ファイルに移動する場合:
   - <strong>macOS</strong>: `~/Library/Application Support/Claude/claude_desktop_config.json`
   - <strong>Windows</strong>: `%APPDATA%\Claude\claude_desktop_config.json`
5. テキストエディタでファイルを開きます
6. 選択した設定(リモートまたはローカル)に応じて、上記のコードブロックのいずれかを貼り付けます
7. ファイルを保存します
8. Claude Desktop を再起動します
9. OAuth を使用している場合: ツールを初めて使用する際に、ブラウザでサインインフローを完了してください

### 高度な設定 {#advanced-configuration}

特定の API グループを有効化・無効化する方法については [Tools](/bitrise-platform/ai/bitrise-mcp/tools) を参照してください。

## トラブルシューティング {#troubleshooting}

<strong>OAuth flow doesn't open browser:</strong>
- お使いの Claude バージョンが MCP OAuth をサポートしていることを確認してください(最近のビルドのみ)
- PATベースの認証にフォールバックしてみてください

<strong>Authentication Failed:</strong>
- OAuth の場合: Claude Code 内で `/mcp` コマンドを使用するか、サーバーを削除して再追加することで再認証してください
- PAT の場合: トークンの有効期限が切れていないか、失効していないかを確認してください

<strong>Remote Server:</strong>
- URL を確認します: `https://mcp.bitrise.io`

<strong>サーバーが起動しない / ツールが表示されない場合:</strong>
- `claude mcp list` を実行して、現在設定されている MCP サーバーを確認します
- JSON の構文を検証します
- Claude Code を再起動し、`/mcp` コマンドを確認します
- `claude mcp remove bitrise` を実行して Bitrise サーバーを削除し、別の方法でセットアップ手順をやり直します
- ログを確認します:
  - Claude Code: `/mcp` コマンドを使用します
  - Claude Desktop: `ls ~/Library/Logs/Claude/` および `cat ~/Library/Logs/Claude/mcp-server-*.log`(macOS)または `%APPDATA%\Claude\logs\`(Windows)

## 重要な注意事項 {#important-notes}

- リモートサーバーには Streamable HTTP サポートが必要です(Claude のバージョンを確認してください)。OAuth には、基本的な Streamable HTTP よりも新しいビルドが必要です。
- Claude Code の設定スコープ:
  - `-s user`: すべてのプロジェクトで利用可能
  - `-s project`: `.mcp.json` ファイル経由で共有
  - デフォルト: `local`(現在のプロジェクトのみ)
