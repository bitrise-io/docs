# Google Gemini CLIにBitrise MCPサーバーをインストールする

## 前提条件

1. Google Gemini CLIのlatest versionがインストールされていること（[Gemini CLIの公式ドキュメント](https://github.com/google-gemini/gemini-cli)を参照）
2. Bitriseアカウント
3. ローカルセットアップの場合: [Go](https://go.dev/)（1.25以上）がインストールされていること、およびBitriseのPAT

## Bitrise MCPサーバーの設定

Gemini CLI用のMCPサーバーは、`mcpServers`キーの下にある設定JSONで設定します。

- <strong>グローバル設定</strong>: `~/.gemini/settings.json`（`~`はホームディレクトリ）
- <strong>プロジェクト固有</strong>: プロジェクトディレクトリ内の`.gemini/settings.json`

変更を反映するには、Gemini CLIの再起動が必要な場合があります。

### 方法1: Gemini拡張機能（推奨）

最も簡単な方法は、Gemini拡張機能を使ってBitriseがホストするMCPサーバーを利用することです。

```
gemini extensions install https://github.com/bitrise-io/bitrise-mcp
```

この拡張機能は、初回利用時にOAuthフローを自動的に処理します。ブラウザでBitriseへのログインを求められます。

### 方法2: リモートサーバー

ホストされているMCPサーバーに直接接続することもできます。

```json
// ~/.gemini/settings.json
{
    "mcpServers": {
        "bitrise": {
            "httpUrl": "https://mcp.bitrise.io"
        }
    }
}
```

初回のツール利用時に、Gemini CLIがブラウザを開いてBitrise OAuthへのサインインを行います。

#### フォールバック: PATベースの認証

まだMCP OAuthをサポートしていないGemini CLIのビルドでは、[BitriseのPATを作成](https://devcenter.bitrise.io/api/authentication)し、ヘッダーとして渡してください。

```json
// ~/.gemini/settings.json
{
    "mcpServers": {
        "bitrise": {
            "httpUrl": "https://mcp.bitrise.io",
            "headers": {
                "Authorization": "Bearer $BITRISE_PAT"
            }
        }
    }
}
```

<details>
<summary><b>PATを安全に保存する</b></summary>
<br/>

セキュリティのため、トークンをハードコーディングしないでください。`~/.gemini/.env`（`~`はホームディレクトリまたはプロジェクトディレクトリ）を作成または更新し、PATを設定します。

```bash
# ~/.gemini/.env
BITRISE_PAT=your_token_here
```

</details>

### 方法3: ローカルサーバーのセットアップ（Goが必要）

ローカルサーバーは、個人アクセストークンを使用してstdioで動作します。

```json
// ~/.gemini/settings.json
{
    "mcpServers": {
        "bitrise": {
            "command": "go",
            "args": [
                "run",
                "github.com/bitrise-io/bitrise-mcp/v2@v2"
            ],
            "env": {
                "BITRISE_TOKEN": "$BITRISE_PAT"
            }
        }
    }
}
```

## 確認

Bitrise MCPサーバーが設定されていることを確認するには、ターミナルで`gemini`を使ってGemini CLIを起動し、次の操作を行います。

1. <strong>Check MCPサーバーのステータスを確認する</strong>:

    ```
    /mcp list
    ```

    ```
    ℹ Configured MCP servers:

    🟢 bitrise - Ready (62 tools)
        - abort_build
        - abort_pipeline
        - add_member_to_group
        ...
    ```

2. <strong>プロンプトでテストする</strong>
    ```
    List my Bitrise apps
    ```

    PATなしでリモートサーバーを使用している場合、最初のツール呼び出しでOAuthのサインインフローがトリガーされます。

## 高度な設定

特定のAPIグループの有効化/無効化については、[ツール](/bitrise-platform/ai/bitrise-mcp/tools)を参照してください。

Gemini CLI向けのその他のMCP設定オプションについては、[MCP設定構造](https://google-gemini.github.io/gemini-cli/docs/tools/mcp-server.html#configuration-structure)を参照してください。たとえば、ツールの確認をバイパスしたり、特定のツールを除外したりできます。

## トラブルシューティング

### 認証の問題

- <strong>OAuthフローが開かない</strong>: Gemini CLIを最新のビルドに更新するか、PATベースの認証にフォールバックしてください。
- <strong>Tokenの有効期限切れ（PAT）</strong>: 新しいBitriseトークンを生成してください。

### 設定の問題

- <strong>Invalid JSON</strong>: 設定を検証してください:
    ```bash
    cat ~/.gemini/settings.json | jq .
    ```
- <strong>MCPの接続問題</strong>: 接続エラーについてログを確認してください:
    ```bash
    gemini --debug "test command"
    ```
