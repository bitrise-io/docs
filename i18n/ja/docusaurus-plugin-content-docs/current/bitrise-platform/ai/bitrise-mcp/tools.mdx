## Advanced configuration

MCP クライアントに公開するツールの数を制限できます。トークン使用量を最適化したい場合や、MCP クライアントにツール数の上限がある場合に便利です。

ツールは「API group」ごとにグループ化されており、ツールとして公開したいグループを指定できます。指定可能な値: `apps, builds, workspaces, outgoing-webhooks, artifacts, group-roles, cache-items, pipelines, account, read-only, release-management, configuration, release-management-code-push, insights`。

`apps` API グループとの混同を避けるため、`release-management` API グループは別々に使用することをお勧めします。

デフォルトでは、すべての API グループが有効です。有効にするグループは、ローカル (stdio) サーバーでは `ENABLED_API_GROUPS` 環境変数を使用し、リモート (Streamable HTTP) サーバーでは `x-bitrise-enabled-api-groups` HTTP ヘッダーを使用して、カンマ区切りのグループ名リストで指定できます。

## Output schemas

すべてのツールは `outputSchema` (結果の JSON Schema) を公開し、テキストコンテンツと併せて結果を `structuredContent` として返します。これにより、それを利用する MCP クライアントやディレクトリ (たとえば OpenAI コネクターディレクトリ) が結果を解釈できます。API レスポンスをそのまま返すツールのスキーマは、API が公開している OpenAPI ドキュメント (`internal/tool/outputschema/`) から生成されます。プレーンテキストの結果 (`bitrise.yml`、ガイド、ステータスメッセージ) は `{"content": "<text>"}` として返されます。オプションのフィールドは `null` になる場合があります。

## Tools

### Apps

1. `list_apps`
   - 認証済みアカウントで利用可能なすべてのアプリを一覧表示します
   - 引数:
     - `sort_by` (オプション): アプリの並び順。last_build_at (デフォルト) または created_at
     - `next` (オプション): レスポンスの最初のアプリの slug
     - `limit` (オプション): 1 ページあたりの最大要素数 (デフォルト: 50)

2. `register_app`
   - Bitrise に新しいアプリを追加します
   - 引数:
     - `repo_url`: リポジトリ URL
     - `is_public`: アプリのビルドの公開範囲が "public" かどうか
     - `organization_slug`: アプリの追加先の Organization (別名 workspace)
     - `project_type` (オプション): プロジェクトの種類 (ios、android など)
     - `provider` (オプション): github

3. `finish_bitrise_app`
   - Bitrise アプリのセットアップを完了します
   - 引数:
     - `app_slug`: セットアップを完了する Bitrise アプリの slug
     - `project_type` (オプション): プロジェクトの種類 (例: android、ios、flutter など)
     - `stack_id` (オプション): アプリに使用する stack ID
     - `mode` (オプション): セットアップのモード
     - `config` (オプション): アプリに使用する設定

4. `get_app`
   - 特定のアプリの詳細を取得します
   - 引数:
     - `app_slug`: Bitrise アプリの識別子

5. `delete_app`
   - Bitrise からアプリを削除します
   - 引数:
     - `app_slug`: Bitrise アプリの識別子

6. `update_app`
   - アプリを更新します
   - 引数:
     - `app_slug`: Bitrise アプリの識別子
     - `is_public`: アプリのビルドの公開範囲が "public" かどうか
     - `project_type`: プロジェクトの種類
     - `provider`: リポジトリプロバイダー
     - `repo_url`: リポジトリ URL

7. `get_bitrise_yml`
   - 指定した Bitrise アプリの現在の Bitrise YML 設定ファイルを取得します
   - 引数:
     - `app_slug`: Bitrise アプリの識別子

8. `update_bitrise_yml`
   - 指定した Bitrise アプリの Bitrise YML 設定ファイルを更新します
   - 引数:
     - `app_slug`: Bitrise アプリの識別子
     - `bitrise_yml_as_json`: 新しい Bitrise YML 設定ファイルの内容

9. `list_branches`
   - アプリのリポジトリで、既存のビルドがあるブランチを一覧表示します
   - 引数:
     - `app_slug`: Bitrise アプリの識別子

10. `register_ssh_key`
    - 特定のアプリに SSH-key を追加します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `auth_ssh_private_key`: 秘密 SSH キー
      - `auth_ssh_public_key`: 公開 SSH キー
      - `is_register_key_into_provider_service`: プロバイダーサービスにキーを登録します

11. `register_webhook`
    - 特定のアプリケーション用の受信 Webhook を登録します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子

### Builds

12. `list_builds`
    - 指定した Bitrise アプリのすべてのビルド、またはアクセス可能なすべてのビルドを一覧表示します
    - 引数:
      - `app_slug` (オプション): Bitrise アプリの識別子
      - `sort_by` (オプション): ビルドの並び順。created_at (デフォルト)、running_first
      - `branch` (オプション): ブランチでビルドを絞り込みます
      - `workflow` (オプション): Workflow でビルドを絞り込みます
      - `status` (オプション): ステータスでビルドを絞り込みます (0: 未完了、1: 成功、2: 失敗、3: 中止、4: 進行中)
      - `next` (オプション): レスポンスの最初のビルドの slug
      - `limit` (オプション): 1 ページあたりの最大要素数 (デフォルト: 50)

13. `trigger_bitrise_build`
    - 指定した Bitrise アプリの新しいビルドまたはパイプラインをトリガーします
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `branch` (オプション): ビルドするブランチ (デフォルト: main)
      - `pipeline_id` (オプション): ビルドするパイプライン
      - `workflow_id` (オプション): ビルドする Workflow
      - `pipeline_id` (オプション): ビルドするパイプライン
      - `commit_message` (オプション): ビルドのコミットメッセージ
      - `commit_hash` (オプション): ビルドのコミットハッシュ
      - `stack` (オプション): このビルドに限り、Workflow の `meta.bitrise.io.stack` を上書きしてビルドを実行する Stack (例: "osx-xcode-16.0.x")
      - `environments` (オプション): ビルド用のカスタム environment variables (`mapped_to`、`value`、およびオプションの `is_expand` プロパティを持つオブジェクトの配列)

14. `get_build`
    - 指定したアプリの特定のビルドを取得します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: ビルドの識別子

15. `abort_build`
    - 特定のビルドを中止します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: ビルドの識別子
      - `reason` (オプション): ビルドを中止する理由

16. `get_build_log`
    - Bitrise アプリの指定したビルドのビルドログを取得します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: Bitrise ビルドの識別子

17. `get_build_bitrise_yml`
    - ビルドの bitrise.yml を取得します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: ビルドの識別子

18. `list_build_workflows`
    - アプリの Workflow を一覧表示します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子

19. `get_build_steps`
    - 指定したアプリの特定のビルドの Step ステータスを取得します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: ビルドの識別子

### Artifacts

20. `list_artifacts`
    - すべてのビルドアーティファクトの一覧を取得します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: ビルドの識別子
      - `next` (オプション): レスポンスの最初のアーティファクトの slug
      - `limit` (オプション): 1 ページあたりの最大要素数 (デフォルト: 50)

20. `get_artifact`
    - 特定のビルドアーティファクトを取得します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: ビルドの識別子
      - `artifact_slug`: アーティファクトの識別子

21. `delete_artifact`
    - ビルドアーティファクトを削除します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: ビルドの識別子
      - `artifact_slug`: アーティファクトの識別子

22. `update_artifact`
    - ビルドアーティファクトを更新します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `build_slug`: ビルドの識別子
      - `artifact_slug`: アーティファクトの識別子
      - `is_public_page_enabled`: アーティファクトの公開ページを有効にします

### Outgoing Webhooks

24. `list_outgoing_webhooks`
    - アプリの送信 Webhook を一覧表示します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子

25. `delete_outgoing_webhook`
    - アプリの送信 Webhook を削除します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `webhook_slug`: Webhook の識別子

26. `update_outgoing_webhook`
    - アプリの送信 Webhook を更新します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `webhook_slug`: Webhook の識別子
      - `events`: Webhook をトリガーするイベントのリスト
      - `url`: Webhook の URL
      - `headers` (オプション): Webhook と共に送信するヘッダー

27. `create_outgoing_webhook`
    - アプリの送信 Webhook を作成します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `events`: Webhook をトリガーするイベントのリスト
      - `url`: Webhook の URL
      - `headers` (オプション): Webhook と共に送信するヘッダー

### Cache Items

28. `list_cache_items`
    - アプリに属するキーバリュー形式のキャッシュアイテムを一覧表示します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子

29. `delete_all_cache_items`
    - アプリに属するキーバリュー形式のキャッシュアイテムを Delete all
    - 引数:
      - `app_slug`: Bitrise アプリの識別子

30. `delete_cache_item`
    - キーバリュー形式のキャッシュアイテムを削除します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `cache_item_id`: キャッシュアイテムの識別子

31. `get_cache_item_download_url`
    - キーバリュー形式のキャッシュアイテムのダウンロード URL を取得します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `cache_item_id`: キャッシュアイテムの識別子

### Pipelines

32. `list_pipelines`
    - アプリのすべてのパイプラインとスタンドアロンビルドを一覧表示します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子

33. `get_pipeline`
    - 指定したアプリのパイプラインを取得します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `pipeline_id`: パイプラインの識別子

34. `abort_pipeline`
    - パイプラインを中止します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `pipeline_id`: パイプラインの識別子
      - `reason` (オプション): パイプラインを中止する理由

35. `rebuild_pipeline`
    - パイプラインを再ビルドします
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `pipeline_id`: パイプラインの識別子

### Group Roles

36. `list_group_roles`
    - アプリのグループロールを一覧表示します
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `role_name`: ロールの名前

37. `replace_group_roles`
    - アプリのグループロールを置き換えます
    - 引数:
      - `app_slug`: Bitrise アプリの識別子
      - `role_name`: ロールの名前
      - `group_slugs`: グループ slug のリスト

### Workspaces

38. `list_workspaces`
    - ユーザーがアクセスできる workspaces を一覧表示します

39. `get_workspace`
    - 1 つの workspace の詳細を取得します
    - 引数:
      - `workspace_slug`: Bitrise workspace の slug

40. `get_workspace_groups`
    - workspace 内のグループを取得します
    - 引数:
      - `workspace_slug`: Bitrise workspace の slug

41. `create_workspace_group`
    - workspace 内で Create a group
    - 引数:
      - `workspace_slug`: Bitrise workspace の slug
      - `group_name`: グループの名前

42. `get_workspace_members`
    - workspace 内のメンバーを取得します
    - 引数:
      - `workspace_slug`: Bitrise workspace の slug

43. `invite_member_to_workspace`
    - workspace にメンバーを招待します
    - 引数:
      - `workspace_slug`: Bitrise workspace の slug
      - `email`: ユーザーのメールアドレス

44. `add_member_to_group`
    - グループにメンバーを追加します
    - 引数:
      - `group_slug`: グループの slug
      - `user_slug`: ユーザーの slug

### Account

45. `me`
    - 現在認証されているユーザーアカウントの情報を取得します

### Release Management

46. `create_connected_app`
   - Bitrise に新しい Release Management 接続済みアプリを追加します。
   - 引数:
     - `platform`: 接続済みアプリのモバイルプラットフォーム (ios/android)。
     - `store_app_id`: 接続済みアプリのアプリストア識別子。
     - `workspace_slug`: Bitrise workspace の識別子。
     - `id`: (オプション) 新しい接続済みアプリ用の uuidV4 識別子。
     - `manual_connection`: (オプション) 手動接続であることを示します。
     - `project_id`: (オプション) 関連付ける Bitrise Project を指定します。
     - `project_title`: (オプション) `project_id` が指定されていない場合に作成されるプロジェクトのタイトル。`project_id` と同時には指定できません。
     - `store_app_name`: (オプション) 手動接続用のアプリ名。
     - `store_credential_id`: (オプション) Bitrise に追加された認証情報の選択。
     - `framework`: (オプション) アプリのビルドに使用するフレームワーク (flutter/react_native/kotlin_multiplatform/other/native_ios/native_android)。デフォルトは 'other' です。
     - `tester_groups`: (オプション) アプリと同時に作成されるテスターグループ (`name`、およびオプションの `type`、`auto_notify`、`user_slugs`、`emails` プロパティを持つオブジェクトの配列)。1 つずつ作成されるため、レスポンスの `errors` 配列を確認してください。
     - `code_push_deployments`: (オプション) アプリと同時に作成される CodePush deployments (`name` とオプションの `key` プロパティを持つオブジェクトの配列)。1 つずつ作成されるため、レスポンスの `errors` 配列を確認してください。

47. `list_connected_apps`
   - workspace 内で、認証済みアカウントが利用可能な Release Management connected apps を一覧表示します。
   - 引数:
     - `workspace_slug`: Bitrise workspace の識別子。
     - `items_per_page`: (オプション) 1 ページあたりの connected apps の最大数。
     - `page`: (オプション) 返すページ番号。
     - `platform`: (オプション) 特定のモバイルプラットフォームで絞り込みます。
     - `project_id`: (オプション) 特定の Bitrise Project で絞り込みます。
     - `search`: (オプション) バンドル ID、package name、または app title で検索します。

48. `get_connected_app`
   - 認証済みアカウントの Release Management 接続済みアプリを返します。
   - 引数:
     - `id`: Release Management 接続済みアプリの識別子。

49. `update_connected_app`
   - 接続済みアプリを更新します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `store_app_id`: アプリのストア識別子。
     - `connect_to_store`: (オプション) App Store または Google Play に対して有効性を確認します。
     - `store_credential_id`: (オプション) Bitrise に追加された認証情報の選択。

50. `list_installable_artifacts`
   - 接続済みアプリの Release Management インストール可能なアーティファクトを一覧表示します。
   - 引数:
     - `connected_app_id`: Release Management 接続済みアプリの識別子。
     - `after_date`: (オプション) アーティファクトの作成/アップロード期間の開始日時。
     - `artifact_type`: (オプション) 特定のアーティファクトタイプで絞り込みます。
     - `before_date`: (オプション) アーティファクトの作成/アップロード期間の終了日時。
     - `branch`: (オプション) Bitrise CI ブランチで絞り込みます。
     - `distribution_ready`: (オプション) 配布可能なアーティファクトで絞り込みます。
     - `items_per_page`: (オプション) 1 ページあたりのアーティファクトの最大数。
     - `page`: (オプション) 返すページ番号。
     - `platform`: (オプション) 特定のモバイルプラットフォームで絞り込みます。
     - `search`: (オプション) バージョン、ファイル名、またはビルド番号で検索します。
     - `source`: (オプション) インストール可能なアーティファクトのソースで絞り込みます。
     - `store_signed`: (オプション) ストア提出可能なインストール可能アーティファクトで絞り込みます。
     - `version`: (オプション) 特定のバージョンで絞り込みます。
     - `workflow`: (オプション) 特定の Bitrise CI Workflow で絞り込みます。

51. `generate_installable_artifact_upload_url`
   - Bitrise にアップロードするインストール可能なアーティファクト用の、署名付きアップロード URL を生成します。
   - 引数:
     - `connected_app_id`: Release Management 接続済みアプリの識別子。
     - `installable_artifact_id`: インストール可能なアーティファクトの uuidv4 識別子。
     - `file_name`: インストール可能なアーティファクトファイルの名前。
     - `file_size_bytes`: インストール可能なアーティファクトファイルのバイトサイズ。
     - `branch`: (オプション) CI ブランチの名前。
     - `with_public_page`: (オプション) 公開インストールページを有効にします。
     - `workflow`: (オプション) CI Workflow の名前。

52. `get_installable_artifact_upload_and_proc_status`
   - インストール可能なアーティファクトの処理およびアップロードのステータスを取得します。
   - 引数:
     - `connected_app_id`: Release Management 接続済みアプリの識別子。
     - `installable_artifact_id`: インストール可能なアーティファクトの uuidv4 識別子。

53. `set_installable_artifact_public_install_page`
   - インストール可能なアーティファクトの公開インストールページを利用可能にするかどうかを変更します。
   - 引数:
     - `connected_app_id`: Release Management 接続済みアプリの識別子。
     - `installable_artifact_id`: インストール可能なアーティファクトの uuidv4 識別子。
     - `with_public_page`: 公開インストールページを有効/無効にするブールフラグ。

54. `list_build_distribution_versions`
   - テスターが利用可能な Build Distribution のバージョンを一覧表示します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `items_per_page`: (オプション) 1 ページあたりのバージョンの最大数。
     - `page`: (オプション) 返すページ番号。

55. `list_build_distribution_version_test_builds`
   - 指定した Build Distribution バージョンのテストビルドの一覧を返します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `version`: Build Distribution のバージョン。
     - `items_per_page`: (オプション) 1 ページあたりのテストビルドの最大数。
     - `page`: (オプション) 返すページ番号。

56. `create_tester_group`
   - Release Management 接続済みアプリのテスターグループを作成します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `name`: 新しいテスターグループの名前。
     - `auto_notify`: (オプション) グループへの自動通知を行うかどうかを示します。外部テスターグループでは無視されます。
     - `user_slugs`: (オプション) 内部テスターとして追加する workspace メンバーの slug。外部テスターグループでは無視されます。
     - `emails`: (オプション) 外部テスターグループのテスターとして追加するメールアドレス (最大 1000 件)。
     - `type`: (オプション) テスターグループの種類。'internal' または 'external' (デフォルト: internal)。

57. `notify_tester_group`
   - 新しいテストビルドについて、内部テスターグループにメールで通知します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `id`: テスターグループの uuidV4 識別子。
     - `test_build_id`: テストビルドの一意の識別子。

58. `add_testers_to_tester_group`
   - 接続済みアプリのテスターグループにテスターを追加します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `id`: テスターグループの uuidV4 識別子。
     - `user_slugs`: (オプション) 内部テスターとして追加する User slug。内部テスターグループでは必須で、外部テスターグループでは無視されます。
     - `emails`: (オプション) 外部テスターとして追加するメールアドレス。外部テスターグループでは必須 (最大 1000 件) で、内部テスターグループでは無視されます。

59. `update_tester_group`
   - 指定したテスターグループの設定を更新します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `id`: テスターグループの uuidV4 識別子。
     - `auto_notify`: (オプション) 自動メール通知の設定。
     - `name`: (オプション) テスターグループの新しい名前。

60. `list_tester_groups`
   - 特定の接続済みアプリに関連するテスターグループの一覧を返します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `items_per_page`: (オプション) 1 ページあたりのテスターグループの最大数。
     - `page`: (オプション) 返すページ番号。
     - `type`: (オプション) 特定のテスターグループの種類 ('internal' または 'external') で絞り込みます (デフォルト: internal)。
     - `installable_artifact_id`: (オプション) 指定すると、そのアーティファクトに関する通知の詳細を、各テスターグループのレスポンスに追加します。

61. `get_tester_group`
   - 選択したテスターグループの詳細を返します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `id`: テスターグループの uuidV4 識別子。

62. `get_potential_testers`
   - テスターグループに追加できる候補テスターの一覧、またはテスターグループが存在する前の workspace メンバーの一覧を取得します。
   - 引数:
     - `workspace_slug`: (オプション) メンバーを一覧表示する workspace の slug。`connected_app_id`/`id` とは同時に指定できません。
     - `project_id`: (オプション) `workspace_slug` と併せて使用します。プロジェクトの外部コントリビューターも一覧表示します。
     - `connected_app_id`: (オプション) 接続済みアプリの uuidV4 識別子。`id` と併せて指定する必要があります。
     - `id`: (オプション) テスターグループの uuidV4 識別子。`connected_app_id` と併せて指定する必要があります。
     - `items_per_page`: (オプション) 1 ページあたりの候補テスターの最大数。1-1000 (デフォルト: 25)。
     - `page`: (オプション) 返すページ番号 (デフォルト: 1)。
     - `search`: (オプション) メールアドレスまたはユーザー名でテスターを検索します。

63. `get_testers`
   - 特定の接続済みアプリに関連するテスターグループに関連付けられているテスターの一覧を取得します。
   - 引数:
     - `connected_app_id`: 接続済みアプリの uuidV4 識別子。
     - `tester_group_id`: (オプション) テスターグループの uuidV4 識別子。指定すると、その特定のテスターグループ内のテスターのみが返されます。
     - `items_per_page`: (オプション) 1 ページあたりのテスターの最大数 (デフォルト: 10)。
     - `page`: (オプション) 返すページ番号 (デフォルト: 1)。
     - `type`: (オプション) 特定のテスターグループの種類 ('internal' または 'external') に属するテスターで絞り込みます (デフォルト: internal)。

### Configuration

64. `validate_bitrise_yml`
    - Bitrise YML 設定ファイルを検証します。このエンドポイントは、指定された bitrise.yml が有効かどうかを確認します。
    - 引数:
      - `bitrise_yml`: 検証対象の Bitrise YML 設定ファイルの内容。文字列である必要があります。
      - `app_slug` (オプション): Bitrise アプリの slug。この値を指定すると、利用可能なスタック、マシンタイプ、ライセンスプールなどの workspace 固有の設定に対して YML を検証できます。

65. `step_search`
    - Bitrise YML 設定ファイルで Workflow または step bundles を構築するための Step を検索します。名前、説明、タグ、またはメンテナーに基づいて Step を検索します。
    - 引数:
      - `query`: `clone`、`npm`、`deploy` などの、Step を検索するフレーズ。
      - `categories` (オプション): Step を絞り込むカテゴリ。指定可能な値: `build`、`code-sign`、`test`、`deploy`、`notification`、`access-control`、`artifact-info`、`installer`、`dependency`、`utility`
      - `maintainers` (オプション): メンテナーで Step を絞り込みます。指定可能な値: `bitrise`、`verified`、`community`

66. `step_inputs`
    - Step の入力を、デフォルト値や許可される値などと共に一覧表示します。
    - 引数:
      - `step_ref`: `step_lib_source::step_id@version` 形式の Step 参照。`step_id` と正確な `version` は必須で、`step_lib_source` はカスタム Step ソースの場合にのみ必要です。

67. `list_available_stacks`
    - 利用可能なスタックを、マシン構成とバージョン情報と共に一覧表示します。workspace_slug を指定すると、カスタムスタックを含め、その workspace で利用可能なスタックを返します。省略すると、グローバルに利用可能なスタックを返します。
    - 引数:
      - `workspace_slug` (オプション): Bitrise workspace の slug。指定すると、その workspace で利用可能なスタック (カスタムスタックを含む) を一覧表示します。省略すると、グローバルに利用可能なスタックを一覧表示します。

### CodePush

68. `codepush_list_deployments`
   - Bitrise アプリの CodePush deployments を一覧表示します。
   - 引数:
     - `app_id`: Bitrise アプリの識別子。
     - `search`: (オプション) 名前でデプロイを検索します。フィルターは大文字と小文字を区別します。
     - `items_per_page`: (オプション) 1 ページあたりのデプロイの最大数 (デフォルト: 10)。
     - `page`: (オプション) 返すページ番号 (デフォルト: 1)。

69. `codepush_get_deployment`
   - ID を指定して、特定の CodePush デプロイを取得します。
   - 引数:
     - `id`: CodePush デプロイの識別子 (UUID)。

70. `codepush_create_deployment`
   - Bitrise アプリの新しい CodePush デプロイを作成します。
   - 引数:
     - `name`: 新しいデプロイの名前。
     - `app_id`: Bitrise アプリの識別子。
     - `key`: (オプション) デプロイキー。指定しない場合は自動生成されます。

71. `codepush_update_deployment`
   - 既存の CodePush デプロイの名前を更新します。
   - 引数:
     - `id`: CodePush デプロイの識別子 (UUID)。
     - `name`: デプロイの新しい名前。

72. `codepush_delete_deployment`
   - CodePush デプロイを削除します。この操作は元に戻せません。
   - 引数:
     - `id`: 削除する CodePush デプロイの識別子 (UUID)。

73. `codepush_promote_deployment`
   - 元のデプロイから対象のデプロイへ、パッケージをプロモートします。package_id を指定しない限り、元のデプロイ内の最新のパッケージがプロモートされます。
   - 引数:
     - `id`: 元のデプロイの識別子 (UUID)。
     - `target_deployment_id`: 対象のデプロイの識別子 (UUID)。
     - `package_id`: (オプション) プロモートする特定のパッケージの UUID。デフォルトは最新のパッケージです。
     - `app_version`: (オプション) プロモートするパッケージの Semver アプリバージョン制約。
     - `description`: (オプション) プロモートするパッケージの説明。
     - `disabled`: (オプション) true の場合、クライアントはこのアップデートをダウンロードしません。
     - `mandatory`: (オプション) true の場合、クライアントはただちにインストールする必要があります。
     - `rollout`: (オプション) このアップデートを受け取るユーザーの割合 (0-100)。

74. `codepush_rollback_deployment`
   - CodePush デプロイを以前のバージョンにロールバックします。
   - 引数:
     - `id`: ロールバックする CodePush デプロイの識別子 (UUID)。
     - `package_id`: (オプション) ロールバック先の特定のパッケージの UUID。デフォルトは直前のパッケージです。

75. `codepush_list_updates`
   - 特定のデプロイの CodePush アップデートを一覧表示します。
   - 引数:
     - `deployment_id`: CodePush デプロイの識別子 (UUID)。
     - `search`: (オプション) ラベルまたは説明でアップデートを検索します。フィルターは大文字と小文字を区別します。
     - `items_per_page`: (オプション) 1 ページあたりのアップデートの最大数 (デフォルト: 10)。
     - `page`: (オプション) 返すページ番号 (デフォルト: 1)。

76. `codepush_get_update`
   - ID を指定して、特定の CodePush アップデートを取得します。
   - 引数:
     - `id`: CodePush アップデートの識別子 (UUID)。

77. `codepush_patch_update`
   - CodePush アップデートを部分更新して、無効状態、必須フラグ、または rollout percentage を変更します。変更したいフィールドのみを含めてください。省略したフィールドは変更されません。
   - 引数:
     - `id`: CodePush アップデートの識別子 (UUID)。
     - `disabled`: (オプション) 無効にするには 'true'、再び有効にするには 'false' を設定します。
     - `mandatory`: (オプション) 必須にするには 'true'、任意にするには 'false' を設定します。
     - `rollout`: (オプション) このアップデートを受け取るユーザーの割合 (0-100)。

78. `codepush_delete_update`
   - CodePush アップデートを削除します。この操作は元に戻せません。
   - 引数:
     - `id`: 削除する CodePush アップデートの識別子 (UUID)。

79. `codepush_get_update_status`
   - CodePush アップデートの処理ステータス (例: pending、ready、failed) を取得します。
   - 引数:
     - `id`: CodePush アップデートの識別子 (UUID)。

80. `codepush_generate_update_upload_url`
   - CodePush アップデートバンドルをアップロードするための、署名付きアップロード URL (有効期間 1 時間) を生成します。レスポンスには、直接アップロードに必要な URL、HTTP メソッド、およびヘッダーが含まれます。アップロード後、`codepush_get_update_status` でステータスを確認します。
   - 引数:
     - `id`: new update 用のクライアント生成の UUID。
     - `deployment_id`: このアップデートが属するデプロイの識別子 (UUID)。
     - `app_version`: このアップデートの対象となるアプリの Semver バージョン (例: '1.2.3')。
     - `file_name`: アップロードするアップデートバンドルのファイル名 (拡張子付き)。
     - `file_size_bytes`: アップデートバンドルファイルのバイトサイズ (文字列)。
     - `description`: (オプション) このアップデートの説明。
     - `disabled`: (オプション) true の場合、クライアントはアップロード後にこのアップデートをダウンロードしません。
     - `mandatory`: (オプション) true の場合、クライアントはこのアップデートをただちにインストールする必要があります。
     - `rollout`: (オプション) このアップデートを受け取るユーザーの割合 (0-100)。デフォルトは 100 です。

81. `codepush_get_metrics`
   - データ転送量、ストレージ、月間アクティブユーザー数を含む workspace レベルの CodePush usage metrics を、上限および請求サイクルの情報と共に取得します。
   - 引数:
     - `workspace_slug`: Bitrise workspace の slug。

### Insights

Bitrise Insights (公開 Insights API、`https://api.bitrise.io/insights/v1`) のビルドおよびテストのメトリクスです。workspace で有料の Insights プランが必要です。プランがない場合、すべての呼び出しが HTTP 402 で失敗します。各ツールは、Insights プロジェクト ID で識別される 1 つのプロジェクトのみを対象にレポートします。時間範囲は UTC で RFC3339 され、`start` は含み、`end` は含みません。所要時間の単位は秒で、割合は 0-100 のパーセンテージです。`branch` フィルターは、ワイルドカードとして `*` を受け付けます (`release/*`)。

すべての Insights ツールに共通する引数:
- `workspace_slug`: プロジェクトが属する workspace の slug
- `project`: レポート対象の Insights プロジェクトの ID
- `start`: 時間範囲の開始 (含む)、RFC3339
- `end`: 時間範囲の終了 (含まない)、RFC3339

1. `insights_get_build_totals`
   - グループ化なしで、ウィンドウ全体の Build count、失敗率、p50/p90 の所要時間、および total duration を取得します。ウィンドウは最大 2 年間です。
   - 引数:
     - `branch` (オプション): これらのブランチのビルドのみを対象にします。`*` はワイルドカードです
     - `workflow` (オプション): これらの Workflow のビルドのみを対象にします
     - `pipeline` (オプション): これらのパイプラインのビルドのみを対象にします

2. `insights_get_build_series`
   - 同じビルドメトリクスを時系列で取得します。時間バケットごとに 1 行で、古い順に並びます。`group_by` を指定すると、バケットごと、グループごとに 1 行となり、各行にグループ名が含まれます。ウィンドウの上限: 1 時間単位では 7 日間、日単位では 90 日間、週単位では 1 年間、月単位では 2 年間。
   - 引数:
     - `branch`、`workflow`、`pipeline` (オプション): 上記と同じ
     - `granularity` (オプション): hourly、daily (デフォルト)、weekly、または monthly
     - `group_by` (オプション): workflow, pipeline、stage、または step
     - `limit` (オプション): グループの最大数、1-100 (デフォルト: 20)。`group_by` がない場合は無視されます

3. `insights_get_test_totals`
   - グループ化なしで、ウィンドウ全体のテスト実行回数、失敗率、p50/p90 の所要時間、total duration、および不安定な実行回数を取得します。カウントは個別のテストケースではなく、テストケースの実行回数です。ウィンドウは最大 2 年間です。
   - 引数:
     - `branch`、`workflow`、`pipeline` (オプション): 上記と同じ。テストが実行されたビルドが対象です
     - `test_suite` (オプション): これらのテストスイートの実行のみを対象にします

4. `insights_get_test_series`
   - 同じテストメトリクスを、ビルドの時系列と同じウィンドウ上限で、時系列として取得します。
   - 引数:
     - `branch`、`workflow`、`pipeline`、`test_suite` (オプション): 上記と同じ
     - `granularity` (オプション): hourly、daily (デフォルト)、weekly、または monthly
     - `group_by` (オプション): workflow, pipeline、stage、branch、または test_suite
     - `limit` (オプション): グループの最大数、1-100 (デフォルト: 20)

5. `insights_list_flaky_tests`
   - ウィンドウ内で不安定な結果の後に再実行された Test cases を、ランキング順に 1 ページずつ取得します。ウィンドウは最大 2 年間です。
   - 引数:
     - `branch`、`workflow`、`test_suite` (オプション): 上記と同じ (このツールには `pipeline` フィルターはありません)
     - `test_case` (オプション): これらのテストケースのみを対象にします
     - `module` (オプション): これらのモジュールのテストケースのみを対象にします
     - `order_by` (オプション): flaky_rerun_count (デフォルト) または flaky_rate
     - `order` (オプション): desc (デフォルト) または asc
     - `page` (オプション): 1 から始まるページ番号 (デフォルト: 1)
     - `per_page` (オプション): 1 ページあたりのテストケース数、1-100 (デフォルト: 20)
