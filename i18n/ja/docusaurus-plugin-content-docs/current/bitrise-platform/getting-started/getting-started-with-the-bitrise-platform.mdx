Bitrise platformはアカウント、workspaces、プロジェクトを中心に構成されています。ここでは、それらの使い方をすぐに確認できるように説明します。

## サインアップ

メールアドレス、3つのGitプロバイダー(GitHub、GitLab、Bitbucketのいずれか)、またはGoogleアカウントを使ってサインアップできます。[Bitriseへのサインアップ](/bitrise-platform/getting-started/signing-up-for-bitrise)。

BitriseはSAML SSOにも対応しています。[BitriseでのSAML SSO](/bitrise-platform/accounts/saml-sso-in-bitrise/configuring-saml-sso-on-bitrise)。

サインアップすると、期間限定のトライアルを利用できます。

## 最初のworkspace

サインアップすると、最初のworkspaceが自動的に作成されます。このworkspaceはユーザーアカウントの所有物です。workspacesはいつでも追加で作成でき、他のworkspacesに招待されることもあります。

WorkspacesはBitriseにおいて非常に重要です。作業はすべてworkspaces単位で管理されます。次のことができます。

- ユーザーを追加し、ユーザーグループに整理する: [Workspaceのコラボレーション](/bitrise-platform/workspaces/collaboration-and-permissions-in-workspaces/workspace-collaboration)。
- Apple StoreやGoogle Playなどのサードパーティサービスとのworkspaceレベルの連携を設定する: [インテグレーションについて](/bitrise-platform/integrations/about-integrations)。
- Bitrise CIおよびRelease ManagementのためのCreate project。

## プロジェクト

最初のworkspaceを作成すると、最初のプロジェクトを追加するよう促されます。

![gettingstarted.png](/img/_paligo/uuid-4f8203e0-c79b-b9ec-7537-53e96b0f1924.png)

新しいプロジェクトを作成するには、2つの方法があります。

- Bitrise CIから始める: 自動的に<strong>Add new project</strong>フローに移動します。この方法では、Gitリポジトリと連携したCIプロジェクトが作成されます: [新しいプロジェクトの追加](/bitrise-ci/getting-started/adding-a-new-project)。
- Release Managementから始める: Release Managementに新しいappを追加すると、Bitriseが自動的に新しいプロジェクトにリンクします: [Release Managementへの新しいappの追加](/release-management/getting-started-with-release-management/adding-a-new-app-to-release-management)。

  この方法で作成したプロジェクトにはCIの設定は含まれませんが、後から追加できます。

この画面にある<strong>Build Cache</strong>カードは、プロジェクトを作成する3つ目の方法ではありません。これはBuild Cacheのセットアップに移動するものであり、事前にBitrise CIプロジェクトが存在している必要があります。

<strong>Project settings</strong>に入ってプロジェクトを設定します。これはBitrise CIとRelease Managementの両方からアクセスできます。
