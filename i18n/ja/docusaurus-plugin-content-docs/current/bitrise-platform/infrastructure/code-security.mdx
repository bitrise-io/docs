コードのセキュリティを確保するため、Bitriseビルドはそれぞれ専用のクリーンな仮想マシン上で実行され、ビルドが完了すると仮想マシン全体を破棄します。これにより、ビルドで使用したすべてのファイルと、ビルド中に加えたすべての変更が消去されます。

これは、Docker コンテナを使用してビルドを実行する Android と Docker の<GlossTerm baseform="Stack">スタック</GlossTerm>にも当てはまります。ビルド自体は引き続き完全な仮想マシンを取得し、そこではビルドの環境として使用されるコンテナ以外の Docker コンテナは起動されません。つまり、Docker コンテナは環境の管理にのみ使用しており、ビルド環境の分離には使用していません。分離は、すべてのビルドで完全な仮想マシンを使用することによって保証されています。

こうすることで、ビルドは常に他の人による変更や過去のビルドの影響から保護され、他の誰もあなたのコードにアクセスできず、安定した環境でビルド<GlossTerm baseform="Workflow">Workflow</GlossTerm>を定義できます。各ビルドは、過去のビルドや並行して実行されているビルドとは無関係に、独立した環境で完了します。


## ソースコード

ソースコードは保存しません。ソースコードは、[Bitrise 設定](/bitrise-ci/configure-builds/configuration-yaml/storing-an-apps-configuration-yaml)で定義した方法でのみ、build machines(仮想マシン)上でアクセスされます。設定内に <strong>Git Clone</strong> <GlossTerm baseform="Step">Step</GlossTerm> や、Gitリポジトリにアクセスするその他の Step がない場合、ソースコードにはまったくアクセスされません。ビルドの終了時に、仮想マシン全体が破棄されます。そのため、変更をコミットしてリモートリポジトリにプッシュしない限り、仮想マシン上でソースコードに加えた変更はすべて失われます。


## Code signing とその他のファイル

<GlossTerm baseform="Workflow Editor">Workflow Editor</GlossTerm> の <strong>Code Signing</strong> タブでアップロードしたファイルは、ウェブサーバーからのみアクセスできる形で `Amazon S3` に保存されます。

必要な認証情報はどのデータベースにも保存されず、ウェブサーバーの環境内でのみ利用できます。ビルドサーバーもファイルに直接アクセスすることはできません。ビルドが開始されると、ウェブサーバーは [Amazon S3 の署名付きURL](https://docs.aws.amazon.com/aws-sdk-php/v3/guide/service/s3-presigned-url.html)を使用して、これらのファイルに対する読み取り専用の、有効期限付きアクセスURLを生成します。


## パスワード

パスワードはハッシュ化・暗号化された形式で保存されます。パスワードは複数回のストレッチングを使用して [bcryptアルゴリズム](https://en.wikipedia.org/wiki/Bcrypt) で暗号化しています。
