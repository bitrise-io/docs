当社のデータセンターは一連のパブリックな静的IPアドレスの背後にあり、仮想マシンはそれらのアドレスの内側に独自の内部サブネットを持っています。会社のセキュリティポリシーによっては、build machineにアクセスできるようにするために、パブリックなIPアドレスを許可リストに追加する必要がある場合があります。[Bitrisebuild machinesのIPアドレス範囲](#ip-address-ranges-for-the-bitrise-build-machines)を参照してください。

同様に、[app.bitrise.io](http://app.bitrise.io)のUIおよび関連するコントロールプレーン、構成管理、サービスへのシグナリングを支えているBitriseバックグラウンドワーカーには、一連の静的IPアドレスからアクセスできます。これらのアドレスを許可リストに追加すると、ビルドステータスの更新を引き続き受信できるようにしたり、Bitriseが`<GlossTerm baseform="bitrise.yml">bitrise.yml</GlossTerm>`ファイルにアクセスできるようにしたりできます。詳細はアプリの[BitriseバックエンドワーカーのIPアドレス範囲](#ip-address-ranges-for-bitrise-backend-workers)をご覧ください。

## BitriseバックエンドワーカーのIPアドレス範囲

Bitriseバックエンドワーカーは、ファイアウォールやNATゲートウェイの背後で動作しています。当社のバックエンドシステムは、お客様のサービスやWebhookにアクセスしたり、セルフホスト型リポジトリのコミット、プルリクエスト、タグに関するビルドステータスの更新を送信したりします。

これらのアドレスは、セルフホスト型のGitサービスを使用している場合や、リポジトリに`bitrise.yml`ファイルを保存している場合に関係することがあります。このようにして、Bitriseは、たとえば`bitrise.yml`ファイルにアクセスしたり、セルフホスト型リポジトリのコミットやプルリクエストに関する[ビルドステータスの更新を送信](/bitrise-ci/configure-builds/configuring-build-settings/reporting-the-build-status-to-your-git-hosting-provider)したりできます。
