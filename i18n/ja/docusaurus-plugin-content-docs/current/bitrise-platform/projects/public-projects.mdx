オープンソースプロジェクトは素晴らしいものです。誰もが大好きです。ただし、特に CI/CD が絡むと、メンテナンスが大変になることがあります。そこで、みなさんの作業をぐっと楽にするために、Bitrise にパブリックプロジェクト機能を導入しました。

Bitrise project が公開されている場合、ビルド URL を知っていれば誰でもビルドログを閲覧できます。たとえば、プルリクエストで GitHub 上の CI ステータスチェックが失敗した場合、誰でもビルド URL をクリックしてビルドログを確認できます。

パブリックプロジェクトを作成するには、Bitrise に[新しいプロジェクトを追加](/bitrise-ci/getting-started/adding-a-new-project)するだけです。<strong>Build settings</strong> のステップで、プロジェクトのプライバシーを <strong>Public</strong> に設定します。

パブリックプロジェクトには公開リポジトリが必要です。ビルドログを閲覧できる人は、コードも閲覧できる必要があります。Bitrise は、プロジェクトを追加するときにリポジトリの公開状態を確認します：

- リポジトリがプライベートの場合、<strong>Public</strong> オプションは利用できません。
- Bitrise がGitプロバイダーに接続できない場合、<strong>Public</strong> オプションにその旨が表示されるので、再試行できます。
- リポジトリがセルフホスト型のGitサーバー（GitHub Enterprise Server、セルフマネージドの GitLab、または Bitbucket Server）にある場合、Bitrise は Workspace に接続されているサーバーに問い合わせます。

:::warning[プライバシーは後から変更できません]

この設定は後から変更できません。一度パブリックプロジェクトとして追加したプロジェクトを、プライベートに戻すことはできません。その場合は、プロジェクトを追加し直す必要があります。

:::

パブリックプロジェクトがあると、外部のコントリビューターは問題をより簡単に調査でき、たとえば自分のプルリクエストでビルドが失敗した理由を確認できます。Bitrise チームに招待されなくてもビルド Bitrise ログを閲覧でき、Bitrise チームのメンバーの助けも必要ありません。

もちろん、誰でもパブリックプロジェクトで Bitrise 上のあらゆる操作ができるわけではありません。ログを閲覧しているユーザーが[何らかのロール](/bitrise-platform/projects/roles-and-permissions-for-bitrise-ci)でプロジェクトでの作業に招待されていない場合、できるのは次のことだけです：

- [ビルドログ](/bitrise-ci/run-and-analyze-builds/build-data-and-troubleshooting/build-logs)を閲覧する。
- ビルドログをダウンロードする。
- [ビルドの `bitrise.yml` ファイル](/bitrise-ci/configure-builds/configuration-yaml/storing-an-apps-configuration-yaml)を閲覧する。

:::caution[パブリックプロジェクトのビルドログは誰でも閲覧できます]

ご注意ください：パブリックプロジェクトのビルドログと `bitrise.yml` ファイルは誰でも閲覧できます。見られたくない情報が含まれていないことを確認してください。

:::
