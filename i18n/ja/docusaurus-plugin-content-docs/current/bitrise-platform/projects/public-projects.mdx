オープンソースプロジェクトは素晴らしいもので、誰もが愛用しています。しかし、CI/CDが絡むとメンテナンスが大変になることがあります。だからこそ、Bitrise向けにパブリックプロジェクト機能を導入し、誰もが楽になるようにしました。

Bitriseのprojectがパブリックである場合、ビルドのURLを持っていれば誰でもビルドログを閲覧できます。たとえば、プルリクエストでGitHubのCIステータスチェックが失敗した場合、誰でもビルドのURLをクリックしてビルドログを閲覧できます。

パブリックプロジェクトを作成するには、Bitriseに[新しいプロジェクトを追加](/bitrise-ci/getting-started/adding-a-new-project)するだけです。<strong>Build settings</strong>ステップで、プロジェクトのプライバシーを<strong>Public</strong>に設定します。

:::warning[後でプライバシー設定は変更できません]

この設定は後から変更できません。プロジェクトをパブリックプロジェクトとして追加すると、プライベートに戻すことはできません。プロジェクトを追加し直す必要があります。

:::

パブリックプロジェクトがあれば、外部の貢献者も問題のトラブルシューティングがしやすくなり、たとえば自分のプルリクエストがビルド失敗になった理由を確認できます。Bitriseチームに招待されなくてもBitriseログを閲覧でき、Bitriseチームメンバーの助けを借りる必要もありません。

もちろん、これはBitrise上でパブリックプロジェクトに対して誰でも何でもできるという意味ではありません。ログを閲覧しているユーザーが[何らかのロール](/bitrise-platform/projects/roles-and-permissions-for-bitrise-ci)でプロジェクトの作業に招待されていない場合、次のことしかできません。

- [ビルドログ](/bitrise-ci/run-and-analyze-builds/build-data-and-troubleshooting/build-logs)を閲覧する。
- ビルドログをダウンロードする。
- [ビルドの`bitrise.yml`ファイル](/bitrise-ci/configure-builds/configuration-yaml/storing-an-apps-configuration-yaml)を閲覧する。

:::caution[パブリックプロジェクトのビルドログは誰でも閲覧可能です]

注意: パブリックプロジェクトのビルドログと`bitrise.yml`ファイルは誰でも閲覧できます。これらのファイルに見られたくない情報が含まれていないか、必ず確認してください。

:::
