<GlossTerm baseform="workspace">Workspaces</GlossTerm> 独自のプロジェクトを所有します。Bitrise にプロジェクトを追加するときに、プロジェクトのオーナーとなる workspace を選択します。それ以降、プロジェクトの所有権を変更できるのは workspace のオーナーだけです。

[Bitrise](https://www.bitrise.io) 上のプロジェクトを別の workspace に移管する必要が生じることがあります。これには2つの方法があります：

- Workspace settings ページの <strong>Projects</strong> メニューから、移管するプロジェクトを選択します。
- プロジェクトごとに、プロジェクトの <strong>Project settings</strong> ページから移管できます。

プロジェクトを移管すると、カスタム設定も一緒に移管されます。対象は次のとおりです：

- すべての <GlossTerm baseform="workflow">Workflows</GlossTerm> と <GlossTerm baseform="pipeline">Pipelines</GlossTerm>。
- ビルドの <GlossTerm baseform="trigger">トリガー</GlossTerm>。
- Environment Variables。
- ビルドのアーティファクト。

移管により、プロジェクトのチームのユーザーがアクセス権を失う場合があります。

- プロジェクトを受け取る workspace のオーナーであるプロジェクトのユーザーは、アクセス権を保持します。
- コントリビューターは、プロジェクトを受け取る workspace が外部コントリビューターを許可している場合は、移管されてアクセス権を保持します。workspace が外部コントリビューターを許可していない場合、アクセス権を失います。
- <strong>Groups</strong> タブに表示されているグループに属するユーザーは、グループが以前プロジェクトを所有していた workspace に属しているため、プロジェクトへのアクセス権を失います。

サービスアカウントと API キーは workspace に属しているため、プロジェクトと一緒には移動しません。移管後は次のようになります：

- Bitrise は、プロジェクトを [Google Play サービスアカウント](/bitrise-platform/integrations/connecting-a-google-service-account-to-bitrise)および [App Store Connect API キー](/bitrise-platform/integrations/apple-services-connection/connecting-to-an-apple-service-with-api-key)から切断します。
- Release Management は、connected apps を以前の workspace のアプリレベルのサービスアカウントおよび API キーから切断します。

受け取る側の workspace でサービスアカウントまたは API キーを設定し、プロジェクトに接続して、[接続された各アプリのストア接続を設定](/release-management/configuring-connected-apps/configuring-connected-app-integration)してください。それまでは、プロジェクトのサービスアカウントまたは API キーで認証する Steps は失敗し、Release Management は Google Play や App Store Connect にアクセスできません。


## Workspace settingsページでのプロジェクトの移行 {#transferring-projects-on-the-workspace-settings-page}

:::important[オーナーのみ]

そのプロジェクトを別のWorkspaceに移行するには、Workspaceのオーナーである必要があります。

:::

1. <Partial_OpeningTheWorkspaceSettingsPage />
1. 左側のメニューから <strong>Projects</strong> を選択します。
1. プロジェクトを選択するには、プロジェクト名の横にある <strong>Move project (↔)</strong> ボタンをクリックします。

   :::note[外部コントリビューターがいるプロジェクト]

   外部コントリビューターを許可していないWorkspaceに、外部コントリビューターがいるプロジェクトを移行すると、既存のコントリビューターはプロジェクトチームから自動的に削除されます。

   :::
1. プロジェクトの移行先となるユーザーまたはWorkspaceを選択します。

   ![move-project.png](/img/_paligo/uuid-5aa8c4c0-1851-b6c3-810b-11ca0c3dda28.png)
1. 完了するには <strong>Move project</strong> をクリックします。

   :::warning[所有権の移行は元に戻せません]

   移行が完了すると、プロジェクトの所有権を変更できるのはnew ownerのみです。

   :::


## Project settingsページでのプロジェクトの移行 {#transferring-a-project-on-the-project-settings-page}

1. プロジェクトのオーナーであるアカウントでLog inしてください。
1. <strong>Project settings</strong> ページを開きます。
1. 左側で <strong>Basic settings</strong> を選択し、<strong>Move or delete project</strong> セクションを見つけます。
1. <strong>Move project</strong> ボタンをクリックします。

   ![move-project-button.png](/img/_paligo/uuid-2ce0bbbd-d455-1840-7b19-0bcfc6da8e12.png)
1. プロジェクトの移行先となるWorkspaceを選択します。

   ![move-project-dialog.png](/img/_paligo/uuid-4c68fb66-ab5a-75a7-bb14-ab0f2617444f.png)
1. 完了するには <strong>Move project</strong> をクリックします。

   :::warning[所有権の移行は元に戻せません]

   移行が完了すると、プロジェクトの所有権を変更できるのはnew ownerのみです。

   :::
