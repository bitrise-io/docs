OpenID Connect（OIDC）を使用すると、Bitrise は有効期間の長いサービスアカウントキーなしで、誰がリクエストを行っているかを Google Cloud Platform（GCP）に証明できます。Bitrise はビルドまたはセッションを記述する ID トークンを発行し、GCP は Workload Identity Federation を通じて、それをスコープ付きアクセストークンと交換します。

OIDC トークンは、次の 2 か所で GCP に使用できます。

- <strong>CI build</strong>: [<strong>Get OIDC Identity Token</strong>](https://github.com/bitrise-steplib/bitrise-step-get-identity-token) <GlossTerm baseform="step">Step</GlossTerm> または [<strong>Authenticate with Google Cloud Platform (GCP)</strong>](https://github.com/bitrise-steplib/bitrise-step-authenticate-with-gcp) Step のいずれかでトークンを取得します。
- <strong>Remote Dev Environment セッション</strong>: gcloud または Google クライアントライブラリが認証情報を必要とするたびに、セッションの `rde-agent` コマンドがトークンを提供します。[OIDC でのクラウド認証](/bitrise-rde/configuration/oidc-cloud-authentication)を参照してください。

OIDC トークンを GCP に使用するには、次の作業が必要です。

- ワークロード ID プールを作成します。
- Google サービスアカウントを ID プールに接続します。

セットアップは、ビルドとセッションで共通です。ただし、属性マッピングとプリンシパルフィルターは、ビルドまたはセッションのクレームに合わせて設定します。


## ワークロード ID プールの作成 {#creating-a-workload-identity-pool}

GCP でワークロード ID プールを作成して、Workload Identity Federation を有効にします。

:::tip[Workload Identity Federation]

GCP での Workload Identity Federation による認証の仕組みについては、[Google の公式ドキュメント](https://cloud.google.com/sap/docs/abap-sdk/on-premises-or-any-cloud/latest/authentication-wif)を参照してください。

:::

1. Google Cloud コンソールで、<strong>IAM & Admin</strong> に移動し、<strong>Workload Identity Federation</strong> を選択します。
1. <strong>Create an identity pool</strong> セクションで、次のフィールドに値を入力します。

   - <strong>Name</strong>: プールの名前。この名前はプール ID として使用され、後からプール ID を変更することはできません。
   - <strong>Description</strong>: プールの目的。
1. <strong>Add a provider to pool</strong> で、Bitrise をプロバイダーとして追加します。

   - <strong>Select a provider</strong> フィールドで、<strong>OpenID Connect (OIDC)</strong> を選択します。
   - <strong>Provider name</strong>: 名前を入力します。わかりやすくするため、`Bitrise` の使用をおすすめします。
   - <strong>Issuer URL</strong>: https://token.builds.bitrise.io.
   - <strong>Audience</strong>: Select <strong>Allowed audience</strong>。トークンの使用時に、GCP は、許可されたオーディエンスが `aud` クレームにエンコードされたオーディエンスと一致するかどうかを確認します。Bitrise では、OIDC サービスを提供する Steps でオーディエンスを設定できます: [GCP でのトークンの取得と交換](/bitrise-platform/integrations/oidc-authentication/oidc-for-gcp#fetching-and-exchanging-tokens-with-gcp)。
1. <strong>Continue</strong> をクリックします。
1. <strong>Configure provider attributes</strong> で、必要な属性マッピングの値を設定します。

   - `google.subject` キーは、ユーザーの一意の識別子です。`assertion.sub` を使用して、トークンをリクエストするビルドまたは Remote Dev Environment セッションを識別できます。セッションのサブジェクトは `rde:` で始まります。[OIDC でのクラウド認証](/bitrise-rde/configuration/oidc-cloud-authentication)を参照してください。
   - `attribute.NAME` 形式を使用して、最大 50 個のカスタム属性を追加します。各属性には `assertion.VALUE` 形式の値を指定します。Bitrise トークンで使用可能な属性の一覧は、こちらで確認できます: [OIDC トークンに含まれる情報](/bitrise-platform/integrations/oidc-authentication/oidc-authentication-overview#information-in-the-oidc-token)。

   :::important[明示的なマッピングが必要]

   使用するすべての属性をマッピングする必要があります。Google では、明示的にマッピングされた属性のみを使用できます。詳細については、[Google ドキュメントの属性マッピング](https://cloud.google.com/iam/docs/workload-identity-federation?_gl=1*1sz7kri*_ga*MTM0MTUyNjA1OC4xNzYyNTMwMjA5*_ga_WH2QY8WWF5*czE3NjM0Nzc1MzYkbzIkZzEkdDE3NjM0Nzc4MDEkajUwJGwwJGgw#mapping)を参照してください。

   :::
1. 必要に応じて、属性条件を追加します。サービスアカウントの作成時に、プールレベルで属性に基づいて ID トークンを直接フィルタリングすることもできます。


## ワークロードIDプールへのGoogleサービスアカウントの接続 {#connecting-a-google-service-account-to-the-workload-identity-pool}

GCPサービスでOIDC認証を使用するには、ワークロードIDプールをGoogleサービスアカウントに接続する必要があります。これには次の作業が含まれます:

- サービスアカウントの作成。
- サービスアカウントの権限借用を使用したIDプールへのアクセス許可の付与。

### サービスアカウントの作成 {#create-a-service-account}

1. Google Cloudコンソールで、<strong>IAM & Admin</strong>に移動し、次に<strong>Service accounts</strong>を選択します。
1. <strong>Create service account</strong>をクリックします。
1. 表示名、一意のサービスアカウントID、説明を追加します。
1. <strong>Create and continue</strong>をクリックします。
1. <strong>権限</strong>で、必要なall rolesを追加します。

   :::note[IAM conditions]

   必要に応じて、<strong>Add IAM condition</strong>をクリックすることで、先ほどマッピングした属性値に基づいてIAM conditionsを追加できます。

   :::
1. <strong>Done</strong>をクリックします。

### ワークロード ID プールへのアクセス権の付与 {#granting-access-to-the-workload-identity-pool}

1. Google Cloud コンソールで、<strong>IAM & Admin</strong> に移動し、<strong>Workload Identity Federation</strong> を選択します。
1. ID プールを選択します。
1. <strong>Grant access</strong> をクリックします。
1. <strong>Grant access using service account impersonation</strong> オプションを選択します。
1. 作成した service account を選択します。
1. プリンシパルを選択します: サービスアカウントにアクセスできる ID です。

   選択可能なオプションは、ID プールのプロバイダー属性マッピングのキーに限られ、フィルターは属性の値と完全に一致します。たとえば、属性マッピング `google.subject=assertion.sub` を使用する場合は、<strong>Attribute name</strong> を `subject` に設定し、<strong>Attribute value</strong> にビルドのサブジェクトを `app:APP_SLUG:workflow:WORKFLOW` 形式で設定します。使用可能な値は、Bitrise トークンで確認できます: [OIDC トークンに含まれる情報](/bitrise-platform/integrations/oidc-authentication/oidc-authentication-overview#information-in-the-oidc-token)。
1. <strong>Save</strong> をクリックします。
1. ダイアログで、Bitrise OIDC トークン用に作成したプロバイダーを選択します。
1. OIDC ID トークンのパス https://token.builds.bitrise.io を追加し、形式を <strong>text</strong> に設定します。
1. <strong>Download config</strong> をクリックし、アクセスできる場所にファイルを保存します。


## GCPでのトークンの取得と交換 {#fetching-and-exchanging-tokens-with-gcp}

ワークロードIDプールの設定とGoogleサービスアカウントへの接続が完了すると、BitriseビルドはGCPとトークンを交換できるようになります。次のいずれかの方法を使用できます:

- <strong>Authenticate with GCP</strong> Stepを使用して、プロセス全体を処理します。
- <strong>Get OIDC Identity Token</strong> Stepでトークンを取得し、スクリプトで認証情報の交換を行います。

:::note[OIDCトークン内の情報]

Bitriseは、OIDCトークンに次のクレームを含めます: [Information in the OIDC token](/bitrise-platform/integrations/oidc-authentication/oidc-authentication-overview#information-in-the-oidc-token).

:::

### Authenticate with GCP Stepの使用 {#using-the-authenticate-with-gcp-step}

1. Bitriseで<GlossTerm baseform="workflow editor">Workflow Editor</GlossTerm>を開きます。
1. <strong>Authenticate with GCP</strong> Stepを<GlossTerm baseform="workflow">Workflow</GlossTerm>に追加します。
1. <strong>Client config</strong>と<strong>Token audience</strong>の入力を設定します:

   - token audienceは、Google Cloudでワークロードのプールを設定する際に設定した許可されたaudienceと一致させる必要があります。
   - <strong>Client config</strong>の入力は、プロセスの最後にダウンロードしたファイルを指す必要があります。

### Get OIDC Identity token Stepの使用 {#using-the-get-oidc-identity-token-step}

1. BitriseでWorkflow Editorを開きます。
1. <strong>Get OIDC Identity Token</strong> StepをWorkflowに追加します。
1. BITRISE_IDENTITY_TOKEN環境変数を使用します: ファイルに書き込み、[client library configuration file](/bitrise-platform/integrations/oidc-authentication/oidc-for-gcp#connecting-a-google-service-account-to-the-workload-identity-pool)を更新して、その環境変数を含むファイルを参照するようにします。これは<strong>Script</strong>Stepで設定できます:

   ```bash
   tmpfile="$(mktemp)"       
   printf '%s' "$BITRISE_IDENTITY_TOKEN" > "$tmpfile"

   # Replace the token path in client library configuration

   gcloud auth login --cred-file=/path/to/updated-client-library-config.json
   gcloud auth list
   ```

   その後、gcloud CLIが自動的にそれらを検出して使用します。CLIを介したあらゆる操作が問題なく動作します。
