サービスクレデンシャルは、接続されたGitプロバイダーアカウント(GitHub、GitLab、またはBitbucket)を持つユーザーで、Bitriseが実行する特定のアクションのためにこれらのGitサービスへのアクセスに使用されます。

:::important[GitHub プロジェクト]

Gitリポジトリへの接続に[GitHub Appインテグレーション](/bitrise-platform/repository-access/github-app-integration)を使用する場合、service credential userは不要です。

:::

他にもありますが、次のようなことを行うにはservice credential userを設定する必要があります。

- [ビルドステータスレポート](/bitrise-ci/configure-builds/configuring-build-settings/reporting-the-build-status-to-your-git-hosting-provider)をGitプロバイダーに送信する。
- [Selective builds](/bitrise-ci/configure-builds/configuring-build-settings/selective-builds)機能を使用すると、リポジトリ内の特定のファイルやディレクトリを指定し、それらが変更されると自動Bitriseビルドを<GlossTerm baseform="trigger">トリガー</GlossTerm>できます。
- [`bitrise.yml`ファイルをリポジトリに保存する](/bitrise-ci/configure-builds/configuration-yaml/storing-an-apps-configuration-yaml#storing-the-bitriseyml-file-in-your-repository)。

:::tip[アクションと要件]

アクションとその必要なアクセス要件の全リストについては、[Service credential userのアクションと必要なリポジトリアクセス](/bitrise-platform/integrations/the-service-credential-user#service-credential-user-actions-and-their-required-repository-access)を参照してください。

:::

デフォルトでは、Bitriseにプロジェクトを追加したユーザーがservice credential userとして設定されます。変更する場合でも、常にプロジェクトのリポジトリへのアクセス権を持つユーザーにする必要があります。

service credential userは必須ではありません。<strong>service credential userなし</strong>設定を使用すれば、設定しないことも可能です。この場合でもビルドの実行や自動ビルドのトリガーは引き続き行えますが、BitriseがGitプロバイダーにビルドステータスレポートを送信することはできず、[Selective builds](/bitrise-ci/configure-builds/configuring-build-settings/selective-builds)機能の使用や、<GlossTerm baseform="bitrise.yml">bitrise.yml</GlossTerm>ファイルをリポジトリに保存することもできなくなります。


## service credential userの変更 {#changing-the-service-credential-user}

service credential userはいつでも変更できますが、service credential userとして自分自身を設定できるのはBitrise<GlossTerm baseform="project">プロジェクト</GlossTerm>のみです。

:::important[ロール要件]

service credential userを変更するには、Bitriseで[プロジェクトのチームの<strong>Admin</strong>ロール](/bitrise-platform/projects/roles-and-permissions-for-bitrise-ci)を持っている必要があります。

:::

service credential userを変更するには:

1. 新しいservice credential userになるアカウントを使って、BitriseにLog inしてください。
1. そのアカウントが[プロジェクトのチーム](/bitrise-platform/projects/roles-and-permissions-for-bitrise-ci)で<strong>Admin</strong>ロールを持っていることを確認してください。
1. <GlossTerm baseform="Workspace">workspace</GlossTerm>のメインページに移動してください。
1. service credential userを変更したいプロジェクトを選択してください。
1. <strong>Project Settings</strong>をクリックしてください。
1. 左側のメニューから<strong>Integrations</strong>を選択してください。
1. <strong>Service credential user</strong>の部分までスクロールしてください。
1. <strong>Change SCU</strong>をクリックしてください(まだservice credential userが設定されていない場合は<strong>Set SCU</strong>)。

   :::note[GitHub組織のOAuthプロジェクトアクセス制限を無効にする]

   プロジェクトのservice credential userを接続または変更しようとしてエラーが発生した場合は、そのユーザーがGitHubリポジトリへのプロジェクトアクセス権を持っていること、および<strong>Third-party app access policy restrictions</strong>が無効になっていることを確認してください。

   GitHubでThird-party app access policyを無効にする方法の詳細については、[組織のOAuthプロジェクトアクセス制限を無効にする](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/about-oauth-app-access-restrictions)を参照してください。

   :::
1. 確認するには、<strong>Change</strong>をクリックしてください。


## Service credential userのアクションと必要なリポジトリアクセス {#service-credential-user-actions-and-their-required-repository-access}

:::important[GitHubプロジェクト]

Gitリポジトリへの接続に[GitHub Appインテグレーション](/bitrise-platform/repository-access/github-app-integration)を使用する場合、service credential userは不要です。

:::

service credential userを使用すると、BitriseはプロジェクトのGitリポジトリへのアクセスを必要とするさまざまなアクションを実行できます。アクションによって必要なアクセスレベルは異なります。たとえば、[リポジトリから`bitrise.yml`ファイルを使用する](/bitrise-ci/configure-builds/configuration-yaml/storing-an-apps-configuration-yaml#storing-the-bitriseyml-file-in-your-repository)にはGitHubへの<strong>read</strong>アクセスが必要ですが、[新しいSSHキーを登録する](/bitrise-platform/repository-access/configuring-ssh-keys)には<strong>admin</strong>アクセスが必要です。

次の表は、service credential userを必要とするすべてのアクションと、主要な3つのGitプロバイダーにおけるservice credential userのアカウントのアクセスレベルを示しています

| アクション | GitHubでの必要なアクセスレベル | Bitbucketでの必要なアクセスレベル | GitLabでの必要なアクセスレベル |
| --- | --- | --- | --- |
| [リポジトリから`bitrise.yml`を使用する](/bitrise-ci/configure-builds/configuration-yaml/storing-an-apps-configuration-yaml#storing-the-bitriseyml-file-in-your-repository) | read | read | reporter |
| リポジトリのブランチを一覧表示する | read | read | reporter |
| [Selective builds](/bitrise-ci/configure-builds/configuring-build-settings/selective-builds) | read | read | reporter |
| [Gitステータスレポートを送信する](/bitrise-ci/configure-builds/configuring-build-settings/reporting-the-build-status-to-your-git-hosting-provider) | write | write | GitLab.com: developer  セルフホストGitLab: maintainer |
| [リポジトリにSSHキーを登録する](/bitrise-platform/repository-access/configuring-ssh-keys) | admin | admin | maintainer |
| [webhookを登録する](/bitrise-platform/integrations/webhooks/adding-incoming-webhooks#registering-an-incoming-webhook-automatically) | admin | admin | maintainer |
| bitrise.io上でGit接続を確認する | admin | admin | maintainer |
