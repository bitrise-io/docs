Insightsでは、CIメトリクスの3つの主なカテゴリーを追跡できます：

- Build metrics。
- テストメトリクス。
- 使用率。

さらに、Insightsでは次のデータも提供できます：

- [Bitrise Build Cache](/bitrise-build-cache)。
- Gitの操作：[Git Insights](/insights/git-insights)。

## ビルドメトリクス {#build-metrics}

ビルドメトリクスには、<strong>Overview</strong>ページのチャート、または左側の<strong>Builds</strong>の選択からアクセスできます。ビルドメトリクスは、app-、<GlossTerm baseform="Pipeline">Pipeline</GlossTerm>、Stage、<GlossTerm baseform="Workflow">Workflow</GlossTerm>-、<GlossTerm baseform="Step">Step</GlossTerm>の各レベルでも利用可能です：

- <strong>Top build time (p90):</strong> 成功したビルドのビルド時間の90パーセンタイル値です。つまり、成功した100件のビルドのうち、90番目に遅いビルドがこの時間を要したことを意味します。フィルターが選択されていない場合、このメトリクスはPipelinesの実行時間に基づいて計算されます。
- <strong>Typical build time (p50):</strong> 成功したビルドの中央値の時間です。つまり、成功した100件のビルドのうち、50番目に遅いビルドがこの時間を要したことを意味します。フィルターが選択されていない場合、このメトリクスはPipelinesの実行時間に基づいて計算されます。
- <strong>Failure rate:</strong> 失敗したビルドの割合、つまり特定のWorkflowが失敗した割合です。たとえば、Workflowが10回中6回失敗した場合、失敗率は60%になります。フィルターが選択されていない場合、このメトリクスはPipelinesの失敗率に基づいて計算されます。
- <strong>Build count:</strong> 設定したフィルターと期間に基づく、appまたはWorkflowで開始されたビルドの総数です。
- <strong>Total duration:</strong> 設定したフィルターと期間に基づく、appまたはWorkflowのすべてのビルドのtotal durationです。

## テストメトリクス {#test-metrics}

テストメトリクスには、メインのInsightsページを開き、左側の<strong>Tests</strong>を選択してアクセスします。基本的なビルドメトリクスと同様に、テスト実行にもフィルターを適用できます。個々のテストスイート、テストケース、モジュール、さらにはappのリポジトリのブランチでフィルタリングできます。

- <strong>Top duration (p90):</strong> テストスイートまたはテストケースの所要時間の90パーセンタイル値です。特定のテストケースでフィルタリングしている場合、<strong>Top duration (p90)</strong>はその特定のテストケースの90パーセンタイル所要時間を示します。それ以外の場合は、設定したフィルターと期間に基づく、appまたはWorkflowのテストスイートの90パーセンタイル所要時間を示します。90パーセンタイルとは、成功した100回のテスト実行のうち、90番目に遅い実行がこの時間で完了したことを意味します。
- <strong>Typical duration (p50):</strong> テストスイートまたはテストケースの所要時間の中央値（50パーセンタイル）です。特定のテストケースでフィルタリングしている場合、<strong>Typical duration (p50)</strong>はその特定のテストケースの50パーセンタイル所要時間を示します。それ以外の場合は、設定したフィルターと期間に基づく、appまたはWorkflowのテストスイートの50パーセンタイル所要時間を示します。50パーセンタイルとは、成功した100回のテスト実行のうち、50番目に遅い実行がこの時間で完了したことを意味します。
- <strong>Failure rate:</strong> テストの失敗率は、テストスイートまたはテストケースがどのくらいの頻度で失敗するかを示します。たとえば、テストスイートまたはテストケースを100回実行し、そのうち10回失敗した場合、失敗率は10%になります。特定のテストケースでフィルタリングしている場合、<strong>Failure rate</strong>はその特定のテストケースの失敗率を示します。それ以外の場合は、設定したフィルターと期間に基づく、appまたはWorkflowのテストスイートの失敗率を示します。
- <strong>Total duration:</strong> 設定したフィルターと期間に基づく、appまたはWorkflowのすべてのテストのtotal durationです。
- <strong>テスト実行</strong>：テスト実行の総数です。
- <strong>Flaky runs</strong>：コードに変更がないにもかかわらず、一貫性のない結果を生むテスト実行の数です。

## 使用率メトリクス {#utilization-metrics}

:::important[利用可能性]

ここで説明する完全な使用率データは、カスタムのEnterpriseプランを利用しているユーザーのみが閲覧できます。その他のプランでは、クレジット使用量のみを確認できます。

:::

使用率メトリクスには、メインのInsightsページを開き、左側の<strong>Utilization</strong>を選択してアクセスします。<strong>Utilization</strong>ページにはBitriseビルドで使用されたリソースが表示され、コストを効率的に追跡できます。

デフォルトでは、このページには請求サイクルに基づくすべてのメトリクスが表示されます。これにより、自分で計算することなく、サイクル中のコミットメントと支出を追跡できます。また、このページには現在のサイクルの残り時間も表示されます。この既定の参照期間は、右上のドロップダウンメニューから変更できます。

<strong>Utilization</strong>ページには、常にインフラストラクチャ全体の使用率が表示されます。このメトリクスは、ビルド時間（分）、キャッシュストレージ、アーティファクトストレージ、ネットワーク下り(egress)トラフィックなど、インフラストラクチャの使用率をすべて集計したものです。このページでは、この合計値をコミットメントの総量と比較し、金額と割合の両方を表示します。

- <strong>Credit usage</strong>：Insightsは、各appで使用されたクレジットの量と、必要に応じて特定のappの各Workflowで使用されたクレジットの量を追跡します。
- <strong>Build minutes</strong>：さまざまなマシンタイプでのビルドに費やした時間を追跡し、コンピューティングリソースの消費を効率的に把握できます。フィルターを設定することで、appごと、Pipeline、Stage、またはWorkflowごとのビルド時間（分）など、複数のレベルでデータを表示できます。
- <strong>キャッシュされた呼び出し</strong>：このメトリクスは、build cacheを使用したビルドツールの呼び出し回数を示します。カウントされるのは、キャッシュからデータをダウンロードした呼び出しのみです。
- <strong>Network egress</strong>：ビルドのアーティファクトを取得するために、build cacheから外部ネットワークまたはクライアントへ転送されるデータです。これには、ローカル開発環境や、Bitrise以外のCI環境にダウンロードされたデータも含まれます。フィルターを設定し、ユーザー名別にデータを内訳表示することで、ローカルユーザーがどれだけの下り(egress)トラフィックを消費しているかを確認できます。
