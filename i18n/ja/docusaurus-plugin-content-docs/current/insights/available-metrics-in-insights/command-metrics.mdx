コマンドメトリクスは、GradleとBazelコマンドのパフォーマンスをデータドリブンで可視化します。コマンドメトリクスは[Bitrise Build Cache](https://bitrise.io/platform/devops/build-caching)の一部として利用でき、Build Cacheのセットアップが完了していれば、Insightsでこれらのメトリクスにアクセスできます。

:::note[キャッシュのパフォーマンス]

コマンドメトリクスはBitrise Build Cacheでのみ利用できますが、キャッシュのパフォーマンスは測定されません。キャッシュのパフォーマンスについては、[Build cacheメトリクス](/insights/available-metrics-in-insights/build-cache-metrics)をご覧ください。

:::

左側のナビゲーションメニューでInsightsにログインし、<strong>Commands</strong>を選択すると、コマンドのパフォーマンスを確認できます。

次のメトリクスを利用できます:

- <strong>Duration（p50およびp90）</strong>: デュレーションメトリクスは、コマンドの実行時間を測定します。コマンドの実行にかかる時間を把握することで、ボトルネックの特定、ビルド時間の最適化、生産性の向上に役立ちます。たとえば、想定よりも時間がかかっているコマンドを特定し、そこに最適化の取り組みを集中させることができます。
- <strong>Error率</strong>: コマンドが失敗する割合です。エラー率が低いほど、ビルドの信頼性が高く、CI/CDパイプラインの中断も少なくなります。特定のコマンドでエラー率が高い場合は対応が必要なサインであり、詳しく調査して不安定性の原因を解消することが求められます。
- <strong>Invocation count</strong>: このメトリクスは、特定のGradleおよびBazelコマンドが実行される頻度を測定します。過度に使用されているコマンドや、冗長に実行されているコマンドを浮き彫りにできます。特定のコマンドの実行頻度が高すぎると感じた場合は、コマンドの過剰な使用を避けるためにパイプラインを再構成できないか検討する価値があります。

Insightsの他のメトリクスと同様に、次のことができます:

- [ダッシュボードの作成](/insights/getting-started-with-insights#the-dashboards-page)。
- [アラートを設定](/insights/configuring-alerts-in-insights)（特定のしきい値に対して）。
