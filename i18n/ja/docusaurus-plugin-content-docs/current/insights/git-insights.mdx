Git Insightsを使用すると、Gitでのコラボレーションを定量化し、最適化できます。プルリクエストのサイクルタイムやマージ頻度など、重要な指標を確認できます。

:::important[Gitプロバイダーの要件]

Git Insightsは、リポジトリが次の3つのGitプロバイダーのいずれかでホストされている場合にのみ利用できます。

- GitHub
- GitLab
- Bitbucket。

:::


## Git Insights用のwebhookの設定 {#configuring-webhooks-for-git-insights}

Git Insightsを使用するには、[webhookの登録](/bitrise-platform/integrations/webhooks/adding-incoming-webhooks)をGitプロバイダーに対して行う必要があります。webhookがない場合、Bitriseはプルリクエストのデータにアクセスできません。

:::important[既存のwebhookの更新]

すでに[ビルドを自動的にトリガーする](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers)]ようBitriseでwebhookを登録済みの場合は、その権限がGit Insightsの要件を満たしているか確認し、必要に応じて更新してください。

:::

Git Insightsでは、サポート対象の3つのGitプロバイダーについて、次のwebhook権限が必要です。

- <strong>[GitHub](https://docs.github.com/en/webhooks/using-webhooks/editing-webhooks)</strong>: プッシュ、プルリクエスト。

  ![github-webhook-permissions.png](/img/_paligo/uuid-7a681d2b-732b-b061-0eb1-ecd158c0a9b9.png)
- <strong>[GitLab](https://docs.gitlab.com/ee/user/project/integrations/webhooks.html#configure-a-webhook-in-gitlab)</strong>: プッシュイベント/すべてのブランチ、マージリクエストイベント。

  ![gitlab-webhook-settings.png](/img/_paligo/uuid-130fe737-4629-1dfa-3234-9c03ad22f5dc.png)
- <strong>[Bitbucket](https://support.atlassian.com/bitbucket-cloud/docs/manage-webhooks/)</strong>: リポジトリ: プッシュ、プルリクエスト: 作成、更新、マージ。

## Git Insightsへのアクセス {#accessing-git-insights}

Git Insightsにアクセスするには:

1. BitriseにLog inします。
1. Dashboardの右上にある<GlossTerm baseform="workspace">Workspace</GlossTerm>を選択します。
1. 上部のメニューバーで<strong>Insights</strong>を選択します。
1. 左側で<strong>Git</strong>を選択します。

   ![git_-insights.png](/img/_paligo/uuid-33016129-6c3c-5427-c4ac-8dca1c01770d.png)

## Git Insightsの使用 {#using-git-insights}

Git Insightsでは、Workspace内のすべてのappの集計指標を表示することも、app単位の指標を表示することもできます。

![apps-filter.png](/img/_paligo/uuid-0b5537ea-42ab-780f-cd11-05072d508a72.png)

プルリクエストの対象ブランチでフィルタリングすることも可能です。appを選択したら、appのドロップダウンメニューの横にある<strong>Add filter</strong>をクリックします。

Git Insightsでは現在、サイクルタイムとマージ頻度という2つの主要な指標を提供しています。

<strong>Cycle time</strong>とは、PRをオープンしてからマージするまでに経過した時間を指します。さらに、次の2つの指標に分けられます。

- <strong>Development time</strong>: PRの最初のコミットからPRをオープンするまでの時間。
- <strong>Review time</strong>: PRをオープンしてから、PRが対象ブランチにマージされるまでにかかる時間。

<strong>Merge frequency</strong>とは、特定の期間内にPRがマージされた回数を指します。

これらの指標は、サイクルタイムとマージ頻度の表示を切り替えられるメインチャートで確認できます。

![git-main-chart.png](/img/_paligo/uuid-ef391d65-8868-242c-c6b6-380d117676b7.png)

<strong>Breakdown</strong>タブでは、期間ごとにアプリケーションまたは対象ブランチの詳細情報を確認できます。たとえば、1か月の間の特定の週における対象ブランチの合計マージ頻度を確認できます。

![breakdown-tab.png](/img/_paligo/uuid-7bf083ec-108e-2c84-cb3e-b47a85b69a48.png)

表示される内容は、設定とフィルターによって異なります。

- すべてのアプリケーションの集計データを表示している場合、<strong>Breakdown</strong>タブにはアプリケーション単位のデータが表示されます。
- 特定のアプリケーションでデータをフィルタリングしている場合、<strong>Breakdown</strong>タブには対象ブランチ単位のデータが表示されます。

<strong>Related PRs</strong>タブには、データセットに含まれる個々のPRに関連する指標が表示されます。行内の任意の場所をクリックすると、PRのページに移動できます。
