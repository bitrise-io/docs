## プロジェクト {#project}

Bitriseprojectは、開発作業全体のMobile DevOpsプロセスのコンテナです。各workspaceは複数のプロジェクトを持つことができます。プロジェクトでは、CIの設定を作成し、Release Managementを設定してモバイルアプリをテスターやオンラインストアに配信できます。

## 設定YAML {#configuration-yaml}

設定YAMLファイルには、プロジェクトのビルド設定全体が保存されます。スタックとビルドトリガーを指定し、アプリのWorkflowsを定義します。Workflow EditorのグラフィカルなUIで変更を行うと、実際には設定YAMLが変更されます。

## bitrise.yml {#bitriseyml}

設定YAMLファイルには、プロジェクトのビルド設定全体が保存されます。スタックとビルドトリガーを指定し、アプリのWorkflowsを定義します。Workflow EditorのグラフィカルなUIで変更を行うと、実際には設定YAMLが変更されます。

## Pipeline {#pipeline}

BitrisePipelineは、Bitrise CI/CD設定の最上位レベルです。Pipelinesを使用すると、CI/CDプロセス全体を整理したり、複数の異なるタスクを並列または順次実行する高度な設定をセットアップしたりできます。

## Project scanner {#project-scanner}

プロジェクトスキャナーは、指定されたプロジェクトの種類を識別し、基本的なBitrise設定を生成するツールです。サポートされているプロジェクトの種類にはそれぞれ専用のスキャナーがあり、これらのスキャナーは個別のパッケージとして保存されています。

## シークレット {#secret}

シークレットは[環境変数](/bitrise-ci/configure-builds/environment-variables)の一種で、情報を暗号化された形式で隠し、その値はビルドログにも`bitrise.yml`設定にも公開されません。パスワードやAPIキーなどの機密情報をSecretsとして保存できます。

## Stack {#stack}

ビルドスタックは、Bitriseがビルドの実行に使用する仮想マシンの完全な設定を示します。各スタックには、オペレーティングシステムと、あらかじめインストールされた多数のソフトウェアやツールが含まれています。たとえば、XcodeスタックはmacOSオペレーティングシステム上で動作し、他の多くのツールに加えて、スタック名に示されているXcodeのバージョンが含まれています。

## Step {#step}

Stepとは、Bitrise上でビルドタスクをカプセル化するスクリプト実行のブロックです。つまり、そのタスクを実行するコード、タスクに対して定義できる入力とパラメータ、およびタスクが生成する出力のことです。

## step.yml {#stepyml}

Bitrise Stepのインターフェース定義です。Step inputsと生成される出力に加えて、カテゴリやStepの説明などのその他のStepプロパティを定義します。また、Stepのソースコードも示します。

## トリガー {#trigger}

トリガー(ビルドトリガー)とは、特定のイベントが発生したときにBitriseビルドを自動的に起動するための設定です。トリガーを使用するには、Gitホスティングプロバイダーでウェブフックを設定する必要があります。

## Workflow {#workflow}

Workflowとは、Steps、Environment Variables、およびその他の設定の集合です。Bitriseがビルドを開始すると、`bitrise.yml`ファイルで定義された設定に従って、1つ以上のWorkflowsが実行されます。

## Workflow Editor {#workflow-editor}

BitriseWorkflow Editorを使用すると、Workflowsの編集、Stepsの設定、ファイル(code signingファイルを含む)のアップロード、アプリのトリガーやスタックの管理をグラフィカルユーザーインターフェース上で行うことができます。これはオンラインでも[オフライン](/bitrise-ci/bitrise-cli/installing-and-upgrading-the-offline-workflow-editor)でも利用できます。

## Workspace {#workspace}

Workspaceとは、Bitriseアプリと、そのアプリで作業するチームメンバーを管理できる環境です。複数のWorkspacesを作成できるほか、他のBitriseユーザーからWorkspacesに招待されることもあります。アプリを追加してビルドを実行するには、Workspaceに所属しているか、アプリのチームの外部コントリビューターである必要があります。

## Remote Dev Environment {#remote-dev-environment}

Remote Dev Environment(RDE)は、macOSまたはLinuxのオンデマンドクラウド開発マシンであり、Bitriseのインフラストラクチャ上で、Bitrise CIと同じスタックとキャッシュを使用して動作します。セッションを作成し、ターミナル、IDE、またはAIエージェントから接続して、後でアーカイブしたり復元したりできます。

## セッション {#session}

セッションは、単一のRemote Dev Environmentインスタンスです。テンプレートまたはstack and machine typeから直接作成された、実行中(または復元可能)のクラウドマシンを指します。セッションを終了すると永続ディスクは保持されるため、後で復元できます。

## テンプレート {#template}

テンプレートとは、再利用可能なRemote Dev Environment設定のことで、スタック、マシンタイプ、ウォームアップおよびスタートアップスクリプト、入力、IDEフォルダリンクなどが含まれます。テンプレートからセッションを作成できます。

## 保存済み入力 {#saved-input}

保存済み入力とは、Remote Dev Environmentセッションにマッピングできる、再利用可能でユーザー単位の値または認証情報(SSHの公開鍵やAPIトークンなど)です。シークレットの値は保存時に暗号化されます。

## デバイスセッション {#device-session}

デバイスセッションは、仮想デバイス(macOSスタック上のiOSシミュレーターやLinuxスタック上のAndroidエミュレーターなど)も起動するRemote Dev Environmentセッションであり、準備が完了すると通知し、その画面をブラウザにストリーミングします。

## デバイスプレビューリンク {#device-preview-link}

デバイスプレビューリンクとは、Bitriseへのログインなしで、稼働中のiOSシミュレーターまたはAndroidエミュレーター上でアプリのビルドを受信者のブラウザで開くことができる、共有可能なURLです。開くたびに専用のデバイスセッションが開始され、リンクは設定された有効期間の経過後に失効します。
