プラットフォームとアプリケーションの依存関係を管理することは、開発において重要な要素です。Bitriseでは、プロジェクトの種類を問わず依存関係をインストールできるよう、専用の<GlossTerm baseform="Step">Steps</GlossTerm>を複数提供しています。

依存関係だけでなく、それ以外のほとんどのビルドファイルもキャッシュできます。Bitriseでは、キャッシュをできるだけ簡単に行えるよう、専用のStepsを複数提供しています。

## iOSの依存関係 {#ios-dependencies}

組み込みの依存関係管理機能を備えた公式のXcode Stepsを使用するか、よく使われるサードパーティ製の依存関係マネージャー向けのStepsを使用して、iOSの依存関係をインストールできます: [iOSの依存関係](/bitrise-ci/dependencies-and-caching/ios-dependencies/managing-dependencies-with-carthage)

- 公式のXcode Stepsを使用すると、Xcode以外の設定を気にすることなくSwift Package Managerの依存関係を扱えます: [SPMでの依存関係管理](/bitrise-ci/dependencies-and-caching/ios-dependencies/managing-dependencies-with-spm)。
- CocoaPodsを使用していて`Podfile`を設定している場合は、[<strong>Run CocoaPods install</strong>](https://github.com/bitrise-io/steps-cocoapods-install) Stepを使用してpodをインストールできます: [CocoaPodsでの依存関係管理](/bitrise-ci/dependencies-and-caching/ios-dependencies/managing-dependencies-with-cocoapods)。
- プロジェクトでCarthageを使用している場合は、[<strong>Carthage</strong>](https://github.com/bitrise-steplib/steps-carthage) Stepを使用して依存関係をインストールできます: [Carthageでの依存関係管理](/bitrise-ci/dependencies-and-caching/ios-dependencies/managing-dependencies-with-carthage)。

## Androidの依存関係 {#android-dependencies}

公式のAndroid Stepsは、CI環境でGradleのタスクを代わりに実行します。そのため、プロジェクト内で依存関係が適切に設定されていれば、インストールも自動的に行われます: [Androidの依存関係](/bitrise-ci/dependencies-and-caching/android-dependencies)。

## Flutterの依存関係 {#flutter-dependencies}

Flutterの場合、[<strong>Flutter Build</strong>](https://github.com/bitrise-steplib/bitrise-step-flutter-build) Stepがパッケージとプラグインの両方を処理するため、依存関係をインストールするために追加のStepを加える必要はありません: [Flutterの依存関係](/bitrise-ci/dependencies-and-caching/flutter-dependencies)。

## React Nativeの依存関係 {#react-native-dependencies}

React Nativeの場合、npmとYarnの両方の公式Stepsが用意されているため、どちらを使ってもnpmパッケージをインストールできます。ネイティブの依存関係は別途インストールすることも可能です: [React Nativeの依存関係](/bitrise-ci/dependencies-and-caching/react-native-dependencies)

## キャッシュ {#caching}

当社のキャッシュソリューションでは、ほとんど任意のビルドファイルをキャッシュできます。多くのStepsが依存関係の内容を自動的に収集してキャッシュするため、ほとんど設定を行わずにすべての依存関係をキャッシュできます。それ以外のビルドファイルについては、主要なキャッシュStepsを必要に応じて自由に設定できます。

### キーベースのキャッシュ {#key-based-caching}

キーベースのキャッシュでは、キーと値のペアを使ってキャッシュアーカイブを識別します。キーは動的に生成できるため、たとえば特定のファイルが変更された場合にのみアーカイブを更新する、といった制御が可能です。キャッシュアーカイブへのキーの割り当ては、すべて自由に制御できます: [キーベースのキャッシュ](/bitrise-ci/dependencies-and-caching/key-based-caching/accessing-key-based-cache-archives)。

## Bitrise Build Cache

Bitrise Build Cacheは、特定のビルドシステム向けにリモートキャッシュを行うための、カスタムのホスト型実装です。リモートキャッシュはローカル環境とBitrise CI環境の両方で使用できるため、環境を問わずビルドが一貫して動作し、ビルド時間を大幅に短縮できます。

Bitriseは、以下のビルドシステム向けにBitrise Build Cacheをサポートしています:

- [Build Cache for Gradle](/bitrise-build-cache/build-cache-for-gradle/configuring-the-build-cache-for-gradle-in-the-bitrise-ci-environment)
- [Build Cache for Bazel](/bitrise-build-cache/build-cache-for-bazel/configuring-the-build-cache-for-bazel-in-the-bitrise-ci-environment)
- [Build Cache for Xcode](/bitrise-build-cache/build-cache-for-xcode/configuring-the-build-cache-for-xcode-in-the-bitrise-ci-environment)
- [Build Cache for React Native](/bitrise-build-cache/build-cache-for-react-native/configuring-the-build-cache-for-react-native-in-the-bitrise-ci-environment)
