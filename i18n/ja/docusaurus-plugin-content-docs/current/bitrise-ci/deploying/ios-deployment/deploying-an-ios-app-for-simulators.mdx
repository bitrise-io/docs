iOSアプリケーションをシミュレーターにビルド・デプロイし、たとえばブラウザーで動作を紹介できます。Bitriseでは、シミュレーター向けにビルドするための[専用のStep](https://www.bitrise.io/integrations/steps/xcode-build-for-simulator)を用意しています。[<strong>Xcode build for simulator</strong>](https://github.com/bitrise-steplib/steps-xcode-build-for-simulator) <GlossTerm baseform="Step">Step</GlossTerm>は、`xcodebuild`コマンドをiOSシミュレーターの送信先で実行し、.appファイルを生成します。

.appファイルはどのシミュレーターでも実行できます。Bitriseでは、アプリをAppetize.ioにアップロードするためのStepを用意しています。[<strong>Appetize.io deploy</strong>](https://github.com/bitrise-steplib/steps-appetize-io-deploy) Stepです。このStepを使うと、ブラウザーで実行できるようにアプリをデプロイできます。

シミュレーター向けにアプリをビルドする場合、code signingファイルは必要ありません。


## シミュレーター向けiOSアプリのビルド {#building-an-ios-app-for-a-simulator}

iOSまたはtvOSシミュレータープラットフォーム向けに、iOSアプリをビルドできます。

そのためには、<strong>Xcode Build for Simulator</strong> Stepが必要です。このStepは、任意のmacOSデバイスにインストールしたり、たとえばテスターに送信したりできる`.app`ファイルを作成します。code signingがまったく不要なため、iOSアプリの配布可能なバージョンを簡単に作成できます。

このStepは、テストの実行に使用できる`.xctestrun`ファイルも作成します。`.app`ファイルと`.xctestrun`ファイルはどちらも、後続のStepsから出力変数を参照してアクセスでき、[ビルドアーティファクトとしてダウンロード](/bitrise-ci/run-and-analyze-builds/managing-build-files/build-artifacts-online)することもできます。

シミュレーター向けにアプリをビルドするには、次の手順を行います。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. 必要な依存関係をすべて<GlossTerm baseform="workflow">Workflow</GlossTerm>にインストールしてください。

   さまざまな依存関係マネージャー向けの専用Stepsを用意しています。たとえば次のものがあります。

   - [Carthage](https://bitrise.io/integrations/steps/carthage)
   - [CocoaPods](https://bitrise.io/integrations/steps/cocoapods-install)
   - [Homebrew](https://bitrise.io/integrations/steps/brew-install)
1. 依存関係をインストールするStepの後に、<strong>Xcode Build for Simulator</strong> StepをWorkflowに追加します。
1. <strong>Project path</strong>入力が、`.xcodeproj`ファイルまたは`.xcworkspace`ファイルのいずれかを指していることを確認します。

   この入力は、`xcodebuild`コマンドの`-project`オプションまたは`-workspace`オプションを設定します。[アプリの追加プロセス](/bitrise-ci/getting-started/adding-a-new-project)中に<GlossTerm baseform="project scanner">プロジェクトスキャナー</GlossTerm>がアプリを自動的に設定した場合、ほとんどのケースでdefault valueを変更する必要はありません。
1. <strong>Scheme</strong>入力に、アプリのビルドに使用する[Xcodeスキーム](https://developer.apple.com/documentation/xcode/customizing-the-build-schemes-for-a-project/)の名前を設定します。

   この入力は、`xcodebuild`コマンドの`-scheme`オプションを設定します。default valueは、アプリの追加と初回設定時に作成される環境変数です。別のスキームを使用する必要がある場合は、ここにその名前を入力できます。

   :::tip[ビルド構成]

   デフォルトでは、Stepはスキームで指定されたビルド構成を使用します。ただし、これを上書きして別のビルド構成を使用することもできます。使用したいビルド構成の名前を<strong>Configuration name</strong>入力に追加してください。この入力はオプションで、選択したスキームで指定されたビルド構成を使用しない場合にのみ必要です。

   新しいビルド構成は、Xcodeプロジェクトでいつでも作成できます。詳しくは、[プロジェクトへのビルド構成ファイルの追加](https://developer.apple.com/documentation/xcode/adding-a-build-configuration-file-to-your-project)を参照してください。

   :::
1. <strong>Device destination specifier</strong>入力で、<strong>generic/platform=iOS Simulator</strong>を選択します。
1. 必要に応じて、<strong>Build settings (xcconfig), allow code signing</strong>入力を<strong>CODE_SIGNING_ALLOWED=YES</strong>に設定します。これにより、ビルド中にcode signingファイルをインストールできるようになります。

   シミュレーター向けにビルドするアプリでは、ほとんどの場合code signingは不要です。特定のテストケースやサードパーティの依存関係では必要になることがあります。code signingを設定するには、[iOS code signing](/bitrise-ci/code-signing/ios-code-signing/creating-a-signed-ipa-for-xcode-projects)を参照してください。
1. アプリをビルドアーティファクトとして利用できるようにするには、Workflowの最後に<strong>Deploy to Bitrise.io</strong> Stepを追加します。デフォルトでは、このStepの設定を変更する必要はありません。

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. 必要な依存関係をすべてWorkflowにインストールしてください。

   さまざまな依存関係マネージャー向けの専用Stepsを用意しています。たとえば次のものがあります。

   - [Carthage](https://bitrise.io/integrations/steps/carthage)
   - [CocoaPods](https://bitrise.io/integrations/steps/cocoapods-install)
   - [Homebrew](https://bitrise.io/integrations/steps/brew-install)
1. 依存関係をインストールするStepの後に、`[xcode-build-for-simulator](https://github.com/bitrise-steplib/steps-xcode-build-for-simulator)` StepをWorkflowに追加します。

   ```yaml
   workflows:    
     primary:
       steps:
         - cocoapods-install
         - xcode-build-for-simulator:
             inputs:
   ```
1. `project_path`入力が、`.xcodeproj`ファイルまたは`.xcworkspace`ファイルのいずれかを指していることを確認します。

   この入力は、`xcodebuild`コマンドの`-project`オプションまたは`-workspace`オプションを設定します。[アプリの追加プロセス](/bitrise-ci/getting-started/adding-a-new-project)中にプロジェクトスキャナーがアプリを自動的に設定した場合、ほとんどのケースでdefault valueを変更する必要はありません。

   ```yaml
   - xcode-build-for-simulator:
       inputs:
         - project_path: $BITRISE_PROJECT_PATH
   ```
1. `scheme`入力に、アプリのビルドに使用する[Xcodeスキーム](https://developer.apple.com/documentation/xcode/customizing-the-build-schemes-for-a-project/)の名前を設定します。

   この入力は、`xcodebuild`コマンドの`-scheme`オプションを設定します。default valueは、アプリの追加と初回設定時に作成される環境変数です。別のスキームを使用する必要がある場合は、スキーム名を正確に入力してください。

   ```yaml
   - xcode-build-for-simulator:
       inputs:
         - scheme: $BITRISE_SCHEME
         - project_path: $BITRISE_PROJECT_PATH
   ```

   :::tip[ビルド構成]

   デフォルトでは、Stepはスキームで指定されたビルド構成を使用します。ただし、これを上書きして別のビルド構成を使用することもできます。使用したいビルド構成の名前を`configuration`入力に追加してください。この入力はオプションで、選択したスキームで指定されたビルド構成を使用しない場合にのみ必要です。

   新しいビルド構成は、Xcodeプロジェクトでいつでも作成できます。詳しくは、[プロジェクトへのビルド構成ファイルの追加](https://developer.apple.com/documentation/xcode/adding-a-build-configuration-file-to-your-project)を参照してください。

   :::
1. `destination`入力を`generic/platform=iOS Simulator`に設定します。

   ```yaml
   - xcode-build-for-simulator:
       inputs:
         - scheme: $BITRISE_SCHEME
         - destination: generic/platform=iOS Simulator
         - project_path: $BITRISE_PROJECT_PATH
   ```
1. 必要に応じて、`xcconfig_content`入力に`CODE_SIGNING_ALLOWED=YES`を設定します。これにより、ビルド中にcode signingファイルをインストールできるようになります。

   シミュレーター向けにビルドするアプリでは、ほとんどの場合code signingは不要です。特定のテストケースやサードパーティの依存関係では必要になることがあります。code signingを設定するには、[iOS code signing](/bitrise-ci/code-signing/ios-code-signing/creating-a-signed-ipa-for-xcode-projects)を参照してください。

   ```yaml
   - xcode-build-for-simulator:
       inputs:
         - scheme: $BITRISE_SCHEME
         - destination: generic/platform=iOS Simulator
         - xcconfig_content: |-
             CODE_SIGNING_ALLOWED=YES            
             COMPILER_INDEX_STORE_ENABLE = NO
         - project_path: $BITRISE_PROJECT_PATH
   ```
1. アプリをビルドアーティファクトとして利用できるようにするには、Workflowの最後に`deploy-to-bitrise-io` Stepを追加します。デフォルトでは、このStepの設定を変更する必要はありません。

   ```yaml
   primary:
     steps:
       - generate-cordova-build-configuration@0: {}
       - xcode-build-for-test@2: {}
       - xcode-test@4: {}
       - xcode-build-for-simulator@0.12:
           inputs:
             - scheme: $BITRISE_SCHEME
             - destination: generic/platform=iOS Simulator
             - configuration: debug
             - xcconfig_content: |-
                 CODE_SIGNING_ALLOWED=YES            
                 COMPILER_INDEX_STORE_ENABLE = NO
             - project_path: $BITRISE_PROJECT_PATH
       - deploy-to-bitrise-io
   ```

## Appetize.ioへのアプリのデプロイ {#deploying-the-app-to-appetizeio}

<strong>Xcode build for simulator</strong> Stepでビルドした.appファイルは、ほぼすべてのシミュレーターで動作します。ただし、ブラウザーでアプリを実行できるシミュレーターに手早く簡単に統合したい場合は、<strong>Appetize.io deploy</strong> Stepの使用をお勧めします。このStepは、アプリをAppetize.ioにアップロードし、ブラウザーでアプリを使用するための公開URLを提供します。

1. Appetize.ioのAPIトークンをリクエストします。
1. <Partial_OpeningTheWorkflowEditor />
1. <strong>Xcode build for simulator</strong> StepをWorkflowに追加して設定します。
1. <strong>Appetize.io deploy</strong> StepをWorkflowに追加します。
1. Appetize.ioのAPIトークンを<strong>Appetize.io API Token</strong>入力に追加します。
1. <strong>Application path</strong>入力に、.appファイルへのパスを入力します。最も簡単な方法は、<strong>Xcode build for simulator</strong> Stepの出力である`BITRISE_APP_DIR_PATH_LIST`環境変数を使用することです。必要に応じて、より効率的なデバッグのために詳細ログを有効にすることもできます。

`Appetize.io deploy` Stepは、`APPETIZE_APP_URL`環境変数という1つの出力を生成します。これは、アプリにアクセスできる公開URLです。ぜひ自慢してください。
