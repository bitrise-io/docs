React Nativeプロジェクトは[React Native CLIまたはExpo CLIを使って](https://facebook.github.io/react-native/docs/getting-started.html)生成できます。[Expo](https://docs.expo.dev/versions/latest/)は、XcodeやAndroid Studioでネイティブコードを使用せずにReact Nativeアプリをすばやく立ち上げられるツールチェーンです。

このガイドでは、[Expo CLI](https://docs.expo.dev/get-started/installation/)でビルドしたReact Nativeプロジェクトのセットアップ、テスト、コード署名、デプロイの方法について説明します。


## BitriseへのExpoプロジェクトの追加

プロジェクトの追加方法は他の場合と同じです。ウィザードの詳しい手順については、[新しいプロジェクトの追加](/bitrise-ci/getting-started/adding-a-new-project)を参照してください。このセクションでは、Expoに固有の内容について説明します。

### スキャナーがExpoプロジェクトを検出する仕組み

<GlossTerm baseform="project scanner">プロジェクトスキャナー</GlossTerm>は、まず依存関係として`react-native`を記載した`package.json`ファイルを探します。`expo`も依存関係として記載されており、`package.json`と同じ場所に`app.json`、`app.config.js`、または`app.config.ts`ファイルが存在する場合、Bitriseはプロジェクトを単なるReact NativeではなくExpoベースとして登録します。このモードでは、スキャナーはネイティブの`ios/`ディレクトリと`android/`ディレクトリの確認をスキップします。

### 設定できる項目

<strong>CI configuration</strong>ステージでは、ウィザードに次の項目が表示されます。

- <strong>Expoプロジェクトディレクトリ</strong>: `package.json`とExpo設定ファイルが含まれるディレクトリです。
- <strong>Platform</strong>: EAS Buildでビルドするプラットフォーム(すべて、Android、またはiOS)です。

## Expoプロジェクトのデプロイ

BitriseはExpoプロジェクト向けに[Expo Application Services](https://expo.dev/eas)(EAS)をサポートしており、デフォルトのデプロイBitriseWorkflowは[Run Expo Application Services (EAS) build](https://www.bitrise.io/integrations/steps/run-eas-build)<GlossTerm baseform="step">Step</GlossTerm>を使用してEAS上でビルドを<GlossTerm baseform="trigger">トリガー</GlossTerm>します。

EASを使用しない場合は、BitriseWorkflowsに[Turtle CLI](https://docs.expo.dev/eas/cli/)を使用できます。詳細については、GitHubの[Turtle CLIを使用したExpoビルド](https://github.com/bitrise-io/workflow-recipes/blob/main/recipes/react-native-expo-build-using-turtle-cli.md)のレシピを参照してください。

:::note[CodePush]

Bitrise CodePushを使用すると、ユーザーのデバイスにアップデートをデプロイできます。CodePushは[Release Management](/release-management)の一部であり、React NativeアプリとExpoアプリでサポートされています。

CodePushの詳細については、公式ガイドをご覧ください: [CodePush](/release-management/codepush/about-codepush)。

:::
