Bitriseへの<GlossTerm baseform="Project">プロジェクト</GlossTerm>の追加には、次の2つの方法があります。

- CI設定で新規プロジェクトを追加し、Gitリポジトリをプロジェクトに接続します。

  この過程で、プロジェクトのプラットフォームタイプ(iOSなど)を検出する[プロジェクトスキャナー](https://github.com/bitrise-steplib/steps-project-scanner)も実行され、アプリのビルドとデプロイに必要な<GlossTerm baseform="Step">Steps</GlossTerm>をすべて含むデフォルトの<GlossTerm baseform="Workflow">Workflows</GlossTerm>を生成します。
- 新しいRelease Managementアプリで新規プロジェクトを追加する: [Release Managementに新しいアプリを追加する](/release-management/getting-started-with-release-management/adding-a-new-app-to-release-management)

各Bitrise<GlossTerm baseform="project">プロジェクト</GlossTerm>は[workspace](/bitrise-platform/workspaces/workspaces-overview)が所有します。

:::note[プロジェクトスキャナー]

プラットフォームやフレームワークをサポートしているとは、プロジェクトスキャナーがプロジェクトの種類を検出し、その種類に基づいて基本的なBitrise設定をセットアップできることを意味します。ビルド方法にかかわらず、他のどのようなプロジェクトも追加できますが、その場合は手動で設定する必要があります。

:::

このガイドでは、新しいCIプロジェクトをBitriseに追加する方法について説明します。

1. <strong>Dashboard</strong>で、<strong>New project</strong>をクリックします。
1. <strong>Configure Bitrise CI</strong>を選択します。

   ![CI設定の追加エントリーポイント — 開始方法を選択するモーダル](/img/getting-started/2026-06-27-add-ci-config-dashboard-modal.png)

   :::tip[Release Management]

   代わりに新しいアプリをRelease Managementに追加するには、<strong>Add your app</strong>を選択します。詳細は[Release Managementに新しいアプリを追加する](/release-management/getting-started-with-release-management/adding-a-new-app-to-release-management)を参照してください。

   :::

<strong>Add CI config</strong>ウィザードには、<strong>Repository</strong>、<strong>CI configuration</strong>、<strong>Build settings</strong>の3つのステージがあります。

## Repository

以下の各サブステップを順番に完了してください。

### Gitプロバイダーへの接続 {#connecting-to-your-git-provider}

<strong>Connect to your Git provider</strong>で、<strong>Connection method</strong>ドロップダウンからconnection methodを選択します。

- <strong>GitHub App(推奨)</strong>: GitHubアプリ統合を使用して接続します。事前にWorkspaceの管理者が<strong>Workspace settings > Integrations</strong>で認証情報を設定しておく必要があります。詳細は[GitHubアプリ統合](/bitrise-platform/repository-access/github-app-integration)を参照してください。
- <strong>GitHub OAuth</strong>、<strong>GitLab</strong>、<strong>Bitbucket</strong>: 各プロバイダー上のアカウントにOAuth経由で接続します。詳細は[OAuthによるリポジトリアクセス](/bitrise-platform/repository-access/repository-access-with-oauth)を参照してください。
- <strong>[GitHub Enterprise Server](/bitrise-platform/repository-access/integrating-github-enterprise-with-bitrise)</strong>、<strong>Bitbucket Server</strong>、<strong>[Self-hosted GitLab](/bitrise-platform/repository-access/connecting-self-hosted-gitlab-instances)</strong>: セルフホスト型のGitプロバイダー向けです。
- <strong>Other</strong>: URLを手動で入力して、その他のGitリポジトリを接続します。

プロバイダーを選択したら、<strong>Connect プロバイダー</strong>をクリックして接続をset upするか、すでに接続済みの場合は<strong>Select repository</strong>をクリックします。

![Gitプロバイダーへの接続 — GitHub OAuthが選択されたconnection methodドロップダウン](/img/getting-started/2026-06-27-add-ci-config-connect-git-provider.png)

### リポジトリの選択 {#selecting-a-repository}

接続するリポジトリを選択します。

- <strong>Select from list</strong>: アカウントのドロップダウンを使用して組織またはユーザーでフィルタリングし、一覧からリポジトリを選択します。特定のリポジトリを検索するには検索フィールドを使用します。
- <strong>Add URL manually</strong>: リポジトリのURLを直接入力します。

<strong>Confirm selection</strong>をクリックします。

![リポジトリの選択 — アカウント別にリポジトリを参照](/img/getting-started/2026-06-27-add-ci-config-select-repository.png)

:::note

リポジトリが見つからない場合は、Bitrise OAuthアプリの組織承認をリクエストする必要がある場合があります。リンクはリポジトリ一覧の下に表示されます。

:::

### Bitriseの認証 {#authorizing-bitrise}

:::note

この手順は、GitHubアプリを使用しておらず、リポジトリがSSH URL経由で接続されている場合にのみ必要です。HTTPS URL経由で接続されたリポジトリでは、SSHキーの設定は不要です。この手順が不要な場合、ウィザードは自動的にスキップします。

:::

Bitriseがリポジトリにアクセスする方法を選択します。

- <strong>Auto-add a generated SSH key to your repository</strong>: Bitriseがキーを自動的に追加します。Gitプロバイダーの管理者権限が必要です。
- <strong>Copy a generated SSH key to your Git provider manually</strong>: 接続するリポジトリ以外にも、ビルドが追加のプライベートリポジトリにアクセスする必要がある場合に使用します(たとえば、プライベートなCocoaPods specリポジトリ、Fastlane matchのストレージ、Gitサブモジュールなど)。生成されたキーをコピーし、各リポジトリに手動で追加します。
- <strong>Add your own SSH key to Bitrise</strong>: 既存のSSHキーペアを使用します。

詳細は[SSHキーの設定](/bitrise-platform/repository-access/configuring-ssh-keys)を参照してください。

![Bitriseの認証 — SSHキーのオプション](/img/getting-started/2026-06-27-add-ci-config-authorize-bitrise.png)

### default branchの選択 {#selecting-the-default-branch}

他の設定で別のブランチが指定されていない場合にBitriseがビルドで使用するブランチを選択します。

- リポジトリが接続されている場合は、ドロップダウンからブランチを選択します。
- URLを手動で追加した場合は、branch nameを直接入力します。

[default branchの変更](/bitrise-platform/projects/configuring-the-repository-url-and-the-default-branch)は後からでも可能です。次のステージに進むには<strong>Next</strong>をクリックします。

![default branchの選択 — mainが選択されたブランチドロップダウン](/img/getting-started/2026-06-27-add-ci-config-select-default-branch.png)

## CIの設定 {#ci-configuration}

Bitriseがリポジトリをスキャンし、初期のCI設定を自動的に生成します。

![CI設定 — リポジトリのスキャン](/img/getting-started/2026-06-27-add-ci-config-ci-configuration-scanning.png)

スキャンが完了すると:

- プロジェクトの種類が検出された場合、<strong>Detected options</strong>タブに表示されます。
- プロジェクトの種類が検出されない場合は、<strong>Manual setup</strong>タブに切り替え、<strong>Project type</strong>ドロップダウンからプロジェクトの種類を選択します。

![CI設定 — プロジェクトの種類の手動選択](/img/getting-started/2026-06-27-add-ci-config-project-type-picker.png)

自動設定をスキップし、後で手動でセットアップする場合は<strong>Skip</strong>をクリックします。

## ビルド設定 {#build-settings}

プロジェクトのビルド設定を確認し、必要に応じて調整します。

- <strong>Build machine</strong>と<strong>Stack</strong>: Bitriseがプロジェクトの種類に基づいて最適な設定をあらかじめ選択します。これらは後からWorkflow Editorで変更できます。詳細は[Build machineのタイプ](/bitrise-build-hub/infrastructure/build-machine-types)および[ビルドスタック](/bitrise-build-hub/infrastructure/build-stacks/about-build-stacks)を参照してください。
- <strong>Access to builds</strong>: <strong>Private</strong>(ビルドログとCI設定ファイルにはWorkspaceのメンバーのみアクセス可能)または<strong>Public</strong>(リンクを知っている人なら誰でも閲覧可能)を選択します。詳細は[公開プロジェクト](/bitrise-platform/projects/public-projects)を参照してください。
- <strong>Register webhooks</strong>: このトグルを有効にすると、BitriseがリポジトリにWebhookを自動的に登録し、コードの変更時にビルドがトリガーされるようになります。GitHubアプリを使用している場合は不要です。詳細は[受信Webhookの追加](/bitrise-platform/integrations/webhooks/adding-incoming-webhooks)を参照してください。

![ビルド設定 — マシン、スタック、アクセス、Webhook](/img/getting-started/2026-06-27-add-ci-config-build-settings.png)

<strong>Finish</strong>をクリックします。Bitriseが最初のビルドを開始し、ビルドページに移動してリアルタイムで実行状況を確認できます。そこから[Workflowsの編集](/bitrise-ci/workflows-and-pipelines/workflows/workflows-overview)を開始したり、[ビルドの実行](/bitrise-ci/run-and-analyze-builds/starting-builds/approving-pull-request-builds)を行ったりできます。
