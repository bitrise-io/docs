[<strong>Maestro Test</strong>](https://github.com/bitrise-steplib/bitrise-step-maestro-test) <GlossTerm baseform="Step">Step</GlossTerm>は、Maestro Cloud ではなく、Bitrise build machine上のAndroidエミュレーターまたは iOS シミュレーターで [Maestro](https://maestro.dev) フローを実行し、結果を [Test reports](/bitrise-ci/testing/test-reports/viewing-test-results) ページに表示します。各フローが 1 つのテストケースとなり、スクリーンショット、録画、ログが添付されます。

## Workflowでの Maestro フローの実行 {#running-maestro-flows-in-a-workflow}

Maestro Workflowは、アプリをビルドし、デバイスを起動し、フローを実行して、結果をアップロードします。<strong>Maestro Test</strong> Stepはフローを実行するだけで、アプリのビルドやデバイスの起動は行いません。そのため、その前にビルドStepとデバイスを起動するStepを追加し、後に <strong>Deploy to Bitrise.io</strong> Stepを追加してください。以下の手順では、Androidアプリと iOS アプリ向けにこれを設定します。

:::important

build machineで実行できるエミュレーターまたはシミュレーターは 1 つだけです。1 つもない場合や 2 つ以上ある場合、Stepは失敗します。

:::

### Androidアプリ {#android-apps}

次のものを用意してください。

- リポジトリ内の Maestro フロー。デフォルトでは、Stepは `.maestro` フォルダー内のフローを実行します。他のフローファイルやフォルダーを実行するには、<strong>Flow path</strong> 入力に列挙します。フローの書き方については、[Maestro のドキュメント](https://docs.maestro.dev)を参照してください。
- アプリの `.apk`。フレームワークは問わず、React Nativeや Flutter も使用できます。Stepは Maestro の Web フローを実行しません。
- Linux Androidの[スタック](/bitrise-ci/configure-builds/configuring-build-settings/setting-the-stack-for-your-builds)。Androidエミュレーターは macOS スタックでは動作しません。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. <GlossTerm baseform="Workflow Editor">Workflow Editor</GlossTerm>で、使用するWorkflowを開きます。
1. [<strong>Android Build</strong>](https://github.com/bitrise-steplib/bitrise-step-android-build) Stepを追加し、<strong>Module</strong> 入力と <strong>Variant</strong> 入力を設定します。
1. [<strong>AVD Manager</strong>](https://github.com/bitrise-steplib/steps-avd-manager) Stepを追加し、<strong>Android API Level</strong> 入力、<strong>OS Tag</strong> 入力、<strong>ABI</strong> 入力でエミュレーターを設定します。ABI は、スタックの CPU アーキテクチャと一致している必要があります。
1. <strong>Maestro Test</strong> Stepを追加し、<strong>App path</strong> 入力を `$BITRISE_APK_PATH` に設定します。
1. [<strong>Deploy to Bitrise.io</strong>](https://github.com/bitrise-steplib/steps-deploy-to-bitrise-io) Stepを追加します。

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. アプリの<GlossTerm baseform="configuration yaml"> Configuration YAML</GlossTerm>ファイルを開きます。
1. Workflowに `android-build` Stepを追加し、`module` 入力と `variant` 入力を設定します。Stepは、アプリの APK をビルドします。

   ```yaml
   - android-build:
       inputs:
       - module: app
       - variant: debug
   ```

1. `avd-manager` Stepを追加し、`api_level` 入力、`tag` 入力、`abi` 入力でエミュレーターを設定します。`maestro-test` Stepはデバイスを起動しないため、このStepがエミュレーターを起動します。ABI は、スタックの CPU アーキテクチャと一致している必要があります。

   ```yaml
   - avd-manager:
       inputs:
       - api_level: 34
       - tag: google_apis
       - abi: x86_64
   ```

1. `maestro-test` Stepを追加し、`app_path` 入力を、`android-build` Stepがエクスポートする APK である `$BITRISE_APK_PATH` に設定します。

   ```yaml
   - maestro-test:
       inputs:
       - app_path: $BITRISE_APK_PATH
   ```

1. 結果が Test Reports ページに表示されるように、`deploy-to-bitrise-io` Stepを追加します。

   ```yaml
   - deploy-to-bitrise-io: {}
   ```

Workflow全体は次のとおりです。

```yaml
workflows:
  maestro-android:
    steps:
    - git-clone: {}
    - android-build:
        inputs:
        - module: app
        - variant: debug
    - avd-manager:
        inputs:
        - api_level: 34
        - tag: google_apis
        - abi: x86_64
    - maestro-test:
        inputs:
        - app_path: $BITRISE_APK_PATH
    - deploy-to-bitrise-io: {}
```

</TabItem>
</Tabs>

エミュレーターは、Android App Bundle(`.aab`)をインストールできません。App Bundle をビルドする場合は、<strong>Maestro Test</strong> Stepの前に、<strong>Export Universal APK</strong> Stepで APK に変換してください。

### iOS アプリ {#ios-apps}

次のものを用意してください。

- リポジトリ内の Maestro フロー。デフォルトでは、Stepは `.maestro` フォルダー内のフローを実行します。他のフローファイルやフォルダーを実行するには、<strong>Flow path</strong> 入力に列挙します。フローの書き方については、[Maestro のドキュメント](https://docs.maestro.dev)を参照してください。
- iOS シミュレーター向けにビルドしたアプリの `.app`。フレームワークは問わず、React Nativeや Flutter も使用できます。Stepは Maestro の Web フローを実行しません。
- macOS の[スタック](/bitrise-ci/configure-builds/configuring-build-settings/setting-the-stack-for-your-builds)。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. <GlossTerm baseform="Workflow Editor">Workflow Editor</GlossTerm>で、使用するWorkflowを開きます。
1. [<strong>Xcode Build for Simulator</strong>](https://github.com/bitrise-steplib/steps-xcode-build-for-simulator) Stepを追加し、<strong>Project path</strong> 入力と <strong>Scheme</strong> 入力を設定します。
1. [<strong>Xcode Start Simulator</strong>](https://github.com/bitrise-steplib/bitrise-step-xcode-start-simulator) Stepを追加し、<strong>Device destination specifier</strong> 入力でシミュレーターを設定します。
1. Stepがシミュレーターの起動を待機するように、<strong>Simulator boot timeout (in seconds)</strong> 入力を設定します。設定しないと、<strong>Maestro Test</strong> Stepがシミュレーターを見つけられない場合があります。
1. <strong>Maestro Test</strong> Stepを追加し、<strong>App path</strong> 入力を `$BITRISE_APP_DIR_PATH` に設定します。
1. [<strong>Deploy to Bitrise.io</strong>](https://github.com/bitrise-steplib/steps-deploy-to-bitrise-io) Stepを追加します。

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. アプリの<GlossTerm baseform="configuration yaml"> Configuration YAML</GlossTerm>ファイルを開きます。
1. Workflowに `xcode-build-for-simulator` Stepを追加し、`project_path` 入力と `scheme` 入力を設定します。Stepは、シミュレーター向けにアプリの `.app` をビルドします。

   ```yaml
   - xcode-build-for-simulator:
       inputs:
       - project_path: MyApp.xcodeproj
       - scheme: MyApp
   ```

1. `xcode-start-simulator` Stepを追加し、`destination` 入力でシミュレーターを設定します。`maestro-test` Stepはデバイスを起動しないため、このStepがシミュレーターを起動します。
1. Stepがシミュレーターの起動を待機するように、`wait_for_boot_timeout` 入力を設定します。設定しないと、`maestro-test` Stepがシミュレーターを見つけられない場合があります。

   ```yaml
   - xcode-start-simulator:
       inputs:
       - destination: platform=iOS Simulator,name=Bitrise iOS default,OS=latest
       - wait_for_boot_timeout: 120
   ```

1. `maestro-test` Stepを追加し、`app_path` 入力を、`xcode-build-for-simulator` Stepがエクスポートする `.app` である `$BITRISE_APP_DIR_PATH` に設定します。

   ```yaml
   - maestro-test:
       inputs:
       - app_path: $BITRISE_APP_DIR_PATH
   ```

1. 結果が Test Reports ページに表示されるように、`deploy-to-bitrise-io` Stepを追加します。

   ```yaml
   - deploy-to-bitrise-io: {}
   ```

```yaml
workflows:

    steps:
    - git-clone: {}
    - xcode-build-for-simulator:
        inputs:
        - project_path: MyApp.xcodeproj
        - scheme: MyApp
    - xcode-start-simulator:
        inputs:
        - destination: platform=iOS Simulator,name=Bitrise iOS default,OS=latest
        - wait_for_boot_timeout: 120
    - maestro-test:
        inputs:
        - app_path: $BITRISE_APP_DIR_PATH
    - deploy-to-bitrise-io: {}
```

## フローへの変数の受け渡し {#passing-variables-to-flows}

Maestro は、`MAESTRO_` で始まるすべての環境変数をフローに渡します。機密性の高い値は、このプレフィックスを付けた[Secrets](/bitrise-ci/configure-builds/secrets)として保存してください。たとえば、`MAESTRO_PASSWORD` という名前の Secret は、フロー内では `${MAESTRO_PASSWORD}` になります。

```yaml
appId: com.example.myapp
---
- launchApp
- tapOn: "Password"
- inputText: ${MAESTRO_PASSWORD}
```

## タグによるフローの選択 {#selecting-flows-with-tags}

フローにタグを付けると、<strong>Maestro Test</strong> Stepが、列挙したタグのいずれかを持つフローだけを実行するか、いずれかを持つフローをスキップするようにできます。

フローにタグを付けるには、フローファイルにタグを追加します。

```yaml
appId: com.example.myapp
tags:
  - smoke
---
- launchApp
```

タグでフローを選択するには、Stepを設定します。<strong>Include tags</strong> には、列挙したタグのいずれかを持つフローだけを実行するタグを、<strong>Exclude tags</strong> には、いずれかを持つフローをスキップするタグを指定します。タグは、カンマまたは改行で区切ります。

```yaml
- maestro-test:
    inputs:
    - app_path: $BITRISE_APK_PATH
    - include_tags: smoke
    - exclude_tags: flaky
```

## 失敗したフローの再試行 {#retrying-failed-flows}

再試行では、失敗したフローを最大 10 回まで再実行します。再実行されるのは失敗したフローだけで、タグと引数は同じものが使われます。再試行で成功したフローは、[不安定](/bitrise-ci/testing/detecting-and-quarantining-flaky-tests#detecting-flaky-tests)として報告され、Stepを失敗させません。

設定するには、<strong>Maestro Test</strong> Stepを構成し、<strong>Number of times a failed flow is reattempted</strong> 入力に再試行回数を設定します。デフォルトは 0 で、再試行は無効になります。

```yaml
- maestro-test:
    inputs:
    - app_path: $BITRISE_APK_PATH
    - num_flaky_test_attempts: 2
```

workspaceの設定で `executionOrder` を使ってフローの順序を指定している場合、フローは再試行されません。

:::important[バージョン要件]

再試行には Maestro 2.6.0 以降が必要です。デフォルトの <strong>Maestro CLI version</strong> はこの要件を満たしているため、これより古いバージョンを設定した場合にのみ問題になります。

:::

## 隔離されたフローのスキップ {#skipping-quarantined-flows}

Bitriseでフローを[隔離](/bitrise-ci/testing/detecting-and-quarantining-flaky-tests#quarantining-flaky-tests)すると、<strong>Maestro Test</strong> Stepはそのフローをスキップします。Test Quarantine は、Enterprise プランで利用できます。

Stepは、設定なしでデフォルトで隔離されたフローをスキップします。<strong>Quarantined tests</strong> 入力が、`$BITRISE_QUARANTINED_TESTS_JSON` からそれらを読み取ります。

Stepは、<strong>Flow path</strong> フォルダー内のパスでフローを照合します。別の <strong>Flow path</strong> フォルダーに同じパスのファイルがある場合、Stepはそのファイルもスキップし、警告をログに記録します。

隔離は 1 つのプラットフォームに適用されます。Stepは各フローをクラス名 `<platform>:<flow file>` で報告します(例: `android:.maestro/login.yaml`)。そのため、Androidで隔離されたフローは、iOS では引き続き実行されます。

:::important[バージョン要件]

Stepが <strong>Flow path</strong> フォルダー内で見つけたフローをスキップするには、Maestro 2.9.0 以降が必要です。<strong>Flow path</strong> に列挙したフローファイルは、どのバージョンでもスキップされます。デフォルトの <strong>Maestro CLI version</strong> はこの要件を満たしています。

:::

## 複数のデバイスでのフローの並列実行 {#running-flows-on-several-devices-in-parallel}

Maestro 独自のシャーディングには 1 台のマシン上に複数のデバイスが必要ですが、<strong>Maestro Test</strong> Stepはこれをサポートしていません。代わりに、Workflowのコピーを <GlossTerm baseform="Pipeline">Pipeline</GlossTerm>で並列に実行し、それぞれを専用の仮想マシンで動かします。[Pipelinesでの並列実行](/bitrise-ci/workflows-and-pipelines/build-pipelines/configuring-a-bitrise-pipeline#running-variations-of-the-same-workflow)を参照してください。

1. 各フローに、それを実行するコピーを示すタグを付けます。`shard0`、`shard1` のようにします。
1. <strong>Include tags</strong> を `shard$BITRISE_IO_PARALLEL_INDEX` に設定します。各コピーには、この Env Var 内で 0 から始まる固有のインデックスが割り当てられます。
1. 結果が Test Reports ページで混ざらないように、コピーごとに異なる <strong>Test name</strong> を設定します。

```yaml
pipelines:
  ui-tests:
    workflows:
      maestro-tests:
        parallel: 2

workflows:
  maestro-tests:
    steps:
    - git-clone: {}
    - android-build:
        inputs:
        - module: app
        - variant: debug
    - avd-manager:
        inputs:
        - api_level: 34
        - tag: google_apis
        - abi: x86_64
    - maestro-test:
        inputs:
        - app_path: $BITRISE_APK_PATH
        - include_tags: shard$BITRISE_IO_PARALLEL_INDEX
        - test_name: Maestro shard $BITRISE_IO_PARALLEL_INDEX
    - deploy-to-bitrise-io: {}
```

## 結果の確認 {#viewing-the-results}

<strong>Maestro Test</strong> Stepの結果は、失敗したフローも含めて、Test Reports ページの <strong>Test name</strong> 入力に指定した名前で確認できます。添付ファイルを表示する <strong>Deploy to Bitrise.io</strong> のバージョンについては、[テスト結果のデプロイ](/bitrise-ci/testing/test-reports/deploying-test-results)を参照してください。

Test Reports ページの各フローの出力には、そのフローが実行したコマンドがステップの一覧として表示されます。

:::tip[すべてのフローに一意の名前を付ける]

Stepは、フローの名前でファイルをフローに添付します。2 つのフローが同じ名前の場合、それらのファイルは添付されません。

:::

Stepは、再試行されたフローのすべての実行を含む JUnit レポートを `$MAESTRO_JUNIT_PATH` に、Maestro の出力フォルダー全体を、実行ごとに 1 つの `attempt-N` フォルダーを含む zip として `$MAESTRO_TEST_OUTPUT_ZIP_PATH` にもエクスポートします。この zip は、ビルドアーティファクトとしてアップロードされます。

## トラブルシューティング {#troubleshooting}

Stepのエラーの最初の行に、失敗した内容が示されます。

| エラー | 原因 |
| --- | --- |
| `Failed to process Step inputs` | 入力の値が無効です。次の行にその入力名が示されます。 |
| `Failed to install the Maestro CLI` | Maestro CLIをダウンロードできなかったか、検証できませんでした。 |
| `Failed to install the app` | デバイスが実行されていない、複数実行されている、またはインストールに失敗しました。デバイスを起動するStepが、起動の完了を待機していることを確認してください。 |
| `Maestro flows failed` | 再試行後も、少なくとも 1 つのフローが失敗しました。Test Reports ページを参照してください。 |
| `Maestro failed without a failing flow` | フローが失敗する前に Maestro が停止しました(たとえば、解析できないフローファイルが原因です)。Stepのログを参照してください。 |
