[<strong>Maestro Test</strong>](https://github.com/bitrise-steplib/bitrise-step-maestro-test) <GlossTerm baseform="Step">Step</GlossTerm> は、Maestro Cloud ではなく、Bitrise build machine 上の Android エミュレーターまたは iOS シミュレーターで [Maestro](https://maestro.dev) フローを実行し、結果を [Test reports](/bitrise-ci/testing/test-reports/viewing-test-results) ページに表示します。各フローが 1 つのテストケースとなり、スクリーンショット、録画、ログが添付されます。

## Workflow で Maestro フローを実行する {#running-maestro-flows-in-a-workflow}

Maestro Workflow は、アプリをビルドし、デバイスを起動し、フローを実行して、結果をアップロードします。<strong>Maestro Test</strong> Step はフローを実行するだけで、アプリのビルドやデバイスの起動は行いません。そのため、この前にビルド Step とデバイスを起動する Step を、この後に <strong>Deploy to Bitrise.io</strong> Step を追加してください。以下の手順では、Android と iOS アプリ向けにこれを設定します。

:::important

build machine で実行できるエミュレーターまたはシミュレーターは 1 つだけです。1 つもない場合や複数ある場合、Step は失敗します。

:::

### Android アプリ {#android-apps}

次のものを用意してください。

- リポジトリ内の Maestro フロー。デフォルトでは、Step は `.maestro` フォルダー内のフローを実行します。他のフローファイルやフォルダーを実行するには、<strong>Flow path</strong> 入力に指定してください。フローの書き方については、[Maestro のドキュメント](https://docs.maestro.dev)を参照してください。
- アプリの `.apk`。React Native や Flutter など、どのフレームワークでも使用できます。Step は Maestro のウェブフローを実行しません。
- Linux Android [スタック](/bitrise-ci/configure-builds/configuring-build-settings/setting-the-stack-for-your-builds)。Android エミュレーターは macOS スタックでは動作しません。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. <GlossTerm baseform="Workflow Editor">Workflow Editor</GlossTerm> で、使用する Workflow を開きます。
1. [<strong>Android Build</strong>](https://github.com/bitrise-steplib/bitrise-step-android-build) Step を追加し、<strong>Module</strong> と <strong>Variant</strong> の入力を設定します。
1. [<strong>AVD Manager</strong>](https://github.com/bitrise-steplib/steps-avd-manager) Step を追加し、<strong>Android API Level</strong>、<strong>OS Tag</strong>、<strong>ABI</strong> の入力でエミュレーターを設定します。ABI はスタックの CPU アーキテクチャと一致している必要があります。
1. <strong>Maestro Test</strong> Step を追加し、<strong>App path</strong> 入力を `$BITRISE_APK_PATH` に設定します。
1. [<strong>Deploy to Bitrise.io</strong>](https://github.com/bitrise-steplib/steps-deploy-to-bitrise-io) Step を追加します。

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. アプリの <GlossTerm baseform="configuration yaml">Configuration YAML</GlossTerm> ファイルを開きます。
1. Workflow に `android-build` Step を追加し、`module` と `variant` の入力を設定します。Step はアプリの APK をビルドします。

   ```yaml
   - android-build:
       inputs:
       - module: app
       - variant: debug
   ```

1. `avd-manager` Step を追加し、`api_level`、`tag`、`abi` の入力でエミュレーターを設定します。`maestro-test` Step はデバイスを起動しないため、この Step がエミュレーターを起動します。ABI はスタックの CPU アーキテクチャと一致している必要があります。

   ```yaml
   - avd-manager:
       inputs:
       - api_level: 34
       - tag: google_apis
       - abi: x86_64
   ```

1. `maestro-test` Step を追加し、`app_path` 入力を、`android-build` Step がエクスポートする APK である `$BITRISE_APK_PATH` に設定します。

   ```yaml
   - maestro-test:
       inputs:
       - app_path: $BITRISE_APK_PATH
   ```

1. `deploy-to-bitrise-io` Step を追加して、Test Reports ページに結果が表示されるようにします。

   ```yaml
   - deploy-to-bitrise-io: {}
   ```

Workflow 全体は次のとおりです。

```yaml
workflows:
  maestro-android:
    steps:
    - git-clone: {}
    - android-build:
        inputs:
        - module: app
        - variant: debug
    - avd-manager:
        inputs:
        - api_level: 34
        - tag: google_apis
        - abi: x86_64
    - maestro-test:
        inputs:
        - app_path: $BITRISE_APK_PATH
    - deploy-to-bitrise-io: {}
```

</TabItem>
</Tabs>

エミュレーターには Android App Bundle（`.aab`）をインストールできません。App Bundle をビルドする場合は、<strong>Maestro Test</strong> Step の前に <strong>Export Universal APK</strong> Step で APK に変換してください。

### iOS アプリ {#ios-apps}

次のものを用意してください。

- リポジトリ内の Maestro フロー。デフォルトでは、Step は `.maestro` フォルダー内のフローを実行します。他のフローファイルやフォルダーを実行するには、<strong>Flow path</strong> 入力に指定してください。フローの書き方については、[Maestro のドキュメント](https://docs.maestro.dev)を参照してください。
- iOS シミュレーター向けにビルドしたアプリの `.app`。React Native や Flutter など、どのフレームワークでも使用できます。Step は Maestro のウェブフローを実行しません。
- macOS [スタック](/bitrise-ci/configure-builds/configuring-build-settings/setting-the-stack-for-your-builds)。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. <GlossTerm baseform="Workflow Editor">Workflow Editor</GlossTerm> で、使用する Workflow を開きます。
1. [<strong>Xcode Build for Simulator</strong>](https://github.com/bitrise-steplib/steps-xcode-build-for-simulator) Step を追加し、<strong>Project path</strong> と <strong>Scheme</strong> の入力を設定します。
1. [<strong>Xcode Start Simulator</strong>](https://github.com/bitrise-steplib/bitrise-step-xcode-start-simulator) Step を追加し、<strong>Device destination specifier</strong> 入力でシミュレーターを設定します。
1. Step がシミュレーターの起動を待つように、<strong>Simulator boot timeout (in seconds)</strong> 入力を設定します。設定しないと、<strong>Maestro Test</strong> Step がシミュレーターを見つけられない場合があります。
1. <strong>Maestro Test</strong> Step を追加し、<strong>App path</strong> 入力を `$BITRISE_APP_DIR_PATH` に設定します。
1. [<strong>Deploy to Bitrise.io</strong>](https://github.com/bitrise-steplib/steps-deploy-to-bitrise-io) Step を追加します。

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. アプリの <GlossTerm baseform="configuration yaml">Configuration YAML</GlossTerm> ファイルを開きます。
1. Workflow に `xcode-build-for-simulator` Step を追加し、`project_path` と `scheme` の入力を設定します。Step はシミュレーター向けにアプリの `.app` をビルドします。

   ```yaml
   - xcode-build-for-simulator:
       inputs:
       - project_path: MyApp.xcodeproj
       - scheme: MyApp
   ```

1. `xcode-start-simulator` Step を追加し、`destination` 入力でシミュレーターを設定します。`maestro-test` Step はデバイスを起動しないため、この Step がシミュレーターを起動します。
1. Step がシミュレーターの起動を待つように、`wait_for_boot_timeout` 入力を設定します。設定しないと、`maestro-test` Step がシミュレーターを見つけられない場合があります。

   ```yaml
   - xcode-start-simulator:
       inputs:
       - destination: platform=iOS Simulator,name=Bitrise iOS default,OS=latest
       - wait_for_boot_timeout: 120
   ```

1. `maestro-test` Step を追加し、`app_path` 入力を、`xcode-build-for-simulator` Step がエクスポートする `.app` である `$BITRISE_APP_DIR_PATH` に設定します。

   ```yaml
   - maestro-test:
       inputs:
       - app_path: $BITRISE_APP_DIR_PATH
   ```

1. `deploy-to-bitrise-io` Step を追加して、Test Reports ページに結果が表示されるようにします。

   ```yaml
   - deploy-to-bitrise-io: {}
   ```

Workflow 全体は次のとおりです。

```yaml
workflows:
  maestro-ios:
    steps:
    - git-clone: {}
    - xcode-build-for-simulator:
        inputs:
        - project_path: MyApp.xcodeproj
        - scheme: MyApp
    - xcode-start-simulator:
        inputs:
        - destination: platform=iOS Simulator,name=Bitrise iOS default,OS=latest
        - wait_for_boot_timeout: 120
    - maestro-test:
        inputs:
        - app_path: $BITRISE_APP_DIR_PATH
    - deploy-to-bitrise-io: {}
```

## フローへの変数の受け渡し {#passing-variables-to-flows}

Maestro は、`MAESTRO_` で始まるすべての Environment Variable をフローに渡します。機密性の高い値は、このプレフィックスを付けた [Secrets](/bitrise-ci/configure-builds/secrets) として保存してください。たとえば、`MAESTRO_PASSWORD` という名前の Secret は、フロー内で `${MAESTRO_PASSWORD}` として参照できます。

```yaml
appId: com.example.myapp
---
- launchApp
- tapOn: "Password"
- inputText: ${MAESTRO_PASSWORD}
```

## タグでフローを選択する {#selecting-flows-with-tags}

フローにタグを付けると、<strong>Maestro Test</strong> Step が、リストされたいずれかのタグを持つフローのみを実行したり、いずれかのタグを持つフローをスキップしたりするようにできます。

フローにタグを付けるには、フローファイルにタグを追加します。

```yaml
appId: com.example.myapp
tags:
  - smoke
---
- launchApp
```

タグでフローを選択するには、Step を設定します。<strong>Include tags</strong> を設定すると、リストされたいずれかのタグを持つフローのみを実行し、<strong>Exclude tags</strong> を設定すると、いずれかのタグを持つフローをスキップします。タグはカンマまたは改行で区切ります。

```yaml
- maestro-test:
    inputs:
    - app_path: $BITRISE_APK_PATH
    - include_tags: smoke
    - exclude_tags: flaky
```

## 失敗したフローを再試行する {#retrying-failed-flows}

再試行では、失敗したフローを最大 10 回まで再実行します。再実行されるのは失敗したフローのみで、タグと引数は同じものが使われます。再試行で成功したフローは[不安定](/bitrise-ci/testing/detecting-and-quarantining-flaky-tests#detecting-flaky-tests)（flaky）として報告され、Step を失敗させません。

設定するには、<strong>Maestro Test</strong> Step を構成し、<strong>Number of times a failed flow is reattempted</strong> 入力に再試行の回数を設定します。デフォルトは 0 で、再試行は無効です。

```yaml
- maestro-test:
    inputs:
    - app_path: $BITRISE_APK_PATH
    - num_flaky_test_attempts: 2
```

workspace の設定で `executionOrder` によってフローの順序が指定されている場合、フローは再試行されません。

:::important[バージョン要件]

再試行には Maestro 2.6.0 以降が必要です。デフォルトの <strong>Maestro CLI version</strong> はこの要件を満たしているため、古いバージョンを設定した場合にのみ注意が必要です。

:::

## 隔離されたフローをスキップする {#skipping-quarantined-flows}

Bitrise でフローを[隔離](/bitrise-ci/testing/detecting-and-quarantining-flaky-tests#quarantining-flaky-tests)すると、<strong>Maestro Test</strong> Step はそのフローをスキップします。Test Quarantine は Enterprise プランで利用できます。

Step は、セットアップなしで、デフォルトで隔離されたフローをスキップします。<strong>Quarantined tests</strong> 入力が `$BITRISE_QUARANTINED_TESTS_JSON` から隔離されたフローを読み取ります。

Step は、<strong>Flow path</strong> フォルダー内のパスでフローを照合します。別の <strong>Flow path</strong> フォルダーに同じパスのファイルがある場合、Step はそのファイルもスキップし、警告をログに記録します。

隔離は 1 つのプラットフォームに適用されます。Step は各フローをクラス名 `<platform>:<flow file>`（例: `android:.maestro/login.yaml`）で報告するため、Android で隔離されたフローも iOS では引き続き実行されます。

:::important[バージョン要件]

Step が <strong>Flow path</strong> フォルダー内で見つけたフローをスキップするには、Maestro 2.9.0 以降が必要です。<strong>Flow path</strong> に直接リストしたフローファイルは、どのバージョンでもスキップされます。デフォルトの <strong>Maestro CLI version</strong> はこの要件を満たしています。

:::

## 複数のデバイスでフローを並列実行する {#running-flows-on-several-devices-in-parallel}

Maestro 独自のシャーディングは 1 台のマシン上に複数のデバイスを必要としますが、<strong>Maestro Test</strong> Step はこれをサポートしていません。代わりに、<GlossTerm baseform="Pipeline">Pipeline</GlossTerm> で Workflow のコピーを並列に実行し、それぞれを専用の仮想マシンで動かします。詳しくは、[Pipelines での並列実行](/bitrise-ci/workflows-and-pipelines/build-pipelines/configuring-a-bitrise-pipeline#running-variations-of-the-same-workflow)を参照してください。

1. 各フローに、それを実行するコピーを示すタグを付けます: `shard0`、`shard1` など。
1. <strong>Include tags</strong> を `shard$BITRISE_IO_PARALLEL_INDEX` に設定します。各コピーには、この Env Var 内で 0 から始まる固有のインデックスが割り当てられます。
1. 結果が Test Reports ページで混ざらないように、コピーごとに異なる <strong>Test name</strong> を設定します。

```yaml
pipelines:
  ui-tests:
    workflows:
      maestro-tests:
        parallel: 2

workflows:
  maestro-tests:
    steps:
    - git-clone: {}
    - android-build:
        inputs:
        - module: app
        - variant: debug
    - avd-manager:
        inputs:
        - api_level: 34
        - tag: google_apis
        - abi: x86_64
    - maestro-test:
        inputs:
        - app_path: $BITRISE_APK_PATH
        - include_tags: shard$BITRISE_IO_PARALLEL_INDEX
        - test_name: Maestro shard $BITRISE_IO_PARALLEL_INDEX
    - deploy-to-bitrise-io: {}
```

## 結果を確認する {#viewing-the-results}

<strong>Maestro Test</strong> Step の結果は、失敗したフローも含めて、Test Reports ページの <strong>Test name</strong> 入力で指定した名前で確認できます。添付ファイルを表示できる <strong>Deploy to Bitrise.io</strong> のバージョンについては、[テスト結果のデプロイ](/bitrise-ci/testing/test-reports/deploying-test-results)を参照してください。

Test Reports ページの各フローの出力には、フローが実行したコマンドが Step の一覧として表示されます。

:::tip[すべてのフローに一意の名前を付ける]

Step は、フローの名前でファイルをフローに添付します。2 つのフローが同じ名前の場合、ファイルは添付されません。

:::

Step は、再試行されたフローのすべての実行を含む JUnit レポートを `$MAESTRO_JUNIT_PATH` に、Maestro の出力フォルダー全体を zip として `$MAESTRO_TEST_OUTPUT_ZIP_PATH` にもエクスポートします。zip には、実行ごとに 1 つの `attempt-N` フォルダーが含まれます。zip はビルドのアーティファクトとしてアップロードされます。

## トラブルシューティング {#troubleshooting}

Step のエラーの 1 行目に、失敗した内容が示されます。

| エラー | 原因 |
| --- | --- |
| `Failed to process Step inputs` | 入力の値が無効です。次の行にその入力名が示されます。 |
| `Failed to install the Maestro CLI` | Maestro の CLI をダウンロードまたは検証できませんでした。 |
| `Failed to install the app` | 実行中のデバイスがない、複数のデバイスが実行中、またはインストールに失敗しました。デバイスを起動する Step が起動完了を待つようにしてください。 |
| `Maestro flows failed` | 再試行後も、少なくとも 1 つのフローが失敗しました。Test Reports ページを確認してください。 |
| `Maestro failed without a failing flow` | フローが失敗する前に Maestro が停止しました。たとえば、解析できないフローファイルがあった場合などです。Step のログを確認してください。 |
