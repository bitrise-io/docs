強化されたXcodeレポート機能を使用すると、Xcodeのテスト結果をリッチなHTML形式ですぐに確認できます。成功したテストケースと失敗したテストケースの両方に加え、テストで生成された動画やスクリーンショットも表示されます。

利用するには、ビルドで次の2つを行う必要があります。

- Xcodeのテストを実行し、`.xcresult`ファイルを正しい場所に配置します。<strong>Xcode Test for iOS</strong>と<strong>Xcode Test for Building</strong> Stepsはデフォルトでこれを行うため、追加の設定は必要ありません。<strong>fastlane</strong>など他のStepsを使用することもできますが、その場合はXcodeが`.xcresult`ファイルを配置する場所を指定する必要があります。
- <strong>Generate Xcode HTML report</strong> Stepを実行します。これは`.xcresult`ファイルを受け取ってレポートを生成します。テストの実行に<strong>Xcode Test for iOS</strong> Stepを使用している場合、このStepに設定は必要ありません。他のStepsを使用する場合は、`.xcresult`ファイルの場所を手動で設定する必要があります。

テストの実行には、公式の<strong>Xcode Test for iOS</strong> Stepを使用することを強くおすすめします。このStepは`.xcresult`ファイルを生成し、<strong>Generate Xcode HTML report</strong> Stepが追加の設定なしでそれを検出します。

リッチなテスト結果を表示するには、次の手順に従います。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. Xcodeのテストを実行するStepをWorkflowに追加します。

   :::note[Xcode Test for iOS Stepの使用をおすすめします]

   <strong>Xcode Test for iOS</strong> Step(および<strong>Xcode Test without building</strong> Step)を使用すると、結果のエクスポートに追加の設定は必要ありません。

   他のStepsを使用してテストを実行し、後からリッチな結果を表示することもできます。その場合は、Stepが`.xcresult`ファイルを生成することを確認したうえで、<strong>Generate Xcode HTML report</strong> Stepにその場所を指定する必要があります。たとえば、<strong>fastlane</strong> Stepや独自の<strong>Script</strong> Stepを使用できます。

   :::

   Stepを設定してXcodeのテストを実行する方法の詳細については、[iOSアプリのユニットテストとUIテストの実行](/bitrise-ci/testing/testing-ios-apps/running-unit-and-ui-tests-for-ios-apps)を参照してください。
1. <strong>Generate Xcode HTML report</strong> StepをWorkflowに追加します。

   これは当然、テストを実行するStepの後に配置する必要があります。
1. <strong>Xcresult file paths</strong>の入力が`.xcresult`ファイルの場所を指していることを確認します。

   この入力には、1つ以上のディレクトリを指定するか、改行(/n)で区切ったファイルパスを指定することで、複数の`.xcresult`ファイルを追加できます。各ファイルにはそれぞれ個別のレポートが作成されます。

   :::important[設定は不要です]

   <strong>Xcode Test for iOS</strong> Stepを使用している場合、この入力を変更する必要はありません。

   :::

   ![generate-xcode-reports_input.png](/img/_paligo/uuid-a928eed7-d498-758b-6a6c-5a8ef7b202d1.png)
1. Workflowの末尾に<strong>Deploy to Bitrise.io</strong> Stepが含まれていることを確認します。

   このStepがないと、結果はエクスポートされません。

   :::important[バージョンの要件]

   Stepはバージョン2.7.2以降である必要があります。

   :::
1. ビルドが完了したら、build summaryページに移動します。

   :::note[失敗したビルド]

   ビルドが失敗した場合でも、テスト結果は利用できます。

   :::
1. <strong>Tests</strong>タブを選択して結果を表示します。

   :::important[有効期限]

   HTMLテストレポートは生成から7日間利用できます。7日を過ぎると、アクセスできなくなります。

   :::

   ![html-test-result.png](/img/_paligo/uuid-bf85c17c-277e-088a-13b0-3fe96e79cc7d.png)

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. Xcodeのテストを実行するStepをWorkflowに追加します。

   これには`xcode-test` Stepを使用することを強くおすすめします。

   ```yaml
   my-workflow:
     steps:
     - xcode-test: {}
   ```

   :::note[xcode-test Stepの使用をおすすめします]

   `xcode-test` Step(および`xcode-test-without-building` Step)を使用すると、結果のエクスポートに追加の設定は必要ありません。

   他のStepsを使用してテストを実行し、後からリッチな結果を表示することもできます。その場合は、Stepが`.xcresult`ファイルを生成することを確認したうえで、`generate-xcode-html-report` Stepにその場所を指定する必要があります。たとえば、`fastlane` Stepや独自の`script` Stepを使用できます。

   :::

   Stepを設定してXcodeのテストを実行する方法の詳細については、[iOSアプリのユニットテストとUIテストの実行](/bitrise-ci/testing/testing-ios-apps/running-unit-and-ui-tests-for-ios-apps)を参照してください。
1. `generate-xcode-html-report` StepをWorkflowに追加します。

   これは当然、テストを実行するStepの後に配置する必要があります。

   ```yaml
   my-workflow:
     steps:
     - xcode-test: {}
     - generate-xcode-html-report: {}
   ```
1. `xcresult_patterns`の入力が`.xcresult`ファイルの場所を指していることを確認します。

   この入力には、1つ以上のディレクトリを指定するか、改行(/n)で区切ったファイルパスを指定することで、複数の`.xcresult`ファイルを追加できます。各ファイルにはそれぞれ個別のレポートが作成されます。

   ```yaml
   my-workflow:
     steps:
     - xcode-test: {}
     - generate-xcode-html-report:
         is_always_run: true
         inputs: 
         - xcresult_patterns: /path/to/MyApp.xcresult
   ```

   :::important[設定は不要です]

   <strong>Xcode Test for iOS</strong> Stepを使用している場合、この入力を変更する必要はありません。

   :::
1. Workflowの末尾に`deploy-to-bitrise-io` Stepが含まれていることを確認します。

   このStepがないと、結果はエクスポートされません。

   :::important[バージョンの要件]

   Stepはバージョン2.7.2以降である必要があります。

   :::

   ```yaml
   my-workflow:
     steps:
     - xcode-test: {}
     - generate-xcode-html-report:
         is_always_run: true
         inputs: 
         - xcresult_patterns: /path/to/MyApp.xcresult
     - deploy-to-bitrise-io: {}
   ```
1. ビルドが完了したら、build summaryページに移動します。

   :::note[失敗したビルド]

   ビルドが失敗した場合でも、テスト結果は利用できます。

   :::
1. <strong>Tests</strong>タブを選択して結果を表示します。

   :::important[有効期限]

   HTMLテストレポートは生成から7日間利用できます。7日を過ぎると、アクセスできなくなります。

   :::

   ![html-test-result.png](/img/_paligo/uuid-bf85c17c-277e-088a-13b0-3fe96e79cc7d.png)

</TabItem>
</Tabs>

:::caution

生成されるHTMLレポートは、公式のBitriseコンテンツではないことにご注意ください。このレポートはWorkflowの設定に完全に基づいて生成されます。Bitriseはレポートに表示される内容を直接制御することはできません。

:::
