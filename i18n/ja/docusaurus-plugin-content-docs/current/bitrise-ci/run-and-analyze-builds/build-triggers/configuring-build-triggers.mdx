このページでは、<GlossTerm baseform="workflow">Workflow</GlossTerm>または<GlossTerm baseform="pipeline">Pipeline</GlossTerm>内で定義される、ターゲットベースのビルドトリガーについて説明します。より詳細で柔軟なビルドトリガーシステムを利用できるため、すべての新規ユーザーにこの方法をお勧めします。

## ビルドトリガーの作成

ビルドトリガーは、WorkflowまたはPipeline内で直接作成します。このようなトリガーを使用すると、1つのコードイベントで複数のWorkflowsまたはPipelinesをトリガーできます。トリガーはUI、または<GlossTerm baseform="configuration yaml">設定YAML</GlossTerm>ファイルで作成できます。

トリガーを作成するには、次の手順に従います。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. <Partial_OpeningTheWorkflowEditor />
1. Select a Workflow。
1. Workflowのページで<strong>Triggers</strong>タブを選択します。

   ![trigger-in-workflow.png](/img/_paligo/uuid-fcb0bba9-a8a5-e874-c5ba-a5e0f08d8a80.png)
1. trigger typeを選択し、<strong>Add trigger</strong>ボタンをクリックします。
1. ダイアログでトリガーを設定します。

   トリガー条件の値を定義する際に正規表現を使用するには、正規表現パターンボタンをクリックして有効にします。

   ![regex-button.png](/img/_paligo/uuid-2106af45-7e79-2a1c-5974-9a8f0bb78ffe.png)
1. 完了したら、<strong>Add trigger</strong>をクリックします。

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. 設定YAMLファイルを開きます。
1. Workflowを見つけます。
1. Workflow内に`triggers`プロパティを追加します。

   ```yaml
   my-workflow:
     triggers:
   ```
1. トリガーを作成します。各トリガータイプの正確な構文については、[YAMLのビルドトリガー構文](/bitrise-ci/run-and-analyze-builds/build-triggers/yaml-syntax-for-build-triggers)をご覧ください。

   たとえば、次のトリガーは`my-workflow`という名前のWorkflowでビルドを開始します。

   ```yaml
   my-workflow:
     triggers:
       push:
       - commit_message: your_message
   ```

   パターンマッチングには2つのプロパティを使用できます。

   - `pattern`を使用すると、シンプルなワイルドカードマッチングを利用できます。
   - `regex`を使用すると、正規表現による複雑なパターンマッチングを利用できます。

   ```yaml
   my_awesome_workflow
     triggers:
       push:
         - branch: main
         - commit_message:
             pattern: "hello"
             last_commit: true
       pull_request:
         - source_branch: "*"
   ```
1. 設定を保存します。

</TabItem>
</Tabs>

### Triggersページでターゲットベースのトリガーを新規追加する

<strong>Triggers</strong>ページを離れることなく、新しいターゲットベースのトリガーをすばやく追加できます。たとえば、アクティブなトリガーを確認した後、コンテキストを切り替えずにすぐ別のトリガーを追加でき、設定作業を効率化できます。

1. プロジェクトの<strong>Triggers</strong>ページに移動します。
1. まだトリガーがない場合、<strong>Triggers</strong>ページの中央に新しい<strong>Add Trigger</strong>ボタンが表示されます。<strong>Add trigger</strong>をクリックし、ダイアログに入力します。

   ![addnewtrigger.png](/img/_paligo/uuid-2d246b3d-6d4f-d215-8ee7-7d628492f7aa.png)
1. すでにターゲットベースのトリガーがある場合、<strong>add trigger</strong>ボタンはトリガーの上、右上に表示されます。<strong>add trigger</strong>をクリックし、ダイアログに入力します。

   ![addanothertrigger.png](/img/_paligo/uuid-8a1664ba-48bd-f04b-5453-60cd9641e2ca.png)

ここでトリガーを追加すると特定のワークフローが作成され、そのワークフローの<strong>Triggers</strong>タブが<strong>Workflows</strong>ページに表示されるため、簡単に管理できます。


## トリガーの無効化

任意のビルドトリガーを一時的に無効にできます。無効化されたトリガーはビルドをトリガーしませんが、設定情報はすべて保持されます。無効化したトリガーはいつでも再度有効にできます。

ビルドトリガーを無効にするには、次の手順に従います。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. Bitriseで<GlossTerm baseform="workflow editor">Workflow Editor</GlossTerm>を開きます。
1. Select a WorkflowまたはPipeline。
1. Workflowページで<strong>Triggers</strong>タブを選択します。

   ![workflow-properties.png](/img/_paligo/uuid-7755ec1f-eb8f-5036-05b3-be1b330f2143.png)
1. 必要なトリガーを見つけ、その名前の横にあるオプションメニュー(⋮)をクリックします。

   ![workflow-properties-ellipsis.png](/img/_paligo/uuid-3ab9024b-207a-0b06-c099-714f8c053ecd.png)
1. <strong>トリガーを無効化</strong>を選択します。

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. 設定YAMLファイルを開きます。
1. WorkflowまたはPipelineとその`triggers`プロパティを見つけます。
1. 無効にしたいトリガーに`enabled: false`を追加します。

   ```yaml
   triggers:
     push:
     - branch: main
       enabled: false
   ```

</TabItem>
</Tabs>


## 最新のGitコミットに対するトリガーの作成

デフォルトでは、コードプッシュトリガーで<strong>Commit message</strong>または<strong>File change</strong>条件を使用する場合、Bitriseは1回のコードプッシュに含まれるすべてのコミットメッセージとすべての変更ファイルを評価します。

ただし、プッシュ内の最新のコミットのみを評価するようにトリガーを設定することもできます。プッシュに複数のコミットが含まれる場合、評価されるのは最新の1件のみです。

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. [新しいプッシュトリガーの作成](/bitrise-ci/run-and-analyze-builds/build-triggers/configuring-build-triggers#creating-build-triggers)を参照してください。
1. <strong>Commit message</strong>または<strong>File change</strong>条件のいずれかを選択します。

   ![last-commit.png](/img/_paligo/uuid-31ba9329-7c53-4411-103e-df47df050799.png)
1. 条件の下で<strong>Last commit only</strong>を有効にします。

</TabItem>
<TabItem value="configuration-yaml" label="Configuration YAML">

1. 設定YAMLファイルを開き、Workflowに移動します。
1. 新しいプッシュトリガーを追加します。この例では`commit_message`条件を使用しています。

   ```yaml
   my-workflow:
     triggers:
       push:
       - commit_message: your_message
   ```
1. `last_commit`プロパティを追加し、`true`に設定します。

   ```yaml
   my-workflow:
     triggers:
       push:
       - commit_message: your_message
         last_commit: true
   ```

</TabItem>
</Tabs>


## ドラフトPRからのビルドトリガー実行

GitHubとGitLabには、[ドラフトプルリクエスト](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/about-pull-requests#draft-pull-requests)(GitLabの場合はマージリクエスト)という機能があります。プルリクエスト(PR)を作成する際、レビュー可能な状態のプルリクエストとして作成するか、ドラフトプルリクエストとして作成するかを選択できます。ドラフトプルリクエストはマージできず、コードオーナーに自動的にレビューが依頼されることもありません。

:::important[Gitプロバイダーの制限事項]

この機能はGitHubおよびGitLabのリポジトリでのみサポートされています。

:::

デフォルトでは、ドラフトPRを開くとビルドがトリガーされます。この動作はいつでも無効にできます。

ドラフトPRを開いた際にビルドがトリガーされた場合、それをレビュー用に提出しても(つまり「正式な」PRに変換しても)、再度トリガーされることはありません。ドラフトPRのトリガー設定によって、どのコードイベントでビルドがトリガーされるかを確認できます。[ドラフトPRのビルドトリガーの動作](#build-trigger-behavior-for-draft-prs)。

それぞれのトリガーには個別のトグルがあり、特定のトリガーはドラフトPRからビルドを開始し、他のトリガーは開始しないようにアプリを設定できます。

### ドラフトPRからのビルドの無効化

:::tip[ビルドがドラフトPRによってトリガーされた場合のStepsのスキップ]

このガイドでは、ドラフトPRからのビルドトリガーを完全に無効にする方法を説明します。ただし、ドラフトプルリクエストによってトリガーされたビルド内で特定のStepsをスキップすることも可能です。その場合は、`run_if`条件とGITHUB_PR_IS_DRAFT環境変数を使用するだけです。詳細については、[Stepの条件付き有効化・無効化](/bitrise-ci/workflows-and-pipelines/steps/enabling-or-disabling-a-step-conditionally)をご覧ください。

:::

<Tabs>
<TabItem value="workflow-editor" label="Workflow Editor" default>

1. <Partial_OpeningTheWorkflowEditor />
1. Workflowを開き、<strong>Triggers</strong>タブを選択します。

   Pipelineがある場合、この設定は設定YAMLファイルでのみ無効にできます。
1. 必要なトリガーを見つけ、その名前の横にあるオプションメニュー(⋮)をクリックします。
1. メニューから<strong>Edit trigger</strong>を選択します。

   ![edit-trigger.png](/img/_paligo/uuid-7e1fea02-d6ed-650a-043c-d8bb81c5f98e.png)
1. <strong>Include draft pull requests</strong>オプションのチェックを外し、<strong>Apply changes</strong>をクリックします。

</TabItem>
<TabItem value="bitriseyml" label="Configuration YAML">

1. 設定YAMLファイルを開きます。
1. 変更したいすべてのWorkflowsまたはPipelines内の`triggers`要素を見つけます。
1. 必要なトリガーエントリに`draft_enabled: false`を追加します。

   ```yaml
   triggers:
         pull_request:
         - target_branch: "develop"
           draft_enabled: false
         - target_branch: "main"
           draft_enabled: false
         - comment: 'run Bitrise'
   ```

   これにより、developブランチとmainブランチに対する非ドラフトのPR、または任意のPRに`run Bitrise`がコメントされた場合にワークフローが開始されます。

</TabItem>
</Tabs>

Assembla、Deveo(Perforce)、Gogsはプッシュベースのトリガーのみをサポートしています。これらのプロバイダーではプルリクエストトリガーは利用できません。

:::

:::important[GitHubのスタックされたプルリクエスト]

[GitHubスタック](https://docs.github.com/en/pull-requests/get-started/about-stacked-prs)内のプルリクエストの場合、Bitriseはターゲットブランチ条件を、プルリクエストが直接ターゲットとするブランチではなく、スタックのベースブランチと照合します。

`feature/part-2`が`feature/part-1`をターゲットとし、スタック全体が`main`にマージされるスタックを例に考えます。`target_branch: main`条件はスタック内のすべてのプルリクエストに一致します。`feature/part-1`に設定された条件はいずれにも一致しません。

:::
