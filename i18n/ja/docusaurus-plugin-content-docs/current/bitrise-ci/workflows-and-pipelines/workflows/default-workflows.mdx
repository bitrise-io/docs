[bitrise.io](https://www.bitrise.io)で新しいプロジェクトを追加すると、初期の<GlossTerm baseform="Pipeline">Pipelines</GlossTerm>と<GlossTerm baseform="Workflow">Workflows</GlossTerm>が作成されます。これらはデフォルトのPipelinesおよびWorkflowsと呼ばれます。デフォルトのPipelineはdefault Workflowsで構成されます。

これらを使用してテストを実行したり、IPAやAPKなどのインストール可能なバイナリを作成したりできます。必要に応じて、デフォルトのPipelinesおよびWorkflowsを自由に変更してください。

:::tip[デフォルトのPipelines]

デフォルトのPipelinesも作成します。[デフォルトのPipelines](/bitrise-ci/workflows-and-pipelines/build-pipelines/default-pipelines)。

:::


## iOSプロジェクト向けのDefault Workflows {#default-workflows-for-an-ios-project}

新しいiOSプロジェクトでは、Bitriseが自動的に複数のWorkflowsを生成します。これらのWorkflowsをカスタマイズしたり、それらをもとに[新しく作成](/bitrise-ci/workflows-and-pipelines/workflows/creating-a-workflow)したりできます。

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | Xcodeのテストを実行し、テストレポートを取得します。 | WorkflowはGitリポジトリをクローンし、プロジェクトの依存関係がある場合はそれをキャッシュしてインストールし、Xcodeのテストを実行してテスト結果を保存します。 |
| `build_for_testing` | テスト用にXcodeプロジェクトをビルドします。 | WorkflowはGitリポジトリをクローンし、テスト用にアプリをビルドし、各テストシャードにテストを振り分けて、後続のWorkflowsで使用できるようにアプリとテストをBitriseにデプロイします。このWorkflowはデフォルトのPipelineの一部です。 |
| `test_without_building` | 再ビルドせずにiOSアプリをテストします。 | Pipeline内の前のWorkflowからアプリとテストを取得し、Xcodeの`test_without_building`コマンドを使用してコンパイル済みのバンドルをテストします。このWorkflowはデフォルトのPipelineの一部です。 |
| `archive_and_export_app` | Xcodeのテストを実行し、デバイスにアプリをインストールしたりチームと共有したりするためのIPAファイルを作成します。 | WorkflowはGitリポジトリをクローンし、プロジェクトの依存関係がある場合はそれをキャッシュしてインストールし、Xcodeのテストを実行して、[プロジェクトからIPAファイルをエクスポート](/bitrise-ci/code-signing/ios-code-signing/creating-a-signed-ipa-for-xcode-projects)します。 |
| `build` | Xcodeプロジェクトをビルドします。このWorkflowは、<GlossTerm baseform="Project scanner">プロジェクトスキャナー</GlossTerm>がXcodeプロジェクトでテストの設定を検出しなかった場合にのみ生成されます。 | WorkflowはGitリポジトリをクローンし、プロジェクトの依存関係がある場合はそれをキャッシュしてインストールし、プロジェクトをビルドします。Xcodeの[テスト用ビルド](/bitrise-ci/testing/testing-ios-apps/building-an-ios-app-for-testing)アクションを使用します。 |


## Androidプロジェクト向けのDefault Workflows {#default-workflows-for-an-android-project}

新しいAndroidプロジェクトでは、Bitriseが自動的に3つの新しいWorkflowsを生成します。これらのWorkflowsをカスタマイズしたり、それらをもとに[新しく作成](/bitrise-ci/workflows-and-pipelines/workflows/creating-a-workflow)したりできます。

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | Androidの単体テストを実行し、テストレポートを取得します。 | WorkflowはGitリポジトリをクローンし、[Gradleの依存関係をキャッシュ](/bitrise-ci/dependencies-and-caching/android-dependencies)し、Androidツールをインストールし、[Androidの単体テスト](/bitrise-ci/testing/testing-android-apps/android-unit-tests)を実行して[テストレポート](/bitrise-ci/testing/deploying-and-viewing-test-results)を保存します。 |
| `build_apk` | Androidの単体テストを実行し、デバイスにアプリをインストールしたりチームと共有したりするためのAPKファイルを作成します。 | WorkflowはGitリポジトリをクローンし、Androidツールをインストールし、[ビルド番号に基づいてプロジェクトのバージョンコードを設定](/bitrise-ci/run-and-analyze-builds/build-numbering-and-app-versioning#setting-up-app-versioning-automatically-on-bitrise)し、[Androidのlint](/bitrise-ci/testing/testing-android-apps/running-lint-for-your-android-apps)と単体テストを実行して、プロジェクトのAPKファイルをビルドして保存します。 |
| `run_instrumented_tests` | テストシャーディングを使用してAndroidのインストルメンテーションテストを実行し、テストレポートを取得します。 | WorkflowはGitリポジトリをクローンし、[Gradleの依存関係をキャッシュ](/bitrise-ci/dependencies-and-caching/android-dependencies)し、Androidツールをインストールし、Androidエミュレーターを起動してAndroidのインストルメンテーションテストを実行し、[テストレポート](/bitrise-ci/testing/deploying-and-viewing-test-results)を保存します。このWorkflowは、[並列処理](/bitrise-ci/workflows-and-pipelines/build-pipelines/configuring-a-bitrise-pipeline#running-variations-of-the-same-workflow)を利用するデフォルトのPipelineの一部です。複数のWorkflowのコピーを実行してインストルメンテーションテストをシャーディングします。 |


## Node.jsプロジェクト向けのDefault Workflows {#default-workflows-for-a-nodejs-project}

Bitriseは、Node.jsプロジェクト向けにデフォルトのWorkflowを1つ生成します。プロジェクトのlintスクリプトとテストスクリプトを実行するWorkflowです。このWorkflowをカスタマイズしたり、それをもとに新しく作成したりできます。

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | プロジェクトのテストを実行します。 | WorkflowはGitリポジトリをクローンし、Nodeのバージョンを選択してインストールし、`npm`パッケージをインストールして、`package.json`ファイル内で利用可能なスクリプトに応じて、lintスクリプトとテストスクリプトを実行します。Workflowはパフォーマンス向上のために`node_modules`のキャッシュもサポートしています。`lint`と`test`の各Stepは、検出されたパッケージマネージャーに応じてnpmまたはYarnを使用します。どちらのロックファイルも存在しない場合、ユーザーはセットアップ時にパッケージマネージャーを対話形式で選択します。 |


## Kotlin Multiplatformプロジェクト向けのDefault Workflows {#default-workflows-for-a-kotlin-multiplatform-project}

Bitriseは、Kotlin Multiplatformプロジェクト向けに3つのdefault Workflowsを生成します。1つはテストを実行するため、1つはAndroidアプリをビルドするため、もう1つはiOSアプリをビルドするためのものです。

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | プロジェクトのテストを実行します。 | WorkflowはGitリポジトリをクローンし、<strong>Gradle Unit Test</strong> <GlossTerm baseform="step">Step</GlossTerm>を使用して`test`のGradleタスクを実行し、Gradleタスクの出力をキャッシュします。 |
| `android_build` | KotlinプロジェクトからAndroidアプリをビルドして署名します。 | WorkflowはGitリポジトリをクローンし、<strong>Android Build</strong> Stepを使用してアプリをビルドし、<strong>Android Sign</strong>で[署名](/bitrise-ci/code-signing/android-code-signing/android-code-signing-using-the-android-sign-step)して、Gradleタスクの出力をキャッシュします。ダウンロード可能なAPKファイルを生成します。 |
| `ios_build` | KotlinプロジェクトからiOSアプリをビルドして署名します。 | WorkflowはGitリポジトリをクローンし、<strong>Xcode Archive & Export for iOS</strong> Stepを使用してアプリをビルドおよび[署名](/bitrise-ci/code-signing/ios-code-signing/creating-a-signed-ipa-for-xcode-projects)し、Gradleタスクの出力をキャッシュします。ダウンロード可能なIPAファイルを生成します。 |


## Javaプロジェクト向けのDefault Workflows {#default-workflows-for-a-java-project}

プロジェクトスキャナーはJavaプロジェクトを検出し、それらに対するdefault Workflowsを作成できます。新しいプロジェクトは、次の場合に汎用のJavaプロジェクトと見なされます。

- Gradleを使用しており(コードにプロジェクトのルートディレクトリ内の通常のGradle設定ファイルとGradle Wrapperスクリプトが含まれている)、AndroidまたはKotlin Multiplatformの必須の依存関係を使用していない。
- ルートディレクトリに`POM.xml`プロジェクト設定ファイルを含むMavenを使用しており、Maven Wrapperスクリプトがある。

汎用のJavaプロジェクトの場合、Bitriseはビルドツールに基づいてdefault Workflowsを生成します。

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | プロジェクトのテストを実行します。 | WorkflowはGitリポジトリをクローンし、`test`のGradleタスクを実行する<strong>Run Gradle Tests</strong> Stepを使用してテストを実行します。 |

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | プロジェクトのテストを実行します。 | WorkflowはGitリポジトリをクローンし、Script Stepを使用してMaven Wrapperのテストコマンド(`./mvnw test`)を実行し、テストを実行します。 |


## Rubyプロジェクト向けのDefault Workflows {#default-workflows-for-a-ruby-project}

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | プロジェクトのテストを実行します。 | WorkflowはGitリポジトリをクローンし、`gem-{{ checksum "Gemfile.lock" }}`のキャッシュキーを使用してgemキャッシュを復元します。コードベース内のシグナルに応じて依存関係をインストールします。 - MySQL gemが検出された場合、システムの依存関係をインストールします。 - Bundlerが検出された場合、`bundle install`で依存関係をインストールします。 リレーショナルデータベースgemが検出された場合、データベースのセットアップ(`db:create db:schema:load`)を実行します。 テストフレームワークまたはRakefileが検出された場合、Workflowがテストを実行します。Workflowは常にRubyのgemキャッシュを保存し、<strong>Deploy to Bitrise.io</strong> Stepを含みます。 |


## Pythonプロジェクト向けのDefault Workflows {#default-workflows-for-a-python-project}

Pythonの場合、単一の`run_tests` Workflowが生成されます。含まれるStepsは、検出されたパッケージマネージャーと、プロジェクト内に`pytest`が見つかったかどうかによって異なります。

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | プロジェクトのテストを実行します。 | WorkflowはGitリポジトリをクローンし、検出されたバージョンに基づいてPythonをインストールします。バージョンが検出されない場合は、[<GlossTerm baseform="stack">スタック</GlossTerm>のデフォルトのPythonバージョンが使用されます。依存関係をインストールします。使用される正確なコマンドは、検出されたパッケージマネージャーによって異なります。`pytest`が検出された場合、Workflowがテストを実行します。 |


## Flutterプロジェクト向けのDefault Workflows {#default-workflows-for-a-flutter-project}

Flutterプロジェクトの場合、Bitriseは2つのdefault Workflowsを作成します。`run_tests` Workflowと`build_app` Workflowです。

これらのdefault Workflowsに含まれる正確なStepsはプロジェクトの種類によって異なります。ただし、プロジェクトの種類にかかわらず、2つのWorkflowsの主な目的は同じです。

| Workflow ID | Workflow概要 | Workflow説明 |
| --- | --- | --- |
| `run_tests` | プロジェクトのテストを実行します。 | WorkflowはGitリポジトリをクローンし、<strong>Flutter Installer</strong> StepでFlutterをインストールし、<strong>Restore Dart cache</strong>を実行してDartキャッシュを取得します。次を実行します。 - プロジェクトに`test/`ディレクトリがある場合は<strong>Flutter Test</strong> Step。 - プロジェクトに`test/`ディレクトリがない場合は<strong>Flutter Analyze</strong> Step。 テストの実行後、Dartキャッシュを保存し、<strong>Deploy to Bitrise.io</strong> Stepを実行してアーティファクトをデプロイします。 |
| `build_app` | Flutterプロジェクトから、iOSアプリとAndroidアプリの両方をビルドします。 | このWorkflowは、プロジェクトにiOSまたはAndroidのサブプロジェクトがある場合にのみ生成されます。Webプロジェクトの場合、このWorkflowは生成されません。WorkflowはGitリポジトリをクローンし、iOSプロジェクト用にsigning certificateをインストールし、Flutterをインストールし、<strong>Flutter Analyze</strong> Stepを実行します。また、`test/`ディレクトリが存在する場合は<strong>Flutter Test</strong> Stepも実行します。<strong>Flutter Build</strong> Stepでアプリをビルドします。検出されたすべてのプラットフォームをビルドします。 |
