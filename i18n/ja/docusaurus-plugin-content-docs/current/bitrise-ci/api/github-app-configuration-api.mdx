[Bitrise GitHub アプリをインストール](/bitrise-platform/repository-access/github-app-integration#installing-the-github-app-integration)すると、デフォルトのGit接続方法として使用できます。[Bitrise GitHub アプリ統合](/bitrise-platform/repository-access/github-app-integration)をAPI経由で設定します:

- connection typeを[OAuth](/bitrise-platform/repository-access/repository-access-with-oauth)からGitHubアプリに変更します。
- GitHubアプリに定義された[完全な権限](/bitrise-platform/repository-access/github-app-integration#extending-github-app-permissions-to-the-builds)をEnable theします。
- 追加の[リンクされたリポジトリ](/bitrise-platform/repository-access/github-app-integration#additional-linked-repositories-via-a-github-app)を設定します。
- GitHubアプリには不要なため、service credential userやその他のauthorization methodを削除します。


## connection typeをOAuthからGitHubアプリに変更する {#changing-the-connection-type-from-oauth-to-the-github-app}

:::important[重要な考慮事項]

API経由でのOAuthへの切り替えは完全にはサポートされていません。プロジェクトをOAuthに戻すには、Bitrise UIによる手動対応が必要です。一括移行を実行する前に、一部のプロジェクトで移行プロセスをテストすることをお勧めします。

:::

APIで`POST /apps/{app-slug}/change-connection-type`エンドポイントを使用して、GitHub接続をOAuthアプリケーションからBitrise Githubアプリに変更します。指定できる値は次のとおりです:

- `github`
- `github-app`

connection typeをGitHubアプリに変更するには:

```bash
curl -X 'POST' \
  'https://api.bitrise.io/v0.1/apps/APP-SLUG/change-connection-type' \
  -H 'accept: application/json' \
  -H 'Authorization: ACCESS-TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
  "connection_type": "github-app"
}'
```

接続の変更は破壊的な操作ではありません。他の認証方法が削除されることはありません。ビルドが引き続き動作するか確認できます。問題がある場合は、OAuth接続に戻すことができます。

接続を元に戻すには:

```bash
curl -X 'POST' \
  'https://api.bitrise.io/v0.1/apps/APP-SLUG/change-connection-type' \
  -H 'accept: application/json' \
  -H 'Authorization: ACCESS-TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
  "connection_type": "github"
}'
```


## GitHubアプリの権限をビルドに拡張する {#extending-github-app-permissions-to-builds}

Bitrise GitHubアプリは、アプリ経由でトリガーされた各ビルドに対して短期間の一時的なトークンを生成します。このトークンにはデフォルトで1つの権限（contents:read）のみが付与されます。つまり、ビルドはGitHubリポジトリにアクセスできますが、それ以外の操作は実行できません。

これらの権限を拡張すると、ビルド中に他の操作を実行できるようになります。たとえば、ビルドからGitタグをプッシュしたり、カスタムステータスレポートを作成したり、プルリクエストにラベルを付けたり、新しいバージョン番号をプッシュしたりできるようになります。

権限を拡張するには、`PUT /apps/APP-SLUG/github-app-connection-configuration`エンドポイントの`use_full_permission`パラメータを使用します:

```bash
curl -X 'PUT' \
  'https://api.bitrise.io/v0.1/apps/APP-SLUG/github-app-connection-configuration' \
  -H 'accept: application/json' \
  -H 'Authorization: ACCESS-TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
  "use_full_permission_set": true
}'
```

:::tip[詳細情報]

権限の拡張方法とGUIでの操作方法については、[GitHubアプリの権限をビルドに拡張する](/bitrise-platform/repository-access/github-app-integration#extending-github-app-permissions-to-the-builds)を参照してください。

:::


## 追加のリンクされたリポジトリを設定する {#setting-additional-linked-repositories}

リンクされたリポジトリとは、Bitrise<GlossTerm baseform="project">プロジェクト</GlossTerm>がGitHubアプリのインストールを使用してアクセスできるものの、プロジェクトのプライマリリポジトリではないリポジトリのことです。追加のリポジトリがBitrise GitHubアプリのインストールにリンクされている場合、ビルド用に生成されたトークンはその追加のリポジトリにアクセスできます。

追加のリンクされたリポジトリについて詳しくは、[追加のリンクされたリポジトリ](/bitrise-platform/repository-access/github-app-integration#additional-linked-repositories-via-a-github-app)を参照してください。

追加のリポジトリをリンクするには`POST /apps/APP-SLUG/github-app-connection-configuration/update-linked-repositories`を使用します。次の2つの方法があります:

- リポジトリのフルネームを手動でリストする。

  ```bash
  curl -X 'POST' \
    'https://api.bitrise.io/v0.1/apps/APP-SLUG/github-app-connection-configuration/update-linked-repositories' \
    -H 'accept: application/json' \
    -H 'Authorization: ACCESS-TOKEN' \
    -H 'Content-Type: application/json' \
    -d '{
    "repositories": ["org1/repo1", "org1/repo2"]
  }'
  ```
- ビルドが現在および今後のすべてのリポジトリにアクセスできるようにするには、`unlimited_repo_access`フィールドをtrueに設定します。

  ```bash
  curl -X 'POST' \
    'https://api.bitrise.io/v0.1/apps/APP-SLUG/github-app-connection-configuration/update-linked-repositories' \
    -H 'accept: application/json' \
    -H 'Authorization: ACCESS-TOKEN' \
    -H 'Content-Type: application/json' \
    -d '{
    "unlimited_repo_access": true
  }'
  ```


## OAuth接続を削除する {#removing-the-oauth-connection}

GitHubアプリの接続が機能している場合は、OAuth接続の構成要素を削除できます。これには以下が含まれます:

- [service credential user](/bitrise-platform/integrations/the-service-credential-user)の削除。
- SSHキーまたはHTTPトークンの削除。

### service credential userを削除する {#removing-the-service-credential-user}

service credential userを削除するには:

```bash
curl -X 'DELETE' \
  'https://api.bitrise.io/v0.1/apps/APP-SLUG/service-credential-user' \
  -H 'Authorization: ACCESS-TOKEN'
```

### SSHまたはHTTPの認証を削除する {#removing-ssh-or-http-authorization}

以前のauthorization methodを削除するには:

```bash
curl -X 'DELETE' \
  'https://api.bitrise.io/v0.1/apps/APP-SLUG/repository-authorization ' \
  -H 'Authorization: ACCESS-TOKEN'
```
