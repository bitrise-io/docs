任意のコマンドラインインターフェイスから、新しい Bitrise <GlossTerm baseform="Project">プロジェクト</GlossTerm> を簡単に登録できます。手順はガイドに沿って進められ、わかりやすい内容です。また、素早く完了できます。たとえば、プロジェクトで使用したい <GlossTerm baseform="bitrise.yml">`bitrise.yml`</GlossTerm> ファイルが既にある場合は、<GlossTerm baseform="project scanner">プロジェクトスキャナー</GlossTerm> がプロジェクトタイプを検出して `bitrise.yml` ファイルを生成するのを待つ必要はありません。既存のファイルを指定するだけで準備完了です。

:::tip[Adding a project with the API]

Bitrise API を使って新しいプロジェクトを追加することもできます。[Adding and managing apps](/bitrise-ci/api/adding-and-managing-apps)

:::


## プロジェクトの準備 {#preparing-the-project}

CLI 経由で Bitrise に新しいプロジェクトを追加する前に、次の点を確認してください。

- Git プロバイダーに接続された Bitrise アカウントが必要です。
- プロジェクトには、お使いのマシン上のローカル Git リポジトリと、Git プロバイダー上のリモートリポジトリが必要です。SSH キーを使ってリポジトリにアクセスする場合は、[リモートリポジトリに URL の SSH URL が必要です](https://help.github.com/en/articles/which-remote-url-should-i-use)。例: `git@github.com:example-user/example.git`。

あらかじめ `bitrise.yml` を作成しておくこともでき、プロジェクトの作成中にそれを追加できます。これは任意です。Web サイトの場合と同様に、プロジェクトスキャナーに生成させることもできます。

この手順では、Bitrise が SSH キーでアクセスするプロジェクトの追加方法を説明します。これには、プロジェクトのリモートリポジトリに SSH URL が必要です。例: `git@github.com:example-user/example.git`。

もちろん、HTTPS URL を使ってリモートリポジトリにアクセスすることもできます。その場合、プロジェクトに SSH キーを設定することはありません。HTTPS URL の使用は、公開プロジェクト(オープンソースプロジェクト)の場合にのみ推奨します。

以上で完了です。新しいプロジェクトへの URL が出力され、[Bitrise CI ページ](https://app.bitrise.io/ci)でもプロジェクトを確認できます。


## プロジェクトの追加 {#adding-the-project}

1. [CLI から新しい CI プロジェクトを追加](https://app.bitrise.io/apps/add/cli)ページに移動します。

   このページには、[Bitrise CI ページ](https://app.bitrise.io/ci)から移動できます。右側の <strong>New CI project</strong> ボタンをクリックし、<strong>CLI から New CI project</strong> を選択してください。

   ![2025-12-10-adding-project-with-cli.png](/img/_paligo/uuid-a6c8e931-615c-8697-8cf6-ab8d5269420b.png)
1. <strong>Create a fully configured project</strong> で、コピーボタンを使って curl コマンドをコピーします。

   このコマンドは、現在使用している workspace にプロジェクトを作成します。

   :::tip[Creating the project only]

   このページには、<strong>Create a project skeleton</strong> の下に `bitrise app create` コマンドも用意されています。このコマンドは、プロジェクトを設定せずに作成するため、後から設定する必要があります。最新の Bitrise CLI (v3)が必要です。

   :::
1. コマンドラインインターフェイスを開きます。
1. プロジェクトの場所にディレクトリを移動します。
1. curl コマンドを貼り付けて、Enter キーを押します。
1. repository URL を選択します。`SSH` オプションを選んでください。

   このプロンプトは、ローカルリポジトリのリモートに SSH URL がある場合にのみ表示されます。リモートリポジトリに HTTPS URL がある場合、このプロンプトは表示されません。

   ```yaml
   Remote URL: git@github.com:example-user/example.git

   ? Select repository URL::
       https://github.com/example-user/example.git
     > ssh://git@github.com:example-user/example.git
   ```
1. SSH キーを登録します。

   ```yaml
   Specify how Bitrise will be able to access the source code: 
    > Automatic
      Add own SSH
   ```

   自動登録を選択することも、独自のキーを追加することもできます。

   - 自動登録を選択すると、Bitrise がキーペアを自動的に生成します。追加のプライベートリポジトリやサブモジュールを使用する必要がある場合は、プロンプトが表示されたときに I need to オプションを選択し、指示に従ってください。必要がない場合は、No, auto-add SSH key オプションを選択します。これにより、公開鍵がリポジトリに自動的に追加されます。
   - 独自のキーを追加する場合は、SSH キーファイルへのパスを指定する必要があります。パスを手動で入力するか、ファイルをドラッグ&ドロップしてパスを入力してください。
1. アップロードする `bitrise.yml` ファイルを決めます。

   ```text
   ? What bitrise.yml do you want to upload? 
     > Run the scanner to generate a new bitrise.yml
       Use the bitrise.yml found in the current directory or specify manually
   ```

   スキャナーにプロジェクトファイルをもとに生成させることも、ファイルを指定することもできます。リポジトリに既に `bitrise.yml` ファイルがある場合は、そのパスが自動的に入力されます。
1. 使用するブランチを選択します。

   デフォルトのオプションは、現在アクティブなブランチです。

   ```yaml
   The current branch is: master (tracking: origin master),

   ? Do you want to run the scanner for this branch?
     > Yes
       No
   ```

   `No` を選択した場合は、使用するブランチをチェックアウトするよう求められます。その後、もう一度 Enter キーを押すと、スキャナーが開始されます。

   スキャナーの処理が完了すると、プロジェクトのタイプが検出されるか、手動設定に切り替わります。手動設定では、プロジェクトのタイプ(iOS、Android、React Native、Flutter など)を選択し、関連する設定ファイルへのパスを指定する必要があります。たとえば、Ionic プロジェクトの場合は `config.xml` です。このガイドでは、自動検出で進めます。
1. 使用する <GlossTerm baseform="stack">スタック</GlossTerm> を選択します。

   スキャナーがプロジェクトタイプを検出した場合は、スタックが自動的に推奨されますが、必要に応じて CLI で変更できます。上記のように手動設定を行った場合は、スタックも選択する必要があります。
1. Webhook と code signing ファイルを設定して、手順を完了します。

   - Webhook の登録はスキップできますが、Bitrise でビルドを自動的に <GlossTerm baseform="trigger">トリガー</GlossTerm> するには Webhook が必要です。詳細については、[Webhooks](/bitrise-platform/integrations/webhooks/adding-incoming-webhooks)
   - code signing ファイルをアップロードできます。プロジェクトのタイプに応じて、iOS の code signing ファイルや Android キーストアファイルをアップロードするかどうかを尋ねられます。これらのファイルは、Web サイトからいつでもアップロードできます。
