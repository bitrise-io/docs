ローカルでビルドを実行する場合、Bitrise CLIを使うと、<GlossTerm baseform="Secret">Secrets</GlossTerm>は`.bitrise.secrets.yml`ファイルから読み込まれます。このファイルは、<GlossTerm baseform="bitrise.yml">`bitrise.yml`</GlossTerm>が置かれているディレクトリ、つまり`bitrise local run`コマンドを実行するディレクトリと同じ場所にあることが想定されています。

Secretsを別の場所に保存したい場合は、`bitrise local run`コマンドの`--inventory`フラグでSecretsファイルの場所を指定できます。例: .

```bash
bitrise local run my-workflow --inventory /path/to/secrets.yml
```

:::tip[Secretsファイルは必ず`gitignore`してください]

ベストプラクティスとして、`.bitrise.secrets.yml`が`.gitignore`に追加されていることを必ず確認し、リポジトリにコミットされないようにしてください。`.bitrise`で始まるものをすべて`gitignore`するのが最善です。これは、`.gitignore`ファイルに次の行を追加することで実現できます: `.bitrise*`

:::

Secrets YAMLファイルには、ルートの`envs:`項目と、それに続くSecret Environment Variablesのリストを含める必要があります。

```yaml
envs:
- SECRET_ENV_ONE: first Secret value
- SECRET_ENV_TWO: second Secret value
```

`.bitrise.secrets.yml`ファイルで定義されたSecretsは、他の環境変数と同様に使用できます。

```yaml
format_version: 11
default_step_lib_source: https://github.com/bitrise-io/bitrise-steplib.git

workflows:
  test:
    steps:
    - script@1.1.3:
        inputs:
        - content: |
            #!/bin/bash
            echo "SECRET_ENV_ONE: ${SECRET_ENV_ONE}"
            echo "SECRET_ENV_TWO: ${SECRET_ENV_TWO}"
```

ディレクトリ内で`bitrise local run test`するだけで、Script <GlossTerm baseform="Step">Step</GlossTerm>がsecretsファイルで指定された値を出力します。

```yaml
SECRET_ENV_ONE: first secret value
SECRET_ENV_TWO: second secret value
```

`bitrise local run`コマンドを実行するときに最初に処理されるのはSecretsEnvironment Variablesであるため、`bitrise.yml`のどこでもSecretsを使用できます。
