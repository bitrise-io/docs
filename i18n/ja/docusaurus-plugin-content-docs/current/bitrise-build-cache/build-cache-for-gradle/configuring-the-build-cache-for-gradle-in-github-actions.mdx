Bitrise Build Cacheを使用すると、CIをBitriseに移行することなく、GitHub Actions ワークフローのGradleビルドを高速化できます。GitHubがホストするランナーでも、[Bitrise Build Hub](/bitrise-build-hub/build-hub-for-github-actions/build-hub-for-github-actions-overview) ランナーでも、同じように動作します。

ワークフローには2つの追加ステップが必要です。1つはBitrise Build Cache CLIをインストールするステップ、もう1つはGradleのキャッシュを有効にするステップです。その後に同じジョブ内で実行されるすべてのGradleステップが、このキャッシュを使用します。

手順を手動で実行する代わりに、AIコーディングエージェントを使ってセットアップすることもできます。[Getting started with AI](/bitrise-build-cache/getting-started-with-the-build-cache/getting-started-with-ai)を参照してください。

## ワークフローへのBuild Cacheの追加 {#adding-the-build-cache-to-your-workflow}

1. Bitrise Build Cache CLIをインストールするステップを追加します。

   ```yaml
   - name: Install the Bitrise Build Cache CLI
     run: curl --retry 5 -sSfL 'https://raw.githubusercontent.com/bitrise-io/bitrise-build-cache-cli/main/install/installer.sh' | sh -s -- -b /tmp/bin -d
   ```
1. Gradleを実行するステップの前に、Build Cache for Gradleを有効にするステップを追加します。

   ```yaml
   - name: Activate Bitrise Build Cache for Gradle
     run: /tmp/bin/bitrise-build-cache activate gradle --cache --cache-push
   ```

   `--cache`はキャッシュからの読み取りを有効にし、`--cache-push`はキャッシュへの書き込みを有効にします。通常、CIはキャッシュを作成する環境であるため、両方とも有効にしておいてください。

   :::important[Containers]

   ジョブがコンテナー内、または複数のコンテナー内で実行される場合、CLIは、高速化するGradleコマンドと同じコンテナー内で実行する必要があります。

   :::

## ワークフローの例 {#example-workflow}

<Tabs>
<TabItem value="github-hosted" label="GitHub-hosted runners" default>

```yaml
name: build

on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    env:
      BITRISE_BUILD_CACHE_AUTH_TOKEN: ${{ secrets.BITRISE_BUILD_CACHE_AUTH_TOKEN }}
      BITRISE_BUILD_CACHE_WORKSPACE_ID: ${{ vars.BITRISE_BUILD_CACHE_WORKSPACE_ID }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: temurin

      - name: Install the Bitrise Build Cache CLI
        run: curl --retry 5 -sSfL 'https://raw.githubusercontent.com/bitrise-io/bitrise-build-cache-cli/main/install/installer.sh' | sh -s -- -b /tmp/bin -d

      - name: Activate Bitrise Build Cache for Gradle
        run: /tmp/bin/bitrise-build-cache activate gradle --cache --cache-push

      - name: Build
        run: ./gradlew assembleDebug
```

</TabItem>
<TabItem value="build-hub" label="Build Hub runners">

このジョブにトークンやenvironment variablesは必要ありません。`runs-on`ラベルは、お使いのプールを対象にします。Bitriseはマシンプールごとに`bitrise-runner-<pool name>`ラベルを作成するため、`android-builds`という名前のプールは`bitrise-runner-android-builds`で指定します。

```yaml
name: build

on: [push, pull_request]

jobs:
  build:
    runs-on: bitrise-runner-android-builds
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: temurin

      - name: Install the Bitrise Build Cache CLI
        run: curl --retry 5 -sSfL 'https://raw.githubusercontent.com/bitrise-io/bitrise-build-cache-cli/main/install/installer.sh' | sh -s -- -b /tmp/bin -d

      - name: Activate Bitrise Build Cache for Gradle
        run: /tmp/bin/bitrise-build-cache activate gradle --cache --cache-push

      - name: Build
        run: ./gradlew assembleDebug
```

プールのカスタムラベルを使用することもできます。詳細については、[Configuring your GitHub Actions workflow](/bitrise-build-hub/build-hub-for-github-actions/configuring-your-github-actions-workflow)を参照してください。

</TabItem>
</Tabs>
