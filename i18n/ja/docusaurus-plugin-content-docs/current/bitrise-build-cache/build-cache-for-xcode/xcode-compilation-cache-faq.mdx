## Xcode Compilation Cache を使用するための要件は何ですか？ {#what-are-the-requirements-to-use-xcode-compilation-cache}

Xcode 26 と、<strong>Explicitly Built Modules の有効化</strong>が必要です（Swift ターゲットでは Xcode 26 でデフォルトで有効）。

## Swift Package Manager の依存関係でも動作しますか？ {#will-this-work-with-swift-package-manager-dependencies}

2025年9月時点では、SPM の依存関係は Xcode 26 Beta ではキャッシュできません。Apple が対応を進めており、今後利用できるようになる見込みです。

## キャッシュできないビルドタスクは何ですか？ {#what-build-tasks-are-not-cacheable}

現在、`CompileStoryboard`、`CompileXIB`、`CompileAssetCatalogVariant`、`PhaseScriptExecution`、`DataModelCompile`、`CopyPNGFile`、`GenerateDSYMFile`、`Ld` のタスクはキャッシュできません。

## Xcode Test は高速化されますか？ {#will-it-speed-up-my-xcode-tests}

Xcode Compilation Cache はコンパイル時間の短縮に役立ちます。そのため、ビルドとアーカイブのアクションで最も効果があります。

Xcode Test の場合、テストのコンパイルは高速になりますが、テストの実行自体は速くなりません。

Xcode のコンパイルキャッシュによるパフォーマンス向上を確認するには、[Xcode Archive](https://bitrise.io/integrations/steps/xcode-archive) または [Xcode Build For Testing](https://bitrise.io/integrations/steps/xcode-build-for-test)（あるいはその他のビルドコマンド）を実行する <GlossTerm baseform="Workflow">Workflow</GlossTerm> でテストすることをお勧めします。

## Xcode のコンパイルキャッシュを一時的に無効にするにはどうすればよいですか？ {#how-can-i-disable-xcode-compilation-cache-temporarily}

最も簡単な方法は、カスタムの Xcode フラグ `--no-bitrise-build-cache` を指定することです。

このフラグは Bitrise ラッパーに認識され、アナリティクスを無効にせずにキャッシュのみを無効にします。つまり、実行は UI に表示されますが、キャッシュは使用されないため、キャッシュのクォータにはカウントされません。

別の方法として、次のコマンドを実行して PATH を上書きし、設定済みのラッピングを削除することもできます。

```bash
export PATH="${PATH#"$HOME/.bitrise-xcelerate/bin:"}"
```

この変更は、次のターミナルセッションで元に戻ります。これは、Bitrise Build Cache CLI が保持されるためで、PATH の上書きは `~/.zshrc` と `~/.bashrc` にあります。

Bitrise <GlossTerm baseform="step">Steps</GlossTerm> をまたいで変更を保持するには、envman で PATH を再度設定します。

```bash
envman add --key PATH --value "$PATH"
```

## コンパイルキャッシュのビルドフラグを手動で渡すにはどうすればよいですか？ {#how-to-pass-compilation-cache-build-flags-manually}

プロジェクトごとにコンパイルキャッシュを手動で有効にするには、[Build Cache for Xcode](https://github.com/bitrise-steplib/bitrise-step-activate-build-cache-for-xcode) Step（Bitrise CI 上）で、<strong>Skip passing cache flags to xcodebuild</strong> Step 入力を使用して、必要なフラグの受け渡しを無効にできます。Bitrise Build Cache CLI をローカルで使用している場合は、`--cache-skip-flag` を `activate xcode` コマンドに渡すことができます。

この場合、ビルドごとにいくつかのフラグを手動で設定するか、プロジェクトのビルド設定で設定する必要があります。一部のフラグは、Xcode IDE で "Enable Compilation Caching" や "Explicitly Built Modules" などの名前で用意されている場合があります。デフォルトで渡しているフラグは次のとおりです。

```yaml
- "COMPILATION_CACHE_ENABLE_PLUGIN":               "YES"
- "COMPILATION_CACHE_ENABLE_INTEGRATED_QUERIES":   "YES"
- "COMPILATION_CACHE_ENABLE_DETACHED_KEY_QUERIES": "YES"
- "SWIFT_ENABLE_COMPILE_CACHE":                    "YES"
- "SWIFT_ENABLE_EXPLICIT_MODULES":                 "YES"
- "SWIFT_USE_INTEGRATED_DRIVER":                   "YES"
- "CLANG_ENABLE_COMPILE_CACHE":                    "YES"
- "CLANG_ENABLE_MODULES":                          "YES"
```

Bitrise でこれらのフラグを渡す方法の詳細については、こちらの[ブログ記事](https://bitrise.io/blog/post/lifting-the-hood-on-build-cache-for-xcode)を参照してください。

## Xcode Index Data Store に依存するツールはどうなりますか？ {#what-about-tools-that-depend-on-xcode-index-data-store}

リモートのコンパイルキャッシュが有効な場合、Xcode は DerivedData に `Index.noindex/DataStore` を生成しません。そのため、タスクが Index Data Store に依存している場合、エラーが発生することがあります。

次は、Index data store が見つからない場合に [Periphery](https://github.com/peripheryapp/periphery) が生成するエラーの例です。

`error: Internal Error: index store path does not exist: /Users/vagrant/Library/Developer/Xcode/DerivedData/.../Index.noindex/DataStore`

現時点では、この問題の解決策はありません。回避策として、Index data store に依存しないすべての Step と Workflow では Bitrise [Build Cache for Xcode](https://github.com/bitrise-steplib/bitrise-step-activate-build-cache-for-xcode) を使用し、Index data store に依存する Step は、Bitrise Build Cache for Xcode を設定しない別の Workflow で実行する方法があります。
