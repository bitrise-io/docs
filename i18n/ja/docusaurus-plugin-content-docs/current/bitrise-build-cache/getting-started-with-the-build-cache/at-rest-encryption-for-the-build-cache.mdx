[Bitrise Build Cache](https://bitrise.io/platform/devops/build-caching)は、エンベロープ暗号化と AES-256-GCM を使用した保存データの暗号化によって、お客様のデータを保護します。

## 保存データの暗号化の概要 {#at-rest-encryption-overview}

- お客様ごとに一意のデータ暗号化キー (DEK) が生成されます。
- DEK は、キー管理システム (KMS) によって生成・管理されるキー暗号化キー (KEK) を使用して暗号化されます。例: Google KMS。
- セキュリティ強化のため、KEK は 90 日ごとにローテーションします。
- 暗号化された DEK はデータベースに安全に保存されます。DEK が復号された状態で永続化されることはなく、データの暗号化または復号の際にメモリ内でのみ使用されます。
- DEK はお客様のデータの暗号化に使用され、機密情報が保存時に安全に保護されます。

KEK と DEK が一緒に保存されることはなく、強力な分離が保たれます。生の KEK が公開されることはありません。KEK は KMS 内でのみ使用され、DEK を安全に暗号化および復号します。この方式により、強力な暗号化、安全なキー管理、そしてお客様のデータに対する高水準の保護が実現します。

## セキュリティ上の利点 {#security-benefits}

- 強力な暗号化: AES-256-GCM は広く信頼されている暗号化標準で、機密データに対して堅牢な保護を提供します。
- お客様ごとの分離: お客様ごとに一意の DEK があるため、あるお客様のキーが侵害されたとしても、他のお客様のデータが影響を受けることはありません。暗号化されたデータにアクセスできるだけでは、復号されたデータにアクセスすることはできません。
- 規制への準拠: 保存データの暗号化は、次のようなセキュリティおよびプライバシー規制が推奨するベストプラクティスに沿っています。

  - <strong>GDPR (一般データ保護規則)</strong>: データ保護対策として暗号化を推奨しています。
  - <strong>CCPA (カリフォルニア州消費者プライバシー法)</strong>: 暗号化されたデータは、特定の情報漏えい責任要件の対象外となる場合があります。
  - <strong>SOC 2</strong>: コンプライアンスのための重要なセキュリティ管理策として暗号化をサポートしています。
  - <strong>ISO/IEC 27001</strong>: 保存データを保護するために暗号化を推奨しています。
  - <strong>NIST (米国国立標準技術研究所)</strong>: 強力なデータ保護と業界のセキュリティフレームワークへの準拠を確保するため、暗号化標準 (例: AES-256) を提供しています。

## お客様管理の暗号化キー {#customer-managed-encryption-keys}

暗号化をより細かく制御したいお客様向けに、お客様管理の暗号化キー (CMEK) を使用するオプションを提供しています。

CMEK を使用すると、お客様は独自の Google Cloud KMS または Amazon KMS にキー暗号化キー (KEK) を保存できます。これにより、次のことが可能になります。

- 完全な制御の維持: 作成、ローテーション、失効を含め、独自の KEK を管理できます。
- セキュリティコンプライアンスの強化: 暗号化キーにアクセスできるのをお客様のみに限定し、厳格な社内セキュリティポリシーに沿った運用ができます。

CMEK の使用をご検討の場合は、[お問い合わせ](https://bitrise.io/contact)のうえ、ご要件をお知らせください。
