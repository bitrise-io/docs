[Bitrise Build Cache](https://bitrise.io/platform/devops/build-caching)は、Gradle、Bazel、Xcode、React Native で構築されたアプリケーションの CI ビルド時間を短縮する、フルマネージドのキャッシュソリューションです。ビルドおよびテストの出力を特にキャッシュすることで、以降のビルドで行う作業量を最小限に抑え、更新頻度の高い環境でより効率的に動作します。あらゆる CI ツールに対応しており、キャッシュインフラストラクチャを管理することなくビルドサイクルを高速化できます。

:::tip[無料でお試しください]

30-day free trial を無料で提供しています。お支払い情報の入力も不要です。トライアルは、Bitrise Build Cache を設定すると自動的に開始されます。

[Bitrise Build Cache を始めるにはこちらをクリックしてください](https://app.bitrise.io/build-cache)。Bitrise アカウントをお持ちでない場合は、先にアカウントの作成を求められ、その後 Build Cache の設定に進みます。

:::

## ローカル開発環境での設定 {#setting-up-in-a-local-dev-environment}

Build Cache は、ご自身のマシンでも使用できます。ローカルビルドは、CI のビルドが蓄積した同じキャッシュを読み取るため、CI がすでにコンパイルしたタスクを、お使いのマシンで再度コンパイルする必要はありません。

ローカル環境の設定にトークンは不要です。CLI がブラウザー経由でサインインし、認証情報を OS キーチェーンに保存します。

## Build Cache への new connection の追加 {#adding-a-new-connection-to-the-build-cache}

Bitrise Build Cache を使い始めるには、new connection を追加する必要があります。手順は次のとおりです。

- CI プロバイダーを選択します。Bitrise またはその他の CI プロバイダーを使用できます。
- ビルドツールを選択します。現在、Bazel、Gradle、Xcode、React Native がサポートされています。
- CI プロバイダーとして Bitrise を使用する場合は、Bitrise project を選択します。
- 別の CI プロバイダーを使用する場合は、Bitrise Build Cache が CI にアクセスできるように、[workspace API トークン](/bitrise-platform/workspaces/workspace-api-token)を追加します。workspace API トークンは特定の個人に紐づかないため、担当者のロールが変わったり退職したりしても、ビルドは引き続き動作します。
- CI プロセスにキャッシュ有効化スクリプトを追加します。Bitrise では、この目的のための専用の [Steps](/bitrise-ci/workflows-and-pipelines/steps/steps-overview) を用意しています。

new connection を追加するには、次の手順を実行します。

1. Bitrise に Log in し、左側のナビゲーションメニューから <strong>Build Cache</strong> を選択します。
1. 右上隅にある <strong>New connection</strong> をクリックします。

   ![cache-new-connection.png](/img/_paligo/uuid-bdbb02c7-b8e7-bf04-fb52-7cacd2231760.png)
1. 画面の指示に従います。
