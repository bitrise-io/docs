Bitrise Build Cache CLIは、サードパーティのCIプロバイダー(GitHub Actions、GitLab CI、CircleCI、Jenkinsなど)にダウンロードして実行できます。

手順を手動で実行する代わりに、AIコーディングエージェントを使ってセットアップすることもできます。[AIの利用開始](/bitrise-build-cache/getting-started-with-the-build-cache/getting-started-with-ai)を参照してください。

:::tip[GitHub Actionsを使用する場合]

GitHub Actionsのワークフロー例を掲載した専用ガイドがあります。[GitHub ActionsでのBuild Cache for React Nativeの設定](/bitrise-build-cache/build-cache-for-react-native/configuring-the-build-cache-for-react-native-in-github-actions)を参照してください。

[Bitrise Build Hub](/bitrise-build-hub/build-hub-for-github-actions/build-hub-for-github-actions-overview)のランナーでは、トークンはまったく必要ありません。マシンはすでにBitrise Workspaceに接続されているため、CLIが自動的に認証されます。以下の手順は、それ以外のすべての環境が対象です。

:::

## キャッシュの設定 {#configuring-the-cache}

1. 少なくとも<strong>viewer</strong>workspaceロールを持つ[workspace APIトークン](/bitrise-platform/workspaces/workspace-api-token)を作成します。
1. [Workspaceのスラッグを取得します](/bitrise-ci/api/identifying-workspaces-and-apps-with-their-slugs)。
1. CIプロバイダーのシークレット/環境設定で、2つの変数を設定します。

   - `BITRISE_BUILD_CACHE_AUTH_TOKEN`: workspace APIトークン。
   - `BITRISE_BUILD_CACHE_WORKSPACE_ID`: workspaceのスラッグ。
1. ビルドを実行するStepの前に、CIパイプラインへ次のスクリプトを追加します。

   このスクリプトは、高速化の対象となるビルドコマンドと同じ環境(同じシェル、同じコンテナー)で実行する必要があります。

   ```bash
   #!/usr/bin/env bash
   set -euxo pipefail

   # Download the Bitrise Build Cache CLI.
   curl --retry 5 -sSfL \
     'https://raw.githubusercontent.com/bitrise-io/bitrise-build-cache-cli/main/install/installer.sh' \
     | sh -s -- -b /tmp/bin -d

   # Activate Build Cache for React Native (Gradle + Xcode + ccache for C++).
   /tmp/bin/bitrise-build-cache activate react-native
   ```

   デフォルトでは、3つのバックエンドすべてが有効になります。バックエンドを無効にするには、対応するフラグを渡します。

   ```
   /tmp/bin/bitrise-build-cache activate react-native --gradle=true --xcode=true --cpp=false
   ```

   CIは通常、キャッシュにデータを書き込む環境です。読み取りに加えて書き込みアクセスも有効にするには、`--cache-push`を渡します。

   ```
   /tmp/bin/bitrise-build-cache activate react-native --cache-push
   ```

   :::note

   これまでBitrise Build Cache CLIをGradleまたはXcodeのみに使用していた場合は、React Nativeのサポートを利用するために、<strong>CLI v1.0.0以降</strong>を使用していることを確認してください。

   :::
1. 有効化後、`bitrise-build-cache`バイナリがPATHに追加されます。ビルドを実行するコマンドの先頭に`bitrise-build-cache react-native run`を付けてください。

   :::note

   ラップの詳細については、[ネイティブビルドコマンドのラップ](/bitrise-build-cache/build-cache-for-react-native/wrapping-native-build-commands)を参照してください。

   :::

<strong>Exampleの設定: GitHub Actions</strong>

Bitrise Build Hubランナーで実行するジョブを含むGitHub Actionsのワークフロー例については、[GitHub ActionsでのBuild Cache for React Nativeの設定](/bitrise-build-cache/build-cache-for-react-native/configuring-the-build-cache-for-react-native-in-github-actions)を参照してください。

## セットアップの検証 {#validating-the-setup}

1. 新しい設定でビルドを実行します。アクティベーションステップが正常に完了するはずです。
1. Bitriseの<strong>Build details</strong>ページを開き、<strong>Build Cache</strong>タブを確認します。ラップされたコマンドがキャッシュ統計とともに一覧表示されます。
1. 最初のビルドでは、キャッシュヒット率が0%と報告されます。この時点ではキャッシュが空のため、これは想定どおりの動作です。
1. キャッシュを温めるために、さらに1~3回ビルドを実行します。以降のビルドでは、ヒット率が0%を超えるはずです。
1. ビルドごと、およびビルド全体のキャッシュパフォーマンスは、[Build Cache一覧ページ](https://app.bitrise.io/build-cache/)で確認できます。
