ほとんどのユーザーは、クラウドベースのサービスプロバイダーでリポジトリをホストしているため、Bitriseを使用するためにネットワーク設定は必要ありません。必要なのはリポジトリへのアクセス権限だけで、それには [SSHキー](/bitrise-platform/repository-access/configuring-ssh-keys) または [アクセストークン](/bitrise-platform/repository-access/configuring-https-authorization-credentials) で十分です。

ただし、社内のセキュリティポリシーによっては、不明な未承認の IP アドレスが、自社データセンターまたはプライベートクラウド上のコード保管サーバーと通信することを許可していない場合があります。その場合、関連する IP アドレスを許可リストに追加しない限り、Bitriseは動作しません。

Bitrise build machines が Git などのサービスからソースコードをダウンロードする際や、テスト用バックエンドサービス、または CI ワークフローの一部として接続が必要な Bitrise 外部のその他のサービスにアクセスする際、送信元として次の範囲の IP アドレスが表示されます。

:::warning[サブネット全体を許可リストに追加する]

提供されたパブリック IP アドレスがサブネットの場合は、ネットワーク上でサブネット全体を許可する必要があります。たとえば、208.52.166.128/28 は、208.52.166.128 から 208.52.166.143 までのすべての IP アドレス(208.52.166.128、208.52.166.129、208.52.166.130 と続き、208.52.166.143 までを含む)を許可リストに追加する必要があることを意味します。

:::

:::warning[マルチテナントとシングルテナント]

以下に記載する build machine IP の範囲は、Bitrise のマルチテナント環境用です。組織のセキュリティ要件によっては、Bitrise のマルチテナント IP の範囲からネットワークへのアクセスを許可することが望ましくない場合があります。セキュリティ要件が厳しい組織では、次の方法を利用できます。

- [VPN で接続する](/bitrise-platform/integrations/connecting-to-a-vpn-during-a-build)。
- [シングルテナント環境を選択する](/bitrise-platform/infrastructure/customizable-enterprise-build-platforms)。
- [ランナーを自分の AWS アカウントにデプロイする](/bitrise-platform/infrastructure/bitrise-on-aws--cloud-controller/aws-cloudformation-templates)。

ご不明な点がございましたら、お気軽に[お問い合わせください](https://bitrise.io/contact)。
